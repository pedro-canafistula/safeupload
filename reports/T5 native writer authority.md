# Build native writer authority before admission

SafeUpload M2 should implement integrated T5 as one ordered chain: **original-subject NTFS checks, an original-grant lease, complete immutable security and destination evidence, a separately negotiated metadata carrier, and coherent seeding with recipient-bound provenance**. For an existing target, the supplemental disposition check must close completely before the original-rights lease opens; only that lease preserves the application's native sharing through cleanup. The chain must retain the supported CREATE inputs and lookup semantics, preserve published V18/V23/V26 layouts and existing security-only behavior, and keep live admission disabled until every dependency is qualified. Microsoft documents the component DDIs, but those contracts do not settle low impersonation tokens, complete metadata observation on restricted leases, NTFS-equivalent assignment through SYSTEM temporary creation, or whole-file seed coherence. The current lookup-capture baseline, `4b478e1019c93076eae74e389289878ceb88126c`, passes all four WDK configurations with **zero warnings and errors**, recorded by documentation commit `c03b40f8`; these are static/component gates, and no revised protected pair has booted. The owner's choice for unreadable old bytes remains pending: preserve write-only clean editing without readable full-file hand-back or justification, or require read authorization for preserving edits; **neither option is approved or implemented**. ([Build evidence](../driver/evidence/2026-10-13/exact-t5-lookup-capture4-summary.txt), [Current contract](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md), [Pending owner choice](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md))

## Native checks must precede original-grant leases

**Documented contract.** CREATE authority depends on the disposition as well as requested access. Supersede requires DELETE; overwrite requires applicable write authority; overwrite and supersede introduce EA/attribute checks when restore authority does not remove them. Creation also requires the containing-directory check. NTFS must decide applicable target, parent DELETE_CHILD, traversal, label and privilege behavior under the original effective subject. The WDK guidance and MS-FSA algorithms identify these obligations; they do not establish that a fixed supplemented mask reproduces every local NTFS CREATE. ([Special CREATE cases](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/checking-for-other-special-cases--on-irp-mj-create), [Existing-file access](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/82b364ce-6d7b-422f-8d88-4db32eea809a))

**Measured local evidence.** The Restore-disabled builder control matches native status and projected app grants in **980 existing-target comparisons** across five dispositions, seven masks, seven ACL profiles and four existing-share conditions. A later control found that retaining supersede's supplemental DELETE grant incorrectly rejects a later reader; the corrected check-close-lease sequence passes **90 sharing cases**. These results establish the tested projection and lifetime correction, not absent-object creator grants, present FILE_CREATE collision precedence, arbitrary flags/descriptors, low token levels or enabled Restore behavior. They ran on builder Windows 10 19045.6466, not the protected product baseline 19045.2965. ([Recorded scope and raw controls](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md), [Split lifetime evidence](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md))

**Proposed design.** Add a writer-specific StagePublic factory consuming the owned `SAFEUPLOAD_STAGE_CREATE_INPUT`, original process lifetime, effective static subject and original instance. The existing public backend requires DELETE and cannot serve ordinary writers unchanged. Run preparation on an initially unimpersonated system worker, outside namespace/stream/spin locks, below the validated fixed local NTFS instance. Impersonate only for caller-authority operations, retain original privileges and backup intent, check impersonation status, and revert on every successful-impersonation exit. Use kernel handles, forced access checking, no-reparse rules and original sharing; never bypass share checks or substitute SYSTEM authority. `FltCreateFileEx2` returns independently owned handle/object resources, and its top-level-IRP restrictions apply. ([Existing DELETE backend](../driver/SafeUpload.Minifilter/StagePublic.c), [FltCreateFileEx2](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltcreatefileex2), [SeImpersonateClientEx](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-seimpersonateclientex))

For a present target, first issue a noncreating, nontruncating FILE_OPEN with the qualified disposition-check authority and original sharing. Capture its exact identity and complete comparison tuple, then close its handle and dereference its object **before** the second FILE_OPEN. The second uses only original requested authority and sharing against the same original lookup. Query its actual `GrantedAccess` through `ZwQueryObject(ObjectBasicInformation)`, directly query its full identity, recapture the complete tuple and reject a mismatch before allocation or exposure. The supplemental grant never becomes app authority. Carry the checked original grant into the app access state/private sharing, applying the existing T10 exclusions of WRITE_DAC, WRITE_OWNER and ACCESS_SYSTEM_SECURITY to staged data handles while retaining the separate supported security-only public route. ([Two-open requirement](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md), [ZwQueryObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-zwqueryobject), [GrantedAccess field](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_public_object_basic_information), [T10 restriction](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md))

Neither authority open may replace captured `LookupRoot`, exact `LookupName` bytes, `LookupById` or original case operation flags with the normalized service locator. Binary file-ID selectors are not Unicode paths. When a root exists, a temporary handle to that **same retained object** is the candidate RootDirectory mechanism; it is an internal locator, not a caller grant. `ObOpenObjectByPointer` documents file-handle/FO_HANDLE_CREATED prerequisites, so retaining a FILE_OBJECT reference alone does not resolve root cleanup races. Derive the canonical destination only after native resolution, verifying the selected parent/leaf link, root relationship and full ID; another hard link to the same ID is insufficient. ID lookup can bypass pathname traversal, so metadata binding cannot introduce a new caller pathname authorization requirement. ([NtCreateFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile), [ObOpenObjectByPointer](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-obopenobjectbypointer), [File-ID traversal guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/checking-for-other-special-cases--on-irp-mj-create), [Lookup capture](../driver/SafeUpload.Minifilter/StagePublic.c))

**Unresolved gate.** Static capture through `SeCreateClientSecurityFromSubjectContext` is documented to fail with STATUS_BAD_IMPERSONATION_LEVEL for unusable Identification/Anonymous clients. Bypassing a local guard does not remove that DDI restriction, and the current fixture always constructs an impersonation-level token. Compare original native CREATE, callback capture and worker candidate at the actual Primary/Anonymous/Identification/Impersonation/Delegation levels, including restricted and deny-only variants. If native succeeds while capture/candidate fails, retain disabled admission until a documented subject-preserving mechanism exists; do not promote token level, infer native failure from capture failure, or use a SID/DACL substitute. `IO_DRIVER_CREATE_CONTEXT` documents no subject/AccessState injection field. ([Capture DDI](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-secreateclientsecurityfromsubjectcontext), [Create context](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_io_driver_create_context), [Required token controls](<../research_notes/T5 native writer authority/writer_authority.md>))

## Complete snapshots separate construction from stored security

The factory needs a bounded owned vector covering **root, every ancestor, parent and target**, with full volume/128-bit identity, exact link/component, directory case mode, non-reparse/type facts and complete stored security. Keep mount identity, canonical long leaf and original request case flag distinct. Existing root/parent-only anchoring and owner/group/DACL queries are incomplete. Directly query FileIdInformation on the checked lease without first requiring READ_ATTRIBUTES: MS-FSA describes the full-ID query, and local a8 controls establish the tested exact 24-byte result for synchronous/asynchronous write/append share-0 objects, including READ_ATTRIBUTES denial. The corresponding `FltQueryInformationFile` kernel path remains to be qualified with exact status, returned length and full-ID assertions. ([Current limitations](../driver/SafeUpload.Minifilter/StagePublic.c), [FileIdInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/a00d78b9-5a5b-44cc-b389-6c67d53611ee), [FltQueryInformationFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltqueryinformationfile), [a8 evidence](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md))

**Complete descriptor observation is still a mechanism gate.** `FltQuerySecurityObject` documents READ_CONTROL for owner/group/DACL and ACCESS_SYSTEM_SECURITY for SACL; it does not promise a write-only-object bypass. Qualify direct full query on the exact retained object, or a separately controlled metadata-only observer matched to its full ID and selected link. Such an observer uses non-data metadata rights and no share bypass; it cannot authorize the writer or export old bytes. MS-FSA's sharing categories support this candidate because metadata rights fall outside data/delete sharing categories, but oplock/audit effects and local share-0 behavior still require controls. Resolve the complete query mask, including labels and supported resource-attribute/CAP information, rather than falling back to partial security. NTFS's documented 64K stored-descriptor bound supports bounded returned-storage allocation; it is not a blanket bound on all raw supplied representations. ([FltQuerySecurityObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltquerysecurityobject), [Sharing algorithm](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8c0e3f4f-0729-49f4-a14d-7f7add593819), [Security information flags](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information), [NTFS query bound](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-zwquerysecurityobject))

The following disposition contract separates successful application behavior from helper FILE_OPEN results. Every failure retains qualified native status/IOSB precedence; it is not translated wholesale into ACCESS_DENIED. ([NtCreateFile results](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile), [Reviewed disposition contract](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md))

| Original state/disposition | Assigned security and app result | Old public bytes |
| --- | --- | --- |
| Present CREATE | Qualified native collision; no successful allocation authority | None copied |
| Present OPEN / OPEN_IF | Complete checked-target security; original native grant; FILE_OPENED | Preserved only through the separate seed contract |
| Present OVERWRITE / OVERWRITE_IF | Complete checked-target security; qualified supplemental check then original grant; FILE_OVERWRITTEN | Empty private data |
| Present SUPERSEDE | Retain checked-target security in the tested native cases; supplemental check then original grant; FILE_SUPERSEDED | Empty private data |
| Absent OPEN / OVERWRITE | Qualified native absence failure | None copied |
| Absent CREATE / OPEN_IF / OVERWRITE_IF / SUPERSEDE | Exact-parent authorization and native-equivalent assignment/creator grant; FILE_CREATED | No old public bytes |

For absence, prove complete anchored absence under original lookup semantics, then check exact-parent FILE_ADD_FILE or applicable original restore behavior under the retained subject. Query error, truncated enumeration or ambiguous case/alias matching is not absence. Construct security from the exact parent's complete descriptor, original supplied descriptor and original static subject. **Do not deny the creator by rechecking the new DACL as an existing object**: MS-FSA separates initial creation grants from later opens, and nine local supplied-descriptor cases include successful absent creations requesting WRITE_DATA with a supplied FR-only protected DACL. Existing successful cases, including supersede, retain the queried prior descriptor. Those SDDL observations do not prove arbitrary supplied-input validation or full binary assignment. ([New-file algorithm](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/498a5eeb-afc9-445f-99ed-a7e4b73c648b), [Supplied-descriptor evidence](../driver/evidence/2026-10-12/writer-supplied-descriptor-native-a6.txt))

`SeAssignSecurityEx` is a documented **candidate constructor**, not a theorem of NTFS equivalence. Its assignment/inheritance/check flags, subject default owner/group/DACL, supplied-owner validation, original privileges, labels, creator-owner/group, restricted groups and owner-rights behavior need binary differential qualification. Do not bypass owner/privilege checks, force service integrity, or choose flags merely to make a case pass. Keep original input, assigned construction descriptor and expected native stored descriptor separate. Construction/callback comparison preserves meaningful defaulted/control flags; stored-object comparison explicitly handles documented nonpersisted bits. In particular SE_DACL_DEFAULTED affects assignment but is not physically stored, so requiring that bit to survive a post-query is incorrect. ([SeAssignSecurityEx](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-seassignsecurityex), [Descriptor controls](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-control), [Mandatory integrity](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control))

Use one bounds-checked binary codec with separate construction and stored comparators. Preserve SID values, absent/NULL/empty ACL distinctions, ACL revisions, ordered ACE types/payloads, labels, inheritance/protection and relevant control/defaulted/RM flags. Normalize offsets and representation padding only under an explicit tested rule; never reorder ACEs, remap assigned masks or round-trip through SDDL. SDDL omits defaulted flags and cannot establish this contract. Validate self-relative lengths/offsets before parsing, retaining original binary blobs for diagnostics and immutable replay. ([SDDL representation](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-string-format), [ACL structure](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-acl), [Relative descriptor validation](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-rtlvalidrelativesecuritydescriptor))

## A separate carrier preserves the published ABI

**Proposed transport.** Inventory reserved feature controls, then define a separately negotiated, typed, read-only allocation-metadata carrier attached to the active original CREATE reservation. Keep **V18's 1192 bytes, V23's 124 bytes and V26's fixed publication layouts unchanged**. V23 already identifies reservation/destination/predecessor but has no assigned descriptor, original case flag or seed/read provenance; V26's permit is not descriptor storage. The live dispatcher must require the new metadata capability, so an old pair cannot silently allocate without it. Final wire number, page size, total bounds and packing/phase rules remain design work, not assigned values in this report. ([V18 layout](../driver/SafeUpload.Minifilter/Protocol.h), [V23 layout](../driver/SafeUpload.Minifilter/StageBoundAllocation.h), [V26 contract](../driver/docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md))

Bind bounded requests/replies to authenticated driver instance, connection epoch, authority revision, V23 request/reservation, immutable snapshot GUID/digest, section kind and checked page offset/length. Define discovery versus subsequent exact-snapshot phase rules, reserved-zero fields, total length/completeness, typed status and zero tails. Required sections carry the exact binding/original CREATE facts; construction and expected stored security with codec/assignment version and source snapshot commitments; a commitment to the complete ancestor validation tuple; and typed seed/read/recipient/predecessor provenance. Complete ancestor objects remain kernel-owned when the service needs only the commitment. Never transmit pointers/token handles or treat PID/path/SID as permission. Read through a referenced existing attach/version owner, without global locks across service waits, and invalidate admission on reconnect or stale snapshot. A page read grants no publication/CREATE/delete authority. ([Carrier proposal](<../research_notes/T5 native writer authority/assigned_security.md>), [Capture ownership](../driver/SafeUpload.Minifilter/StageStream.c))

The service fetches and validates the complete snapshot, takes the existing destination turn and persists canonical metadata, digest, binding and provenance atomically with the allocation manifest **before replying**. That allocation snapshot records seed intent/source lineage and available authorization; a separately bound immutable completion receipt must record actual seed EOF/flush/coherence only after the kernel copy completes. Define those phases without rewriting original authority or inventing success before completion. Retries require the same immutable record; recovery cannot refresh it from current SYSTEM observations. Preserve existing exact allocation/candidate-retirement receipts and lifecycle states. After RPC, the driver recaptures every ancestor/link/case/security fact, target state or complete absence, and directly requeries retained-lease identity outside locks. Under the namespace lock it then checks reserved view/predecessor, original caller lifetime, cancellation, instance/channel state and service generation. A mismatch retires the exact candidate before exposure, without a new writer-rights or zero-access target reopen. ([Post-allocation requirement](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md), [Allocation journal](../agente/SafeUpload.Agent.Service/Interception/StagedBoundAllocationJournal.cs))

Publication loads the saved descriptor for that exact allocation/version and supplies it on the service's **original UserMode NtCreateFile OBJECT_ATTRIBUTES.SecurityDescriptor**. The kernel compares the copied callback input against construction expectation, then full security queried from the exact created object against stored expectation, before admitting temporary writes. Preserve fixed publication access/share, and grant no WRITE_DAC/WRITE_OWNER/ACCESS_SYSTEM_SECURITY to the service temporary handle. Missing/incomplete metadata leaves CreatePermit NotReady. Supplying an already assigned descriptor during SYSTEM creation is **not proven idempotent**: inherited ACEs can be recomputed and token-related labels can differ. The required native round-trip must resolve that mechanism; adding PROTECTED flags, stripping inheritance, post-setting security or injecting privileged AccessState would change the contract. ([Publication equality and CREATE path](../driver/docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md), [Assignment inheritance behavior](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-seassignsecurityex))

## Exact-object seeds need coherence and recipient proof

**Documented contract and remaining unknown.** Seed through the exact retained original-grant FILE_OBJECT after post-RPC validation into the exclusive private backing; the service's current second public data-read open adds different authority/sharing and must leave the integrated live path. `FltReadFile` requires a currently open object, explicit operation constraints and returns filesystem status, but documents neither guaranteed write/append-only success nor an atomic snapshot. `NtReadFile` explicitly requires READ_DATA/GENERIC_READ, so a user-mode read-handle test cannot qualify the kernel operation. Never add READ_DATA to the app grant, rewrite FILE_OBJECT sharing/access fields, use paging I/O to evade locks or replace the source with a privileged second reader. ([FltReadFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltreadfile), [NtReadFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntreadfile), [FILE_OBJECT fields](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_file_object), [Current service source open](../agente/SafeUpload.Agent.Service/Interception/StagedDestinationDirectory.cs))

Implement bounded copy mechanics behind disabled admission: checked 64-bit offsets/EOF, one bounded buffer aligned for both volumes, nonpaging reads with explicit offsets and preserved synchronous position, aligned noncached backing writes, zero final padding, exact output EOF and completed flush. Distinguish expected tail partial reads from unexpected EOF, lock conflict, cancellation and error. Complete an exact stage/version seed receipt before exposure, with no namespace/stream locks across disk waits. Existing 64-KiB/16-MiB helper evidence covers mechanics and the old product limit; it is not full-file transport or coherence qualification, and this report changes no threshold. ([Current helper](../agente/SafeUpload.Agent.Service/Interception/StagedBackingFile.cs), [Existing limit control](../driver/scripts/Test-StagedSeedLimit.ps1), [Read/EOF algorithm](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/aa57e052-40d4-4d9f-837d-2b0ce7c87cf4))

**Whole-copy synchronization remains unproved.** Same full ID, stable EOF, repeated digest or per-chunk locking cannot rule out fixed-size alternate contents between reads. Ordinary range-lock semantics involve owning Open and Key; `FltReadFileEx` can carry a key, but mappings ignore byte locks. Whole-file locks also alter compatible writers' observable behavior. Oplock availability cannot be assumed on original sync/async objects, and documented advisory RH notification alone does not block writes until acknowledgement. Establish a supported interval/linearization mechanism covering cached/noncached writes, append/truncate, existing writable mappings and hard-link access while preserving native sharing/status. If a candidate works only by rejecting otherwise supported native requests, that is an unresolved mechanism limitation, not permission to narrow the product surface. ([Range conflicts](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/124bb289-eeef-4653-b9c6-4fb93dd07a21), [FltReadFileEx](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltreadfileex), [Byte-range locks and mappings](https://learn.microsoft.com/en-us/windows/win32/fileio/locking-and-unlocking-byte-ranges-in-files), [Oplock request restrictions](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_request_oplock))

**Read/export authority is independent of seed I/O.** A successful internal read does not authorize returning old bytes to a user, and a write-only request does not prove the subject is read-denied. A retained-subject/complete-source-descriptor calculation is a candidate that avoids extra live sharing reservations; `SeAccessCheck` does not document complete NTFS traversal, label or audit equivalence, and MIC adds label-sensitive restrictions such as NO_READ_UP. Qualify its decisions against native READ_DATA controls under unchanged subjects/privileges. A live probe's sharing failure remains indeterminate, not denial or approval; record exact status, identity and effects. Original effective identity comes from the thread client token when present, otherwise the primary token; process SID/session alone cannot identify the intended recipient. ([SeAccessCheck](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-seaccesscheck), [MIC](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control), [Effective subject token](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-sequerysubjectcontexttoken))

Persist immutable old-public lineage, exact source/security binding, seed EOF/completion/coherence evidence, authorization outcome/status, intended effective recipient and exact stage/version/predecessor commitment. Every preserving private child/grandchild carries lineage and authorization evidence; a new recipient still needs affirmative authority. New/absent and truncating/superseding allocations explicitly start without old public bytes. Later writes, final length or an all-byte rewrite do not erase conservative lineage. Before hand-back copy, existing-copy recovery or justification, validate the exact version/digest and recipient-bound affirmative export receipt, then recipient/profile/ACL facts. Missing legacy metadata, receipt loss, same process SID with changed effective subject, changed recipient or altered retry cannot create permission. Ordinary read-authorized hand-back/justification and full-replacement behavior remain required. ([Provenance contract](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md), [Current recipient resolution](../agente/SafeUpload.Agent.Service/Interception/StagedHandbackCopier.cs))

The owner has two pending choices when preserved old bytes are unreadable or read authority is unresolved. One preserves native write-only **clean editing/publication** but keeps blocked versions service-private using existing Blocked + HandbackState.Failed, without a readable full-file hand-back or justification. The other requires affirmative read authority before admitting preserving edits, deliberately restricting those edit/append cases while retaining new/full-replacement behavior. **Neither is selected here.** Metadata, replay equality, original-recipient capture, bounded mechanics and isolated control specifications can be prepared independently; uncertain read/coherence mechanisms cannot become policy by default. ([Exact pending options](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md))

## Five stages and seven gates bound implementation

The practical sequence begins by defining immutable descriptor/provenance records, binary comparators and the negotiated carrier's reserved-number/phase/bounds contract. Next implement the writer factory, exact original lookup, complete snapshots and transaction-to-app lease ownership, resolving low-subject and nonmutating CREATE transformations through isolated comparisons. Then connect authenticated metadata fetch and exact manifest replay to corrected allocation/publication, including the original service CREATE descriptor and callback/stored checks. Fourth integrate exact-object bounded seed mechanics, a proven whole-copy synchronization mechanism and recipient/provenance propagation; remove the service public-source read dependency only when the replacement is integrated. Finally connect shared head/permit/recovery and complete local cancellation/cleanup/retirement behavior, pass the required static/service gates and obtain the **single integrated kernel lifetime/lock/retirement review before any revised protected boot**. The table defines finite required evidence; it does not authorize executing stopped product runs. ([Writer integration requirements](../driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md), [Publication qualification gates](../driver/docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md))
