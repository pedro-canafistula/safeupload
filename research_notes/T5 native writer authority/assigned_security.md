# T5 complete assigned security and kernel/service metadata transport

Research date: 2026-10-13. One focused design pass; no product edits, VM execution, host configuration, assertion changes, or runtime qualification. Repository observations refer to the current workspace. Proposed mechanisms below require the existing review and qualification gates; they authorize neither live bound-head admission nor a new owner policy.

## What descriptor and CREATE semantics must the bound writer preserve?

### Takeaway

Capture construction inputs and produce an immutable descriptor under the original effective static subject. Existing-target opens, overwrite and supersede retain the checked target security in the tested NTFS cases; absent-target creation requires a real parent-create authorization and complete native-equivalent assignment, with creator grants treated separately from the new object's DACL.

### Cited Findings

- The reviewed contract requires the original static subject, process lifetime, mapped/previously granted access, original sharing/disposition/options/attributes, EAs, supplied descriptor and original lookup/case semantics. Capture is now present, but the checked writer backend, complete ancestors, assignment, coherent seed and live admission remain unfinished. — [T5 native writer contract](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:456), [owned CREATE input](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.h:9), [capture implementation](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2583).
- The current `StageSecurity.c` helper opens metadata by case-insensitive pathname with share bypass, obtains only owner/group/DACL, performs a separate DACL check, requires traverse privilege, and for absence calls `SeAssignSecurityEx` with only DACL automatic inheritance. It then checks the assigned descriptor against the creator's requested access. These operations do not implement the reviewed bound-writer contract. — [existing helper](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageSecurity.c:18), [absence assignment](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageSecurity.c:145).
- For an absent final component, native OPEN and OVERWRITE fail; creation of a data file checks parent FILE_ADD_FILE or applicable original restore authority. The MS-FSA new-file algorithm grants remaining requested access and initializes security from the subject default DACL plus parent inheritance; it does not run an existing-file DACL check on the newly assigned descriptor to decide the creator's initial grant. MS-FSA is an abstract object-store specification, not a complete local NTFS supplied-descriptor recipe. — [MS-FSA open](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8ada5fbe-db4e-49fd-aef6-20d54b748e40), [MS-FSA new file](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/498a5eeb-afc9-445f-99ed-a7e4b73c648b).
- The nine repository supplied-descriptor controls succeed for the four absent-target creation dispositions despite requesting WRITE_DATA and supplying an FR-only protected DACL. The five successful existing-target cases, including supersede, retain the before/after queried SDDL. This is builder evidence for the tested descriptor, not full binary descriptor equivalence or product-platform qualification. — [raw supplied-descriptor control](/home/victor/Work/safeupload-staging/driver/evidence/2026-10-12/writer-supplied-descriptor-native-a6.txt), [test construction](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:312).
- Existing-file overwrite/supersede has supplemental EA/attribute checks; supersede introduces DELETE while overwrite introduces WRITE_DATA. The repository's initial permission controls and later split-lifetime controls establish the tested projection and sharing behavior, including the need to close the supplemental-rights check before retaining an original-rights lease. — [MS-FSA existing file](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/41f3734a-5bba-4c3b-9d04-7baafc9b7bfe), [reviewed evidence and split checks](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:548).
- `SeAssignSecurityEx` builds a self-relative new-object descriptor from parent, explicit descriptor, subject defaults and generic mapping. Its flags govern DACL/SACL inheritance, owner/group selection and checks; assignment can fail for invalid owner or missing SeSecurityPrivilege. Inherited ACEs in explicit input are not copied, and new inherited entries follow explicit entries. It runs at PASSIVE_LEVEL and allocates paged storage. — [SeAssignSecurityEx](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-seassignsecurityex).
- Mandatory integrity is evaluated in addition to DACL access. Labels reside as mandatory-label ACEs in the SACL; an unlabeled object is treated as medium integrity. A related documented private-security construction API exposes token-derived mandatory-label flags, but its existence does not prove which flags local NTFS uses for each create. — [MIC](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control), [CreatePrivateObjectSecurityEx](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-createprivateobjectsecurityex).

### Inferences

The implementable writer preparation needs distinct outcomes:

| Checked state and disposition | Security result | Initial app authority and bytes |
| --- | --- | --- |
| Present + CREATE | Native collision; no assignment or allocation authority | No successful app open |
| Present + OPEN / OPEN_IF | Full security of the exact checked target | Native original grant; seed existing bytes under the separate read/coherence contract |
| Present + OVERWRITE / OVERWRITE_IF | Full checked target security | Calibrated implicit check, then original-rights lease; empty/truncated private data |
| Present + SUPERSEDE | Full checked target security in current controls, including when the tested supplied descriptor is present | Supplemental DELETE/EA/attribute check must not enlarge the retained app grant; empty private data |
| Absent + OPEN / OVERWRITE | Native absence error | No successful app open |
| Absent + SUPERSEDE / CREATE / OPEN_IF / OVERWRITE_IF | Native-equivalent new-object assignment from exact parent, original supplied input and static subject | Parent/native-create authorization, native initial grant and CREATED result; no old public bytes |

This table operationalizes the [reviewed disposition contract](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:476) and the native controls above. It must not turn the existing helper's post-assignment `SeAccessCheck` into a requirement that denies a restrictive-descriptor new-file creator. Later opens still require their own current native authority.

Use one immutable kernel assignment record attached to the existing CREATE/version owner. Keep separate fields for: original supplied descriptor (including presence versus NULL); exact parent/target stored snapshots; assignment algorithm/version/flags; assigned construction descriptor; expected native stored form; original requested/mapped/previously granted access; actual app grant; original case flag; original share/disposition/CREATE result; and seed/read provenance. The record must identify the held subject and checked objects without exporting token handles or treating PID/SID as filesystem permission. The [current CREATE capture](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2583) supplies inputs, not this result.

For fresh creation, `SeAssignSecurityEx` is a documented candidate assignment primitive, not an NTFS-equivalence theorem. Reconstruct/retain the `SECURITY_SUBJECT_CONTEXT` from the original static token correctly; never use the worker's subject. Include both DACL and SACL inheritance where native controls require it, owner/group defaults, creator-owner/group and generic mapping, mandatory policy, supplied owner validity, enabled original privileges, restricted/deny-only groups and owner-rights restrictions. Do not set AVOID_OWNER_CHECK/AVOID_PRIVILEGE_CHECK or parent-default flags merely to make assignment succeed. Do not force a medium label or copy the service's integrity level. — Candidate grounded in [the reviewed assignment requirement](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:531).

For present objects, an immutable full snapshot must come from the currently checked exact target, with equality across the two sequential permission-check/original-grant opens and again after allocation. A cached `view->Security`, a primary-PID token, private-stage ACL or stale earlier overwrite descriptor cannot replace that result. — [reviewed revalidation requirement](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:497).

### Gaps

- Exact NTFS assignment flags, token mandatory-policy behavior, owner-rights restrictions and arbitrary supplied-descriptor behavior are not established by the nine SDDL controls. Run a native-versus-candidate binary assignment control on the qualified Windows build before relying on a new constructor.
- New-object initial grant, MAXIMUM_ALLOWED, previously granted bits and owner/supplied-descriptor failures need their own differential matrix. Existing-target 980 comparisons do not answer them.
- Existing supersede with unusual supplied SACL/owner/group/control combinations needs explicit tests for validation/ignored-input status, even where successful operations retain target security. Do not infer that every supplied input is ignored without validation.

## How can exact retained objects be queried and complete descriptors compared without extra app rights?

### Takeaway

Keep caller authority on the original-rights/share-checked object, and obtain complete metadata through a separate evidence mechanism. Public documentation does not promise a full security-query bypass on a write-only retained object; the finite direct-query or metadata-only exact-object control must be resolved before integration.

### Cited Findings

- `FltQuerySecurityObject` takes the exact FILE_OBJECT and returns self-relative security. Its documented owner/group/DACL query requires READ_CONTROL, and SACL requires ACCESS_SYSTEM_SECURITY; failure can be ACCESS_DENIED. `ZwQuerySecurityObject` documents the same handle rights and recommends the minifilter API. Neither page establishes that a write-only original lease may query all security without those rights. — [FltQuerySecurityObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltquerysecurityobject), [ZwQuerySecurityObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-zwquerysecurityobject).
- The SDK documents BACKUP_SECURITY_INFORMATION as all parts of a descriptor, requiring READ_CONTROL and ACCESS_SYSTEM_SECURITY to query; label, resource attributes and CAP scope have separate flags. The WDK FltQuerySecurityObject page lists only the traditional four flags. That documentation mismatch means full-mask behavior on the qualified local NTFS path must be tested rather than assumed. — [SDK SECURITY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information), [WDK query information](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/security-information).
- NTFS limits a security descriptor written for a file to 64K, so a 64K query buffer is documented as sufficient for its returned stored descriptor. This supports the existing stored-query bound for M2 fixed NTFS; it is not a general limit on every raw input representation. — [ZwQuerySecurityObject remarks](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-zwquerysecurityobject).
- MS-FSA share checks classify data read/execute/write/append and DELETE; metadata READ_CONTROL/ACCESS_SYSTEM_SECURITY are outside that data-right set. Its open algorithm still considers oplocks. Thus a metadata-only object is a reasonable candidate for observation while a share-0 writer lease remains held, but local native behavior and side effects must be controlled. — [MS-FSA sharing](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8c0e3f4f-0729-49f4-a14d-7f7add593819).
- SDDL omits owner/group/DACL/SACL defaulted flags; it also abstracts representation. SDDL equality therefore cannot prove the requested complete assignment contract. — [Security Descriptor String Format](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-string-format).
- SE_DACL_DEFAULTED affects assignment and is not physically stored in the associated object's security descriptor. SE_DACL_PRESENT is always set after association. Other control bits describe owner/group defaults, inheritance/protection, SACL presence/defaults, self-relative form and resource-manager control validity. — [SECURITY_DESCRIPTOR_CONTROL](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-control).
- ACLs contain an ordered ACE list; AclSize also includes unused memory. AclRevision distinguishes object-specific ACLs. The descriptor validator checks self-relative format with a supplied length and required information, but does not establish authorization or semantic equality. — [ACL structure](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-acl), [RtlValidRelativeSecurityDescriptor](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-rtlvalidrelativesecuritydescriptor).
- The current native controls convert binary query results to SDDL (`GetKernelObjectSecurity` mask 0x1F), and the supplied-descriptor control's before/after comparisons are also SDDL. The ID-query a8 control is successful for write-only/share-0/asynchronous retained objects; that success is not a full-security-query result. — [control security helper](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:122), [ID-only gate](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:573).

### Inferences

Preferred controlled query candidate: invoke `FltQuerySecurityObject` directly on the checked retained object, requesting a demonstrably complete stored security mask into owned bounded storage. If the qualified kernel control proves this operation works without modifying the original app grant, retain that exact-object mechanism. Do not claim documentation guarantees success on a READ_CONTROL-denied/ACCESS_SYSTEM_SECURITY-absent lease. — Based on the [query contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltquerysecurityobject) and [retained-object requirement](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:497).

Alternative controlled observation candidate: below the original instance, open a nonmutating metadata-only handle with READ_CONTROL|ACCESS_SYSTEM_SECURITY, broad metadata sharing, no READ_DATA/WRITE_DATA/APPEND/DELETE, and exact held-parent/leaf or an exact file-ID selector with full-ID verification. Match it to the caller-checked retained object's full ID and canonical link before accepting any descriptor. This handle is observation authority only; its privilege and descriptor cannot authorize the writer or export seeded data. Revalidate every ancestor's ID, link/case mode and full stored security. Metadata helpers may use their own narrowly scoped observation authority without adding those rights to the application's lease. Never enable privileges on the original subject or inherit helper rights into the app grant. Do not use IO_IGNORE_SHARE_ACCESS_CHECK. — Candidate supported by [the share algorithm](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8c0e3f4f-0729-49f4-a14d-7f7add593819) and [separate metadata-anchor contract](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:493).

The alternative needs explicit validation for share 0, delete-pending/rename, async append/write, metadata-read denial to the caller, and oplock/audit effects. A service path reopen and a matching ID alone do not establish the original link or complete ancestors. Keeping the original app lease remains mandatory whichever observation mechanism works.

Define two comparators, sharing one canonical codec:

1. **Construction/callback equality:** compare the retained immutable assigned construction descriptor with the owned descriptor actually supplied at the publication CREATE callback. Preserve all meaningful fields exactly, including ordered ACE bytes, owner/group SIDs, NULL/absent/empty ACL distinctions, ACL revisions, labels, defaulted/protection/inheritance/control bits and valid RM control. Validate bounds before parsing; use self-relative offsets only; retain no caller pointers.
2. **Stored-object equality:** compare actual full post-CREATE security with the native stored-form expectation derived from the original assignment/snapshot. Treat documented nonpersisted construction bits explicitly; do not use a blanket control-bit mask. In particular, requiring post-query DACL_DEFAULTED to equal construction input contradicts the documented storage rule. Preserve the input bit in immutable provenance while checking the exact native stored result.

The codec may normalize component placement and zero representation padding; it must never reorder/canonicalize ACL ACE order, remap already assigned masks, strip unknown valid ACE payloads, replace labels, change protection, or round-trip through SDDL. Whether unused ACL tail bytes matter should be stated as representation policy and tested against native normalization; the ordered meaningful ACE payload remains exact. Retain source binary blobs alongside the canonical comparison form for diagnostics and replay. — Design inference from [control semantics](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-control), [ACL representation](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-acl), and [publication equality requirement](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md:65).

### Gaps

- Full retained-object security query without changing app rights has not been demonstrated in the reviewed evidence. FltQuerySecurityObject access requirements must not be hand-waved as a KernelMode bypass.
- BACKUP_SECURITY_INFORMATION versus an explicit supported complete flag set must be compared on the actual minifilter/NTFS path, including labels/resource attributes/CAP and any Win10-supported SACL ACE families. No silent partial-descriptor fallback.
- Complete target/root/ancestor security observation needs native share/oplock/rename controls; the a6 zero-access revalidation failure does not qualify this metadata-only alternative.
- Defaulted/control persistence must be recorded at original input, assigned construction, actual callback and native post-query. Full equality cannot be defined solely from SDDL or raw arbitrary offsets.
- Supplying an already assigned descriptor on a SYSTEM temporary CREATE is not proven idempotent: inheritance may drop/recompute inherited entries, and mandatory-label handling may use the service token. Do not repair a mismatch by adding PROTECTED flags, stripping inherited flags or post-setting security with a privileged handle. A failing native round-trip control leaves this construction unresolved and admission off; it must not silently narrow supported writer requests.

## What bounded transport, integration points and differential controls are required?

### Takeaway

Keep V18/V23/V26 immutable and add a separately negotiated, typed, read-only allocation-metadata carrier tied to the active original CREATE reservation. Persist exact descriptor/provenance metadata in the existing allocation manifest before the reply; publication must obtain it from that corrected path and compare both callback and stored security before exposing writes.

### Cited Findings

- V18 SAFEUPLOAD_REQUEST is 1192 bytes, with a 128-byte image slot and fixed layout assertions. V23 occupies 124 bytes and carries destination/reservation/predecessor/disposition identities and parent case mode, with no original case flag, assigned descriptor or seed/read provenance. — [immutable core layout](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/Protocol.h:1750), [V23 layout](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageBoundAllocation.h:11), [agent V23 parser](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Minifilter/BoundAllocationV23.cs:65).
- `_stageBoundHeadReady` is explicitly false, both allocation and reply require it, and the reserved capability is not advertised. PID/session/SID/process creation checks on replay verify writer ownership, not filesystem authority. — [bound dispatcher](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Service/Interception/MinifilterBoundAllocation.cs:11).
- Current bound allocation creates/copies the stage using a service-held public source or a private predecessor, applies the private `_fileSecurity`, checks target identity, and commits the binding. The journal persists `AllocationExtensionVersion=23` and `BoundAllocation` but lacks assigned-security/seed provenance. The current service public read open has its own access/share mask, so it cannot implement the reviewed exact retained-object seed path. — [bound allocator](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Service/Interception/StagedBoundTransferAllocator.cs:50), [allocation journal](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Service/Interception/StagedBoundAllocationJournal.cs:31), [public source open](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Service/Interception/StagedDestinationDirectory.cs:82).
- V26 publication control 33 has a fixed 960-byte request and 128-byte typed response. Its permit transports no descriptor. The service must already possess assigned security, supply it as its original UserMode NtCreateFile OBJECT_ATTRIBUTES.SecurityDescriptor, and the kernel must compare copied callback security and full post-CREATE security before admitting temporary writes. The service temporary handle gets no WRITE_DAC/WRITE_OWNER/ACCESS_SYSTEM_SECURITY. Missing assignment requires NotReady. — [publication contract](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md:48), [V26 layout](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageBoundPublication.h:9).
- The existing publisher explicitly refuses bound allocations with “requires the anchored head/permit dispatcher,” preventing fallback to legacy publication. Current required controls include no leaked temporary write grant, actual CREATE outcome/security, exact target checks, recovery and integrated kernel lifetime review before boot. — [publication guard](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Service/Interception/StagedTransferPublisher.cs:83), [qualification contract](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md:251).
- Seed provenance and affirmative source-read/recipient authority must survive private predecessors and later writes. The unreadable-seeded-bytes owner choice is explicitly pending; no new policy/state is approved. — [seed/provenance contract and owner choices](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md:609).

### Inferences

**Concrete carrier proposal, not a reserved ABI number:** allocate the next available feature-only control/extension and a separate negotiated metadata capability after inventorying existing reservations. Do not resize V23, reuse V26's permit fields, or relax existing parsers/assertions. Keep V23's exact snapshot and use its reservation as the lookup key; the additional carrier is required by the live dispatcher, so an old pair cannot silently allocate without metadata. — Based on [existing immutable layouts](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageBoundAllocation.h:11).

Use a fixed pack-4 **read request header** with: core control version/size; extension/version/phase; driver-instance GUID; current authenticated connection epoch and authority revision; allocation reservation GUID; current V23 request ID; metadata snapshot GUID; expected immutable metadata digest; section kind; offset/page length; reserved-zero fields. The first read expects an unspecified snapshot/digest only in the documented discovery phase; later reads must supply the exact returned snapshot/digest. Define exact phase-dependent zero rules and complete length/tail validation. Do not transmit pointers, kernel handles, token handles or arbitrary path authority.

Use fixed-size bounded **reply pages** with the same identities, metadata format version, total length, section count, page offset/count, completeness, exact typed status, a digest and zero tail. Choose a page size compatible with FilterSendMessage/FilterGetMessage buffers after checking both existing endpoints; the descriptor stored form needs no more than the existing 64K NTFS bound. The total record must be bounded by the documented scope and explicit section lengths, with checked arithmetic and no attacker-directed allocation. Construction input and expected stored descriptor are distinct sections. Do not force raw input into a stored-descriptor bound before determining native acceptance. No product size threshold/assertion is changed by this research.

Required typed sections:

- `Binding`: exact V23 snapshot bytes or digest plus canonical UTF-16 leaf and root/parent/public identities, original lookup case flag, original requestor mode, static subject identity for ownership, access/share/disposition/options and expected app result.
- `AssignedSecurity`: canonical-codec version, assignment semantic version/flags, source kind (new-parent assignment versus existing checked target), complete query mask/status, descriptor construction bytes, expected stored descriptor bytes, original supplied-descriptor presence/digest, and original parent/target snapshot digests.
- `ValidationTuple`: full ancestor count and aggregate immutable digest, mount/volume/root/parent identity and case/link observations. Complete per-ancestor bytes may stay kernel-owned if the service never makes a decision requiring them; service receives a typed commitment to the entire tuple, while post-RPC kernel revalidation compares every actual ancestor.
- `SeedProvenance`: source kind (none/exact public/sealed private predecessor), source full identity/version/digest/EOF, recipient binding, independent read-authorization outcome and exact status, coherence evidence/version, and predecessor provenance commitment. A share failure is an unresolved read probe, not denial or permission. None means affirmatively no copied old public bytes, not missing data.

Bind the immutable snapshot to the existing attach/version lifetime; read pages from a referenced active owner, outside global locks, with bounded local buffers. Reconnect invalidates channel admission, and a new driver instance cannot serve an old reservation. Paging across a changed snapshot/revision returns typed retry/refusal, never partial success. Snapshot pages grant no CREATE/delete/publication authority. This design needs no new general kernel reclamation scheme or persisted recovery state; its lifetime follows the already required attach/version references. — Proposed attachment to [existing capture ownership](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2583).

Service sequence: parse exact V23 only under the new negotiated capability; fetch/validate the full authenticated snapshot; acquire the existing destination turn; persist metadata format, canonical bytes, hash, provenance and exact binding atomically with the existing allocation manifest; require byte-exact immutable metadata on retry; then return the existing typed allocation result. The driver retains its original immutable record and performs post-allocation complete-tuple equality before exposure. A lost reply follows existing exact candidate-retirement/receipt semantics. Replay must never refresh a saved descriptor from current SYSTEM observations or infer source provenance from final length. — Proposed extension of [current allocation journal](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Service/Interception/StagedBoundAllocationJournal.cs:31).

Publication sequence: load the saved immutable descriptor for the exact allocation/version; preserve original service UserMode CREATE inputs; supply the descriptor through original OBJECT_ATTRIBUTES; compare bounded canonical callback copy to construction expectation; retain both through post-CREATE; query full security of the actual created exact FILE_OBJECT and compare stored expectation before granting writes. An absent section, digest mismatch, unsupported representation or incomplete metadata refuses the candidate and leaves CreatePermit NotReady; it must never substitute a stage ACL, service defaults or privilege-injected AccessState. This is prerequisite enforcement while incomplete, not approval to reject supported requests as a permanent simplifying policy. — [publication equality contract](/home/victor/Work/safeupload-staging/driver/docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md:59).

**Concrete integration seams:** add the owned assignment/snapshot to the corrected writer preparation alongside `SAFEUPLOAD_STAGE_CREATE_INPUT` and original subject in StagePublic/StageStream; replace StageSecurity authority shortcuts only for this path; integrate typed metadata control/authentication in Communication/StageProtocol; add a dedicated agent binary codec/control client next to BoundAllocationV23; require it in MinifilterBoundAllocation before AllocateV23Async; extend existing manifest immutable comparison/validation and private-predecessor ancestry with descriptor/provenance fields; remove the service public-read seeding route from the live path; and connect corrected publication to the original descriptor at UserMode NtCreateFile plus callback/post validation. Keep native DELETE/public read-only factory separate: its explicit DELETE requirement means it is not the ordinary writer lease factory. — [backend factory](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:603), [current readiness guard](/home/victor/Work/safeupload-staging/agente/SafeUpload.Agent.Service/Interception/MinifilterBoundAllocation.cs:11).

1.
