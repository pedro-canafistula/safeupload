## 1. Disposition-specific NTFS checks, original grant and effective subject

### Takeaway

Implement a separate checked-writer factory with two **sequential** nonmutating NTFS opens: disposition-check authority first, then original requested authority. Close the first handle and object completely before opening the second; retain only the second object's native share reservation per application FILE_OBJECT through cleanup. [Required two-open correction](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:474)

### Cited Findings

- The attach transaction already owns the original requestor process, static effective subject, desired/original/remaining/previously-granted masks, sharing, complete options, operation flags, attributes, allocation size, copied EA bytes and supplied descriptor. This is input retention, not a grant. Existing-view reopens also capture a current subject. [CREATE input](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.h:9), [capture](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2583), [queue capture](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2811)
- The existing `SafeUploadStagePublicOpenBackend` is a DELETE backend: it requires both a queried DELETE grant and `PublicObject->DeleteAccess`. Its absolute-name validation and removal of FILE_OPEN_BY_FILE_ID also prevent simply reusing it as the writer factory. [Existing backend](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:600)
- Microsoft describes disposition-implied checks: supersede requires DELETE; overwrite requires write authority; overwrite/supersede can require EA and attribute writes when Restore is unavailable. Constructive dispositions also need the containing directory check. The example is filesystem guidance, not a complete NTFS-equivalence implementation. [WDK special CREATE cases](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/checking-for-other-special-cases--on-irp-mj-create)
- The current native control's Restore-disabled candidate uses `original | DELETE | FILE_WRITE_EA | FILE_WRITE_ATTRIBUTES` for existing SUPERSEDE, `original | FILE_WRITE_DATA | FILE_WRITE_EA | FILE_WRITE_ATTRIBUTES` for existing OVERWRITE/OVERWRITE_IF, and unchanged original access for OPEN/OPEN_IF. Its 980 comparisons cover those five dispositions, seven request masks and seven ACL profiles/four existing-share conditions, but not present FILE_CREATE, arbitrary CREATE flags or enabled Restore behavior. [CheckAccess](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:127), [matrix](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:334), [recorded evidence limits](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:548)
- MS-FSA expressly permits parent FILE_DELETE_CHILD to contribute to a target DELETE grant. Let NTFS perform that alternative; do not manually accept the operation based only on a parent DACL calculation. The repository's existing controls prove the tested supersede cases, not every token/path/flag combination. [MS-FSA existing-file access](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/82b364ce-6d7b-422f-8d88-4db32eea809a), [native outcomes](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:548)
- The native share-lifetime correction records a real failure when supplemental supersede DELETE remains open: a later reader can receive a sharing violation that the native original-grant handle would not produce. The split control passes 90 combinations and explicitly disposes the check before the lease. [Required correction/evidence](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:584), [split control](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:183)
- `FltCreateFileEx2` routes below the supplied instance, returns a handle and optionally a referenced FILE_OBJECT, and requires both resources to be released. The contract warns against non-NULL top-level IRPs. A share bypass changes bookkeeping, including what later opens can succeed; it is unsuitable for the caller-authority opens. [FltCreateFileEx2](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltcreatefileex2)
- Query the **final lease** using `ZwQueryObject(ObjectBasicInformation)` and its documented `PUBLIC_OBJECT_BASIC_INFORMATION.GrantedAccess`. The supplement's projected grant is useful for comparison; it must not replace a final native grant. [ZwQueryObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-zwqueryobject), [documented granted-access field](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_public_object_basic_information)
- Static subject capture copies the effective token and needs matching `SeDeleteClientSecurity`. Crucially, Microsoft documents `STATUS_BAD_IMPERSONATION_LEVEL` when the effective client token is Identification/Anonymous and cannot be passed to another server. Current `CaptureCreateSubject` bypasses the explicit guard but still calls this DDI; that does **not** document identification-token support. [Capture implementation](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:144), [SeCreateClientSecurityFromSubjectContext](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-secreateclientsecurityfromsubjectcontext)
- `SeImpersonateClientEx` reports failure and must be matched by `SeStopImpersonatingClient` after success. Restricted-token access requires both enabled-SID and restricting-SID checks; a caller SID/session is ownership metadata, not a substitute for the retained token. [SeImpersonateClientEx](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-seimpersonateclientex), [restricted-token semantics](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-sefiltertoken), [caller binding](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:46)

### Inferences

1. Add a writer-specific factory consuming `SAFEUPLOAD_STAGE_CREATE_INPUT`, the exact captured subject/process and original instance, returning an immutable checked snapshot plus an owned original-grant lease. Validate the fixed local NTFS instance and run only on the unimpersonated system worker, outside namespace/stream/spin locks. Impersonate only around the two caller-checked CREATEs, use `OBJ_KERNEL_HANDLE | OBJ_FORCE_ACCESS_CHECK | OBJ_DONT_REPARSE`, original case behavior and original sharing, and revert on every exit. Follow the existing delete factory's worker and cleanup structure without its mandatory DELETE check. [Existing factory](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:600), [writer contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:456)
2. For a present target, use FILE_OPEN, never a destructive disposition, for the temporary check. Query the checked object's full identity directly; obtain all other state through separate non-data metadata anchors. After capturing the complete tuple, close/dereference the temporary authority; open the **same original lookup** with only original requested rights/share, obtain the final granted mask and ID, and recapture/compare the complete tuple. A mismatch or failed native open fails before RPC/exposure. No overlapping supplemental/lease authority handles are allowed. [Two-open contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:474), [split control](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:183)
3. Preserve the application disposition result separately: existing OPEN/OPEN_IF → FILE_OPENED; existing OVERWRITE/OVERWRITE_IF → FILE_OVERWRITTEN; existing SUPERSEDE → FILE_SUPERSEDED; eligible absent creation → FILE_CREATED. Present FILE_CREATE keeps its qualified collision result. The helper FILE_OPENED is never the application result. Preserve status/IOSB failures as qualified by direct controls, rather than translating every failure to ACCESS_DENIED. [Current app-result mapping](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2449), [native IOSB/dispositions](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile)
4. For proven absence, do not fabricate a target lease. Check FILE_ADD_FILE on the exact parent under the same subject, preserving the original request's traversal/case/root semantics, then construct assigned security using original subject/supplied inputs and exact parent. OPEN/OVERWRITE retain absence failure. CREATE/OPEN_IF/OVERWRITE_IF/SUPERSEDE need their qualified creation checks. The private stage's successful SYSTEM CREATE is not the authorization check. [Absence contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:480)
5. Carry checked grant into `STAGE_HANDLE`/AccessState and private sharing; do not re-run the current cached-view DACL helper as authority. Apply the established T10 exclusion of WRITE_DAC/WRITE_OWNER/ACCESS_SYSTEM_SECURITY to staged data grants, preserving the separate supported security-only public route. The control's MAXIMUM_ALLOWED grant is an observed native grant, not permission to expose those excluded rights. [Cached-view check](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2186), [T10 restriction](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:548)

### Gaps

- The fixed Restore-disabled bitmask is not a proof for enabled caller backup/restore privileges. Production must retain the caller's enabled privileges and original backup intent, not disable them like the fixture or add them like a privileged fallback. Also qualify original `DesiredAccess` versus Original/Remaining/PreviouslyGrantedAccess handling; the controls do not cover pregranted access states. [Fixture subject](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:30), [captured masks](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2591)
- Identification/Anonymous capture and native outcome equivalence remain a finite gate. Compare the original native request, capture DDI result and candidate result at each actual token level; preserve exact failure where native fails. If native succeeds and capture fails, implementation needs a documented way to preserve that original subject/request; neither promotion nor SYSTEM/DACL substitution is justified. `IO_DRIVER_CREATE_CONTEXT` has ECP/device/transaction/silo fields, no documented subject/AccessState injection field. [Capture restriction](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-secreateclientsecurityfromsubjectcontext), [create context](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_io_driver_create_context)
- **Exact token-level control required before admission:** add a native-versus-candidate fixture covering primary-token requests and effective Anonymous/Identification/Impersonation/Delegation thread tokens, plus restricted and deny-only variants. Under each original token, record the direct original NTFS CREATE's return status, IOSB Status/Information and actual grant; record the original-callback capture DDI result/retained token level and worker two-open result/grant; require exact native acceptance/status/IOSB/app-grant equivalence for present and absent targets and existing-view reopens. Candidate probes must retain bytes/identity/descriptors, preserve process/thread privilege state, and never increase the retained impersonation level. Include denied target rights, parent DELETE_CHILD, traversal and labels. A documented capture failure is not itself evidence that the original native CREATE fails: if the fixture exposes native success/candidate rejection, admission stays disabled while the subject-preserving implementation is corrected. The current fixture always duplicates an impersonation-level (level 2) token, so it supplies no evidence for the low levels. [Current fixture token construction](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:36), [required no-promotion/native controls](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:468)
- Supplemental FILE_OPEN equivalence still needs denied traversal/labels, readonly/image restrictions, arbitrary supported EA/attributes/descriptor combinations and oplock-related CREATE options. Preserve original inputs and qualify safe probe transformations rather than blindly forwarding mutating CREATE inputs or dropping flags to make tests pass. Present FILE_CREATE's collision and error precedence are not covered by the 980 matrix. ## 2. Preserve original RelatedFileObject, raw-ID, opened-name and case lookup

### Takeaway

The captured `LookupRoot` + exact `LookupName` + `LookupById` + original operation flags are the authority lookup inputs. The normalized service locator can help construct/check a bound destination after NTFS resolves the original request, but must not replace those inputs for either authority open. [Lookup capture](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:191), [required contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:599)

### Cited Findings

- Relative requests retain the original `RelatedFileObject` and unchanged `FileName` even when the name looks rooted. Same-volume checks precede publication; non-ID relative roots are verified as directories. Absolute name requests retain filesystem-only OPENED form. ID requests keep raw bytes and do not require Unicode even-length validation. [Current capture](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:191)
- NTFS ID selectors can contain binary 8/16-byte reference/object IDs and are not safely treated as Unicode or null-terminated strings. Original case operation flags are separately retained from parent case mode. [NtCreateFile binary selectors](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile), [operation flag capture](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2600)
- `FltCreateFileEx2` can use a RootDirectory handle. `ObOpenObjectByPointer` produces a handle to the object pointer, requires an existing file handle/FO_HANDLE_CREATED, and requires matching ZwClose. KernelMode opens can bypass object access restrictions; such a handle is only an internal locator, never a target caller grant. [Relative opens](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltcreatefileex2), [ObOpenObjectByPointer](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-obopenobjectbypointer)
- File-ID opening can succeed without traverse permission to the object's pathname; Microsoft specifically warns against exposing a pathname that the caller cannot traverse. Hence a canonical metadata walk must not introduce new caller pathname/traverse requirements into the ID authority check. [WDK special cases](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/checking-for-other-special-cases--on-irp-mj-create)

### Inferences

- For the two authority opens, use the captured name bytes unchanged. When `LookupRoot` is present, obtain a temporary kernel handle to that **same object** for RootDirectory, not a new directory open by name; close that object-manager handle with ZwClose on all paths. Keep FILE_OPEN_BY_FILE_ID when captured, and derive OBJ_CASE_INSENSITIVE from the original SL_CASE_SENSITIVE separately from metadata component case mode. Root duplication and its lifetime must receive the integrated review; do not claim the temporary root handle as access authority. [Captured pair](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.h:27), [object-handle DDI](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-obopenobjectbypointer)
- Query a canonical normalized/long name from the checked object, then verify its particular parent/leaf link against retained metadata anchors and the checked full ID. For relative/ID requests this is **binding derivation after the native lookup**, not an authorization reopen by normalized pathname. Check the original root relationship and retain sufficient evidence to distinguish the selected link from another hard link to the same ID. [Bound binding contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:492), [existing anchor helper](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:419)

### Gaps

- The captured original root is currently only a referenced FILE_OBJECT. Reference retention is not a documented substitute for an open handle's cleanup state. Qualify root original-handle close/cleanup during queueing and between the sequential opens, root rename/move, relative `..`/rooted-looking names, and ID opens rooted at a volume object. A missing/changed root cannot trigger a pathname reconstruction fallback. [Current retention/destruction](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:191), [active rundown](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2671)
- Case-sensitive paths, short aliases and hard-link link selection are not proven by the native writer control, which always constructs absolute case-insensitive names. Preserve supported operations and add native/candidate comparisons instead of declaring them unsupported. [Control name construction](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:80), [required original lookup](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:599)

## 3. Complete metadata snapshots, post-RPC revalidation and per-app ownership

### Takeaway

The retained writer FILE_OBJECT is the caller authority; metadata anchors validate its destination and state without a second writer or zero-access target authorization open. Existing root/parent-only helpers and three-part descriptor queries do not satisfy complete ancestor/target snapshots. [Complete revalidation contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:492)

### Cited Findings

- `StagePublicBindAnchoredName` walks components and checks identity/case but closes intermediate objects, retains only root/parent, and has no ancestor descriptors. `StagePublicReadIdentity` queries FileAttributeTagInformation before ID, making it the wrong unchanged helper for a caller lease lacking READ_ATTRIBUTES. [Anchor helper](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:419), [identity helper](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:365)
- MS-FSA's FileIdInformation algorithm requires a correctly sized buffer and returns volume serial/full ID without a READ_ATTRIBUTES condition. Native a8 controls establish the tested 24-byte direct query on synchronous/asynchronous write/append leases including explicit READ_ATTRIBUTES denial. Require exact status/length/nonzero ID, not a truncated ID or source pathname. [MS-FSA FileIdInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/a00d78b9-5a5b-44cc-b389-6c67d53611ee), [retained-object gate](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:570)
- `FltQueryInformationFile` works on an open FILE_OBJECT, at PASSIVE_LEVEL with special APCs enabled and no top-level IRP; it reports a returned length. Port the direct FileIdInformation query through this API on the retained source and qualify it in kernel. [FltQueryInformationFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltqueryinformationfile)
- MS-FSA sharing checks use READ_DATA/EXECUTE/WRITE_DATA/APPEND_DATA/DELETE categories. Non-data metadata access avoids those categories, but still has potential oplock effects. This explains the repository's separate READ_CONTROL|ACCESS_SYSTEM_SECURITY metadata control under a share-0 writer; it does not justify a share-bypassing data open. [MS-FSA sharing algorithm](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/8c0e3f4f-0729-49f4-a14d-7f7add593819), [metadata control](/home/victor/Work/safeupload-staging/driver/scripts/t5/writer-permission-native-control.ps1:291)
- Full security query needs owner, group, DACL and SACL; READ_CONTROL suffices for the first three, ACCESS_SYSTEM_SECURITY is required for SACL. FltQuerySecurityObject returns self-relative security, reports required length, and documents NTFS's 64-KB limit. The current StageSecurity query requests only owner/group/DACL, so it cannot supply the required snapshot/assignment. [FltQuerySecurityObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltquerysecurityobject), [current incomplete helper](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageSecurity.c:79)
- `STAGE_HANDLE` has no public writer lease today. Cleanup currently removes only private stream sharing under namespace/stream locks; close frees the handle. Backend close uses local I/O/rundown and explicitly avoids service waits. [Handle](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:267), [cleanup/close](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:4762), [backend close](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:299)

### Inferences

1. Replace the lossy walk with a bounded owned snapshot vector for **every ancestor including root, parent and target**: full volume serial/128-bit ID, non-reparse/type facts, directory case mode, exact link/component, full queried self-relative descriptor including owner/group, ordered ACLs, mandatory labels, inheritance and relevant control/defaulted bits. Keep mount GUID, canonical long leaf and original request case flag separate. Query metadata under the unimpersonated observer on separate read-only anchors; do not demand new LIST_DIRECTORY/READ_CONTROL/SACL permissions from the writer subject. Exact descriptor/semantic comparison must preserve ACE order and distinguish absent/null ACLs. [Required complete snapshot](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:492)
2. Open target metadata relative to the held parent using only non-data metadata authority (e.g. attributes/security), maximal sharing and no share-bypass flag; verify full ID equals the caller-checked object before accepting any metadata. This is an observer, not another subject grant. Query retained lease FileIdInformation directly. For absence, use complete anchored enumeration and original lookup semantics; buffer truncation/query errors or an ambiguous case/alias match are not absence. [Metadata contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:492), [existing exact-link check](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:479)
3. Sequence: reserve name/predecessor under namespace lock → release locks → perform check/lease plus complete matching snapshot → send/persist exact bound allocation/retry snapshot → outside locks recapture every anchor and target link/ID/security or proven absence, and directly requery lease ID → under namespace lock verify the reserved view/predecessor, caller lifetime, cancellation/channel/instance state and service generation → only then attach/expose. A mismatch retires the candidate through the existing exact receipt path. Do not reopen target with writer rights or zero access after RPC. [Post-allocation contract](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:496)
4. Transfer the original-grant lease from transaction to each successful app `STAGE_HANDLE` exactly once. Every independent CREATE/reopen needs its own current check/lease; duplicate/inherited OS handles share their app FILE_OBJECT, so do not allocate another lease for a duplicate or release on one duplicate's close. On app cleanup, detach ownership under local locks, then drain operations/close the public lease **outside** namespace/stream locks and without RPC. Retain only inert data for final close. On cancellation/failure/teardown before attach, locally close the transaction lease before active lookup removal; final cancellation dereference must remain nonpageable/empty. [Per-app lifetime requirement](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:496), [existing rundown](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StageStream.c:2671), [backend rundown](/home/victor/Work/safeupload-staging/driver/SafeUpload.Minifilter/StagePublic.c:299)

### Gaps

- Native a8/a9 are builder evidence, not kernel/protected runtime proof. The kernel direct-ID query, metadata-only target query under share 0, complete SACL/control snapshots, component-case/alias enumeration and oplock side effects need exact candidate/native checks on the qualified platform. Do not weaken the currently required status/length/grant/byte-unchanged assertions. [Evidence limits](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:570)
- Snapshot equality detects observed changes but is not a documented atomic content or namespace snapshot. Mandatory tests need target replacement, parent/each-ancestor rename or replacement, security/case changes during both check-to-lease and RPC windows, disappearance/appearance for absent targets, hard links, and same-name reopens. The seed-coherence work and typed assigned-descriptor/provenance transport are separate required integration gates; this factory alone cannot expose a bound head. [Required gates](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:526)
- Close-order tests need original share 0/7, later reader shares 1/3/7, multiple independent app FILE_OBJECTs, duplicate/inherited handles, canceled attach at every owned-resource stage, process exit, instance teardown and unload. Verify that one object's cleanup drops only its own lease, local close never waits for service, and no supplemental handle survives attach. No reclamation redesign or unreadable-seed hand-back decision is included. [Lifetime correction](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:584), [pending policy exclusion](/home/victor/Work/safeupload-staging/driver/T5-NATIVE-PUBLIC-OPENS.md:636)
