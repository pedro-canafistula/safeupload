## Service restart investigation

The saved `demo1/policy-v2.txt` event ends at `UnauthorizedAccessException: Attempted to perform an` and contains no full stack
or failing path. It cannot establish which ACL query failed. In source, first creation skips the existing journal/stage ACL
branches; restart enters them while the loaded filter may retain backing handles. Initialization already authenticates the port
by pushing the durable policy before opening the private namespace. `StagedJournalFile.Open` already requests GENERIC_READ,
which includes READ_CONTROL; adding that bit to its mask would not fix a missing grant.

The named directory/stage ACL reads now use explicit metadata handles with READ_CONTROL, FILE_READ_ATTRIBUTES and full sharing,
without data access. They reject final reparses, wrong object types and multiply-linked files, and query OWNER/GROUP/DACL on the
same handle. No privilege enablement, permission bypass, discarded journal or recovery-state reset is introduced. Failures name
the path, native operation and Win32 code. Existing journal-handle ACL failures also name their path; the interceptor logs which
startup directory it was initializing.

Five Windows cases cover metadata ACL reads alongside an exclusive backing handle, object/link refusal and reconstruction of
an existing private journal with its bytes and ACL intact. This addresses the ACL reopening mechanism and makes another failure
diagnosable. **The original demo failure's exact cause and a loaded-driver Stop-Service/Start-Service cycle remain unconfirmed
until Windows execution.** Do not count these source changes or unprotected native controls as protected-pair restart qualification.
