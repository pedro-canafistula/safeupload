## Engineering approach

Treat each save as one versioned transaction: capture the caller and destination, allocate private bytes, seal a stable version, inspect complete content under current policy, obtain the exact publication permit, commit once, record the native result, then retire cleanup obligations. Public delete, overwrite and rename must share that destination ordering. Recovery resumes the missing durable step; it does not infer permission to repeat a filesystem mutation.

Keep these concerns separate: Windows decides the caller's native access; inspection decides the content verdict; the destination head decides which generation may commit; cleanup owns private residue. This avoids fixing an access failure by broadening privilege, or fixing cleanup by discarding publication evidence. Use the existing reviewed T5 contracts instead of adding another successor protocol or a second publishing implementation.

A professional DLP also states its inspection coverage. Publish a support table covering format, payload features, encrypted/corrupt cases, maximum work, and the visible failure outcome. Microsoft itself distinguishes content scanning from restrictions on unsupported extensions ([Endpoint DLP documentation](https://learn.microsoft.com/en-us/purview/endpoint-dlp-learn-about)). That supports being explicit about coverage; it does not justify weakening SafeUpload's approved fail-closed contract.

### T4: one causal experiment before another long run

Prepare a diagnostic of the **remaining 2,712 allocations**, not another uninstrumented four-hour trial. First reuse retained data. If it cannot identify owners, request one bounded diagnostic with the original bound unchanged: context type, attached object identity, driver-acquired reference category and cleanup callback balances at start/idle/purged. Compare a fixed physical-identity set with the growing journal/hand-back/public-file population. Diagnostics must add no owning references or cleanup authority.

Decide from the result: an unmatched driver reference gets a narrow lifetime fix; filesystem-attached retention needs its actual owner/release explanation; unattributed retention keeps the gate failed. Do not periodically delete contexts, clear Unknown, subtract background counts or increase the threshold. Microsoft documents that attached contexts and outstanding references have separate deletion/release lifetimes ([deletion](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/deleting-contexts), [release](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/releasing-contexts)). The current stop requires owner direction before the diagnostic or further product VM rows.

### T5: settle the hard semantic questions once

Use the existing [bound publication](docs/design/publication-and-namespace/T5-BOUND-PUBLICATION.md), [native opens](docs/design/publication-and-namespace/T5-NATIVE-PUBLIC-OPENS.md) and [delete](docs/design/publication-and-namespace/T5-DELETES.md) designs as the single contract. Review the unresolved construction mechanism against native CREATE/replace semantics, original versus stored security, creator grants, restricted/low-token callers, parent DELETE_CHILD, share lifetime, full identity and coherent seeding. The builder's 19045.6466 controls do not establish these on target 19045.2965.

For the two descriptor counterexamples, require a finite candidate list and a native reference result. A candidate must preserve the agreed full descriptor without an unapproved repair. If no supported construction satisfies it, present a specific metadata-contract decision with user-visible effects; do not keep trying bit combinations. Keeping the old security comparison intact is the default.

**Recommended pending seeded-byte choice:** preserve native write-only editing, but retain an unreadable blocked version privately with a named reason and no full-file hand-back/justification until read/export authority exists. This lets clean write-only appends work without revealing old bytes. The alternative is to reject edits that preserve unreadable prior bytes; that is simpler but breaks those applications. Neither choice is approved by this review.

The [bound allocator](../agente/SafeUpload.Agent.Service/Interception/StagedBoundTransferAllocator.cs) still opens a second public read handle to seed an existing file. Replace that mechanism with the reviewed original-rights/share-checked kernel object and a proved coherent-copy interval; a path reopen under SYSTEM is not equivalent authority.

Connect and test the whole path behind the existing capability gate. Deterministic fault points should cover accepted native result before journal persistence, persistence before reply, service restart, last-handle close, policy change, stale generation, parent/name replacement and cleanup failure. Include service-absent/crashed mandatory teardown, local I/O/callback rundown, retained unsealed stages and voluntary-unload veto recovery. Preserve the service-stop prohibition and exact durable uncertainty; an expired wait does not authorize freeing live state. A successful native result is never replayed just because its acknowledgement was lost. Do not use a clean unprotected control as the protected acceptance row.

### T9: cover content and bound the entire operation

Create a fixture inventory by payload location, not just extension: visible text, drawing text, comments, annotations/form values, metadata, embedded objects, custom XML, alternate content and malformed/encrypted cases. Begin with the drawing-text and PDF-annotation omissions above. Worksheet names and core properties also need an explicit coverage decision. Every admitted payload must be fully consumed or positively classified as unsupported; a growing denylist alone is not evidence of completeness. Preserve strict encoding and boundary/category controls when changing readers.

T8 and T9 must agree on success: PowerPoint/7-Zip/Paint are required application workflows, while the current extractor registry covers plaintext, Word, Excel and PDF. An explicit safe refusal can demonstrate privacy, but cannot silently count as successful clean saving where the application acceptance row requires publication. Establish the missing format/OCR/archive handling or obtain a scope decision; do not quietly narrow T8.

Reserve storage **before** seed/capture, under per-user and total budgets with host-volume headroom. Account for stage, seed if separate, inspection snapshot, publication temporary, journal/security records and pending hand-back at their actual overlapping lifetimes. Release a charge only when the relevant exact object/handle is gone; a request timeout may leave a worker alive. Reconstruct unresolved charges on restart. Keep the current owned-handle/delete-on-close improvement and test abrupt Windows interruption separately; do not reintroduce pathname sweeps.

For PDF/ZIP/XML libraries without a demonstrable in-process memory bound, prefer a small isolated inspection worker with a Windows Job Object, memory/process limits and a monotonic deadline. The service retains source/permit authority and passes only a read lease to the exact snapshot through a narrow IPC contract. Restrict the worker token/capabilities separately: a Job Object is a resource container, not by itself a security sandbox ([Windows Job Objects](https://learn.microsoft.com/en-US/windows/win32/procthread/job-objects)). Kill and drain the worker on budget failure, then report incomplete inspection; never accept a partial result. This is a proposed security design needing review, not an implemented mechanism or an excuse to increase policy limits.

### T11: improve scaling without silently changing integrity

Measure full admission/commit/recovery latency at 1k and 10k durable heads with the protected workload. Attribute global-lock wait, disk validation and journal writes separately. Keep failure timings and do not attribute the historical NO_WAITER delay to head scans without a trace.

The current contract intentionally detects an unrelated corrupted head on the next lookup. A simple per-destination index/cache would lose that property. First remove redundant work only where the same stable transaction and complete fresh validation can be proved. If acceptable latency requires a different storage model, prepare one small design decision: authoritative transactional index/journal, alias-conflict rules, recovery/compaction, and precisely when unrelated corruption is detected. Any changed integrity timing or assertion requires explicit agreement; a generic database rewrite is not a prerequisite to resume M2.
