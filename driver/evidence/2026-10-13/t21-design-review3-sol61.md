**REVISE** — independent **Sol 6.1, xhigh** review of `e6f1990b`. Two design gaps remain.

1. **High — accepted scheduled backend has no close owner when StageFs attachment fails.** [T21:287](driver/T21-USB-REMOVABLE-DESIGN.md:287) limits failed-create lease release to ordinary opens. The scheduled path assigns an accepted `FILE_DELETE_ON_CLOSE` backend to fallback CCB cleanup, then closes it at app CLEANUP or proven removal ([T21:382](driver/T21-USB-REMOVABLE-DESIGN.md:382), [T21:389](driver/T21-USB-REMOVABLE-DESIGN.md:389)). Cancellation before an app handle exists supplies neither trigger; ECP cleanup only drops a reference. Sharing, scheduled deletion and recovery holds can remain indefinitely. Microsoft confirms that reparse is not a successful open and cancellation does not undo native effects. [FltCancelFileOpen contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltcancelfileopen).

   **Required change:** give the pre-attachment record explicit backend ownership and transfer it atomically to the attached CCB. Failed/unconsumed reparse and canceled-before-handle completion must claim the same close-once lease through a reserved PASSIVE worker after rundown. Preserve native acceptance separately from the outer CREATE result. Add C11b/c cases before ECP consumption and after consumption but before handle creation; require automatic reconciliation without app CLEANUP.

2. **High — ordinary accepted delete lacks original-present remount recovery.** [T21:442](driver/T21-USB-REMOVABLE-DESIGN.md:442) permits original-present downgrade only for scheduled deletion; ordinary completion requires absence. An accepted ordinary TRUE interrupted before cleanup can return with the original file present and the old capability dead. Existing recovery explicitly keeps that case blocked, even after lifetime ends ([StagedPublicRelayJournal.cs:183](agente/SafeUpload.Agent.Service/Interception/StagedPublicRelayJournal.cs:183)). Generic T5 inheritance therefore cannot deliver automatic unchanged-return recovery.

   **Required change:** define ordinary TRUE/FALSE remount outcomes, preserving native facts and generation floors while specifying when proven dead-incarnation effects stop blocking fresh saves. Do not fabricate completion, synthesize FALSE/redelete, or relabel ordinary deletion as scheduled. Retain genuinely unknown outcomes. Add C6/C11c rows for accepted TRUE → removal before cleanup → unchanged return → automatic recovery and fresh publication, plus accepted FALSE with lost bookkeeping. Explain the surviving-delete outcome in D2.
