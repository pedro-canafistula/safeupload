# T5 empty-file and public-delete component classification

Date: 2026-10-11  
Review base: `c8fa2f90be66346cb467a8d025fa4dd12cc92f42` (`feat/driver-m2`).  
Purpose: source/design classification for the revised [T5 delete design](../../T5-DELETES.md). Evidence below describes product source at the review base, not a claim that later worktree bytes are unchanged. Classification itself changed no VM behavior. Later implementation and qualification are recorded in [POST-MVP-PLAN.md](../../POST-MVP-PLAN.md); the T5 test-script references are explicitly marked as worktree observations rather than baseline-source claims.

The owner decision is that stable zero-byte saves are ordinary sealed content, trivially clean, and publishable. Public-file deletion is M2. The classification removes the EmptyHeld product path and its successor workaround while keeping independent identity, lifecycle, drain, and cleanup protections. Public delete has no implementation in this baseline; the transaction described in T5 is a design requirement, not a claim that the current code satisfies it.

The mandatory local-only proposal does not waive EX rundown, callback-body, channel-use, worker-batch, backing-file, or instance-reference safety. It forbids waits for service work and RPC/cleanup acknowledgements; local active callbacks and worker ownership still have to be quiesced before unregister/free. Whether mandatory teardown also must wait for an unrelated application file object is a separate kernel-lifetime implementation question; do not hide it in the service-wait decision.

Public-delete generation rule: deletion commits unless a newer version has already completed its physical publication and durable Published/Released receipt before the delete gets its destination commit turn. Allocated, Unsealed, SealPending, Sealed, Inspecting, Approved, Publishing, Blocked and Retained never suppress deletion. If deletion wins, any later version needs ordinary clean inspection and a later exact atomic publication; no older version can rename after the delete watermark. Test both orders around the physical commit, not merely around a manifest semaphore.

Save As cases stay distinct. A failed CREATE_NEW probe for an existing name does not issue DeleteFileW and must leave the prior file untouched, including on a later CPF block. An explicit public DeleteFileW followed by a CPF-blocked newer save leaves the public name absent. A new-name private probe is discarded before seal; a sealed-but-not-public probe uses an owner-authorized private cancellation generation; an already-published probe uses public delete. Capture actual Notepad UI/native behavior for existing-name Save As before claiming that path cannot delete the original.
