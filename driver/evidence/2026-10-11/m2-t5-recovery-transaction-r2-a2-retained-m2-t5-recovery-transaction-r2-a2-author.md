# T5 recovery transaction R2 A2: source custody and retained-state protocol

Captured 2026-10-11 as an additive R2 candidate after the root-frozen A1 lock-order checkpoint. R1 remains immutable. The candidate is **NO_GO for source integration and all host/runtime actions**. It advances source custody, recovery evidence, and the bounded restore path, but does not yet provide an executable restart-to-full-restore supervisor or prove that already-authorized libvirt API requests have drained.

The A1 checkpoint establishes the permanent canonical lock inode before host-installer attempts and journals. In the invocation path, R2 now takes that same selected-domain lifecycle flock, publishes the PREPARING lease to close the existing libvirt admission gate, then writes its source-acquisition intent, acquires leases, writes the source-set receipt, and only then enters copy preparation. A failed acquisition leaves the immutable PREPARING lease and intent for guarded recovery. The lock inode is never replaced.

`T5SourceLeaseGuard.py` opens only the two pinned disk-chain files, selected NVRAM, and the bounded sorted TPM member set including `.lock`. Each inode must be a no-follow regular file with one link and an unchanged path/device/inode identity. It acquires `F_RDLCK`, fsyncs that same read-only descriptor, checks `F_GETLEASE`, and verifies one matching `ACTIVE READ` row in `/proc/locks`. A `BREAKING` lease row or signal is a hard failure. The guard reads `leases-enable` and `lease-break-time`; it never changes either control. This selected mechanism requires `leases-enable=1` and a zero automatic break timeout, so the observed nonzero host value remains an owner-approved dependency. No live source file, sysctl, or daemon was touched.

The chosen process-loss mechanism is a per-run systemd descriptor store. The candidate adapter pins the service instance name to `safeupload-t5-copy-r2@<RunTag>.service`, requires the service to be its own main process, `NotifyAccess=main`, `FileDescriptorStorePreserve=yes`, an empty initial store, and enough descriptors for the canonical lock plus every source inode (maximum 20). It stores individually named descriptors, confirms the manager's store count, and on restart requires exact `LISTEN_PID`, `LISTEN_FDS`, `LISTEN_FDNAMES`, unit, and store count before adopting those existing descriptors. Reattachment verifies the original source receipt bytes, lease-owner identity, canonical lock inode, source path/inode set, active `/proc/locks` entries, current kernel policy, and exact TPM membership. Disposable controls exercise the named-FD protocol against a local manager surrogate; they do not qualify the deployed systemd manager or its restart behavior.

R2 pins the cold `win10-debug2` exception to UUID `9d6e3f02-b40a-49f0-a77f-439714f8f308`, its exact inactive XML SHA-256 `38ce04f1e099f667de852fe1f4e58cb6e92a2e6cccb772a483d277835483a2dd`, shutoff/crashed state `(5,2)`, and sole reference to the selected shared backing file. The alias must appear exactly once. Other domains remain forbidden from referencing protected paths, and the QEMU hook continues to deny starts of that cold alias. Host installation now refuses both its initial and fresh pre-mutation preflights whenever any domain is active, preserving an unrelated running builder by deferring the installation.

The existing copy coordinator already holds separate run and recovery copies for NVRAM/TPM and never writes guest bytes back to originals. The candidate adds a two-pass pre-run base/backing disk baseline, verifies and reuses the copy ledger's durable original inactive XML instead of attempting a duplicate create, and stores readback-verified private-state and run-bound XML checkpoints before their respective `defineXML` and overlay mutations. The normal completion path keeps the source leases through shutdown, original XML restoration, two-pass disk rehash, full-stream comparison of original NVRAM/TPM against recovery copies, private-copy cleanup, and retention-marker removal last. Its completion records still set `WholeVMPass=false` and do not imply product acceptance.

Failure handling preserves the copy coordinator's retention marker and event ledger, lifecycle lease, source lease receipt, XML checkpoints, baseline, and a root supervisor failure receipt when the process catches an error. The restart adapter now knows how to adopt descriptor custody, but no recovery entrypoint yet reconstructs the copy coordinator's in-memory prepared context, handles every crash point, restores original XML, proves original whole-state equality, or finalizes retained copies. A systemd manager restart/stop or boot loss also has no qualified recovery path. In addition, PREPARING closes future policy-authorized requests but does not prove that a request already authorized or in flight has drained. These gaps keep the candidate NO_GO.

The concrete path for final owner review is:

1. Freeze and independently review the source, root invocation, lifecycle, and recovery files. Do not install the candidate while any libvirt domain is active; the current active-builder check rejects that window.
2. Before any source read, acquire the canonical lock and publish PREPARING. Then require the exact kernel lease policy and an owner-approved per-run service with descriptor-store capacity for 20 FDs, preservation across service restart, and a fixed recovery executable. The service request/entrypoint wiring is not implemented in this candidate and must be included in that review.
3. Persist the source intent and exact lease set before copy reads. Persist original XML and disk baselines before the first configuration mutation; persist private/run XML before each subsequent mutation. Create the copy retention marker before destination objects and append durable intent/result events around each object creation.
4. On ordinary completion, restore original XML only after the guest is shut off; independently verify XML/state, disk streams and metadata, and original NVRAM/TPM full streams against their recovery copies; delete private volumes/pools only after those checks; remove the retention marker last; write the completion receipt; then remove FD-store entries and release leases.
5. On any process failure, restart only inside the same exact service instance. Reattach and verify the named FDs; do not reacquire leases or clear markers. Shut down a selected guest only if its live/inactive XML is one of the exact durable checkpoints. Restore original XML only when inactive and recognized. Any missing descriptor, changed inode, pending lease break, unknown XML, mismatched disk/state stream, or manager-store mismatch retains evidence and blocks cleanup. Recovery then requires an explicitly reviewed guarded path.
6. Before owner approval, qualify the exact kernel build/configuration, global zero-timeout behavior, deployed filesystem lease/fsync path, systemd service restart and manager restart, descriptor loss, pending breaks, and every crash point on disposable filesystems and scratch services. Roll back only exact journaled candidate artifacts before restart; after an ambiguous/restart barrier retain state for recovery. This candidate has not applied or requested any of those host changes.
