## Product findings

- `StagedPrivateStorage.CreateDirectory` supplies the protected owner/SYSTEM/Administrators descriptor for a missing leaf, refuses a missing parent/reparse ancestor, and validates an existing object without setting its ACL. The Windows path uses the journal's existing rule builder; its only journal change is private-to-internal visibility. The [.NET 10 implementation](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.IO.FileSystem.AccessControl/src/System/IO/FileSystemAclExtensions.cs) passes the supplied binary descriptor into directory creation and leaves an already existing directory unchanged; file creation passes it in `SECURITY_ATTRIBUTES`. Thus an existence/create collision does not normalize an unsafe descriptor. Production parent validation and SYSTEM identity gates in startup/allocator are unchanged. This is an internal private-storage helper, not an assertion of safety for concurrent hostile replacement of an ordinary writable parent.
- The budget creates a missing root before preflight; all existing-root/record preflight checks remain before allocator recovery. Reservation directory/record descriptors retain protection and trusted-writer/owner checks. The grant now receives the explicit protected file descriptor at `CreateNew`; existing grants are not repaired. Durable grant bytes, identity, capacity, ordering, inventory, legacy guard, refund and exact cleanup authority are unchanged.
- `PolicyDocument` distinguishes absence from explicit null. Omission selects 20 MiB/5 s for legacy consumers and 4096 MiB/900 s for current staged consumers; either explicit value applies to both modes. Provisioning omits the overrides. Null throws during JSON binding; zero/negative retain existing domain rejection. `HttpPolicyStore.LoadCurrentAsync` has no new fallback. Local staged reads cache a separate legacy mapping; the staged policy cannot become an enlarged legacy ACL fallback. Its un-revalidated legacy mapping is equivalent for validation purposes: all fields except omitted size/time defaults are identical, and both alternative defaults are positive. Existing effective-value fingerprints still bind the mode-specific limits.
- The immutable `_tracksBudget` selection restores the exact `FileStream` duplicate only for unbudgeted snapshots. Budgeted readers still increment before native duplication and unwind on failure; every successful reader releases after its native close. Owner disposal closes its stream before releasing its reference. An OpenRead/Dispose race either retains the accounting reference through the duplicate or attempts to duplicate the disposed owner and fails; it cannot switch a budgeted snapshot to an untracked return path. The exact-object, read-only native duplicate and delete-on-last-handle semantics are unchanged.
- Changed test setup creates a fresh product-private stage child instead of normalizing the generic workspace. Corruption, unknown inventory, exact cleanup, RN-012/RN-013 and native snapshot rights/lifetime expectations remain asserted. The new policy controls cover both transports/modes, independent explicit fields, provisioning, fingerprint differences, explicit null and staged-to-legacy ACL fallback. The new native controls cover broad inherited mutators, preserved parent/unsafe existing descriptor, root/ledger/grant descriptors, exclusive sharing and budgeted snapshot ownership after owner close.
