## Findings

1. **P1 — Complete the sticky resource-failure barrier for every relevant native mutation and real disk-quota status.** In `StageStream.c`, the `FileAllocationInformation` branch marks an over-cap request but does not mark native `FltSetInformationFile` disk-full/quota failure at an otherwise admissible allocation. `StagePagingComplete` marks writes but not the routed AdvanceOnly set-information operation. A successfully written prefix can consequently seal without V31. The predicates also omit `STATUS_DISK_QUOTA_EXCEEDED` (`0xC0000802`), which is distinct from `STATUS_QUOTA_EXCEEDED`; `StagedSpaceFailure` omits Win32 `ERROR_DISK_QUOTA_EXCEEDED` (`1295`). Use one complete resource-failure predicate consistently before seal and test native failure after a clean/empty prefix. The distinct status values are documented by [Microsoft NTSTATUS](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-erref/596a1078-e883-4972-9bbc-49e60bebca55) and [WinError](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1000-1299-).

2. **P1 — Deterministic failed allocations permanently consume the SID's full capacity.** `StagedTransferAllocator.AllocateForReplyAsync` reserves before seeding, but its catch path confirms no committed manifest and safely removes the stage without retiring the content debit. `StagedSpaceBudget.ReconcileAsync` simply retains a missing-manifest reservation forever. One over-cap seed, sharing/permission failure or cancellation can therefore block every subsequent save for that SID after restart, even when no stage exists. Record the allocation path and exact native-created identity before seed growth, distinguish whether a grant/reply could have escaped, and durably refund content only after the corresponding exclusive exact cleanup or proven never-created absence. Keep metadata charged and preserve genuinely uncertain crash states. The primary proposed this correction; it still needs source and controls.

3. **P1 — Authenticate existing accounting storage before using it as charging/deletion authority.** `StagedSpaceBudget` assumes `.space-reservations` inherits the root ACL, checks only its reparse attribute, and loads records with `StagedJournalFile.Open` without the required caller-side owner/protected-DACL validation. That helper explicitly leaves ownership to its caller. The allocator protects direct root files, not this existing child directory/its records. A child with a pre-existing explicit permissive ACL is not repaired by changing its parent's ACL; traversal bypass also makes the parent's DACL insufficient to protect a known child path. Apply the repository's protected-parent/trusted-owner/exact-DACL rules to the held directory and held no-follow, single-link record handles before parsing. Validate the association of any present stage/snapshot with its reserved identity; a matching pathname alone is not object reconciliation. The primary proposed an ACL correction; it still needs source and native controls.

4. **P1 — Define and enforce mode downgrade with outstanding large grants.** The kernel accepts an exact `.space` grant independently of the service's `StageSpace.Enabled` setting. When the setting is disabled, the service stops reconstructing/accounting reservations and snapshots, while existing live streams retain their immutable large capacity and recovered grants can still authorize it. Thus disabling the setting does not necessarily restore the documented 16 MiB legacy profile. Keep accounting active until all large versions/grants retire, or refuse disabled startup/readiness while such state remains. Never silently reset the ledger or remove a grant from a live version. Exercise service restart/downgrade with an open large writer and with a sealed/recovering transfer.

5. **P2 — Free-space arithmetic can wrap and defeat the configured floor.** `Reserve` computes `_available() - FreeSpaceFloorBytes - total` outside `checked`. A large accepted nonnegative configured floor plus existing reservations can underflow into a positive value, and `Math.Max(0, ...)` then treats that as free capacity. Subtract using checked/saturating comparisons and reject invalid availability readings. Include near-`long.MaxValue` configuration/accounting cases; ordinary positive byte settings must not imply unchecked signed arithmetic.

## Mechanisms that look sound at source level

- Capacity remains separate from inspection/publication authority. The full stage identity and transfer GUID, fixed 64-byte grant, strict reserved bytes/alignment, immutable in-stream capacity and at-least-legacy minimum avoid the original small-grant fallback problem. New grant I/O is restricted to the PASSIVE-level backing-open path; the new completion marking uses interlocked access on the existing rundown-pinned stream. No obvious new kernel import or proportional-content allocation was found. WDK/PREfast/import availability and Verifier are still required evidence.
- `StageSpaceFailed` is durable, participates in entry equality, blocks approval/publishing/release transitions, disables new justification and is rechecked at the unbound native commit. V31 is additive, strict, failure-only and rejected by older agents. This is a useful prefix-publication barrier once finding 1 is closed.
- Snapshot admission precedes content copying. A single exact snapshot identity is retained, duplicated read leases hold the reference-counted debit, and exclusive exact cleanup prevents refund while a remote parser still holds the file. Timeout alone does not refund or approve. Failed creation/identity-persistence crash windows intentionally remain charged.
- The parser broker supplies no source handle before job assignment, applies process/memory limits, validates bounded framing/nonce/exit/trailing bytes and keeps the parent read lease until kill/drain. The native Job Object structures have no obvious layout error on the intended Windows architecture. It remains a resource container with the service token, not a security sandbox. Actual job-limit, ignored-cancellation, crash, abrupt-parent-death and user/SYSTEM controls are required before claiming containment.
- ZIP plaintext members rewind/decode in bounded buffers and validate complete length, CRC, final DEFLATE completion and compressed extent at EOF. The scanner consumes every successful pass to EOF; extraction/CRC failure discards partial findings. Seek-requiring members refuse above the separate 8 MiB bound. No new clean partial-archive approval path was found in these changed paths.

The retained 1 MiB metadata debit and conservative whole-SID content grant are explicit prototype limitations. Document the unbound metadata bound/overlap arithmetic, update `UX-LARGE.md` (it still says 64 KiB and describes the parser solution as future work), and keep default/configuration, component passes, native mechanism controls and protected-pair qualification as separate results. Existing test source does not yet establish the real parser-process or snapshot/accounting interruption behavior. No activation, cutover or T9 completion follows from this review.
