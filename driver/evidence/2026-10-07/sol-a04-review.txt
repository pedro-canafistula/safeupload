### Findings

1. **[Blocker] A04 can stop before the child mutation.** The A04 path calls `Get-ActivationHandBackInventory` before issuing `write-old`; that function throws unless it finds exactly one profile for the actor SID ([suite.ps1:2846](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:2846), [suite.ps1:3135](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:3135)). Preparation creates a profile only when `$cachedCase` is true, which excludes A04 ([suite.ps1:3561](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:3561)). The file’s own comment says batch-logon tasks do not create a loaded profile. That leaves the inventory call able to abort before the child write stimulus.

2. **[Blocker] The final-cleanup check compares different clocks.** The Inspector trace timestamp comes from `KeQuerySystemTime` ([StageStream.c:233](/home/victor/Work/safeupload-wt-sol/driver/SafeUpload.Minifilter/StageStream.c:233)); the release receipt uses `Stopwatch.GetTimestamp()`. The comparison at [suite.ps1:3212](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:3212) therefore cannot establish that cleanup occurred within the release interval. In practice, the trace time is far larger than the QPC end value, so `ChildLastCloseExactlyOneCleanup` cannot pass even for a valid close. That assertion is required for A04. The in-diff plan audit also identifies this mismatch ([MVP-PLAN.md:1234](/home/victor/Work/safeupload-wt-sol/driver/MVP-PLAN.md:1234)).

3. **[High] The standard-user actor can alter the command and receipt channel.** Preparation grants the actor Modify access to the actor directory ([suite.ps1:3573](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:3573)); the duplicate actor directory is created beneath it ([suite.ps1:3675](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:3675)). The coordinator reads identity and native-operation replies from these directories, while the Python gate checks their claimed values and ordering, not their origin ([suite.ps1:818](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:818), [qualification.py:459](/home/victor/Work/safeupload-wt-sol/driver/scripts/Invoke-StagedInvariantQualification.py:459)). Under the stated adversary model, the actor can pre-create or modify reply files and alter commands. In particular, `CrossProcessSameFileObject` relies on actor-reported duplicate and shared-position receipts.

4. **[High] A failed raw sample can produce a PASS for “unchanged.”** The A04 approval branch sets `PostPromotionRawDestinationUnchanged` from the difference result alone ([suite.ps1:2916](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:2916)). `Get-ActivationRawDifference` reads images from `Sample.Captures` but does not require `Sample.Status` to be `OK` ([suite.ps1:1017](/home/victor/Work/safeupload-wt-sol/driver/scripts/Test-StagedInvariantSuite.ps1:1017)). The observer preserves captures and partial images in an error sample ([observer.psm1:1007](/home/victor/Work/safeupload-wt-sol/driver/scripts/StagedInvariantObserver.psm1:1007)). If an errored or incoherent capture contains matching extents, this path can report zero differences and PASS. The A04 raw comparison should require a successful complete sample and validate the retained artifacts.
