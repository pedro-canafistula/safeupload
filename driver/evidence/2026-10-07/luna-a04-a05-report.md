## A04 — p1a1

The first failure is the parent-close admission-trace window. In the retained run, the recorder was enabled at case setup, cleared immediately before the parent closed, then left live while the harness read `activation-parent-close-trace.out`. The snapshot has sequences `1..1443`, `cursor=1444`, `snapshotSequence=1443`, and `lostEntries=3`; the timestamp span is `713.9996 ms`. The 16,384-entry ring (`Protocol.h:343`) had not wrapped, and the cursor is consistent. The parser rejects the nonzero loss counter at `Test-StagedInvariantSuite.ps1:1205`. `StageStream.c:209-215` shows callback writers increment `LostEntries` when they contend for the recorder lock. The snapshot output contains 10 global `file_cleanup` and 8 `file_close` rows, but none match the trusted duplicated object `0xFFFF9989170B10C0` from `activation-trusted-physical-object.json`.

`totalEvents=8248` is not the retained snapshot length: `PrintAdmissionTrace` fixes the sequence snapshot on its first batch but refreshes the counters while fetching later batches (`SafeUpload.Inspector/main.c:1703-1764`). Since the harness had not disabled tracing, the event stream and loss counter could continue changing during serialization; the three losses may therefore include events after the fixed sequence snapshot. This is consistent with the global cleanup/close churn described in `luna-reclaim-churn-analysis.md:7-11` (about 2.5–3k reclaim passes/s); it is not evidence that the ring filled.

The second error is not the duplicate actor failing. `Invoke-CapturedProcess` turns any nonzero Inspector process exit into `Child process failed: N` at `Test-StagedInvariantSuite.ps1:207`. The retained `activation-trace-final-disable-264eb905a01f4a069442d5785760a08b.out` says disable was refused with `hr = 0x800700AA`. `SafeUpload.Inspector/main.c:1683-1687` returns exit 3 when the control message fails. The driver returns `STATUS_DEVICE_BUSY` if observer W tickets remain or `LostEntries` changes during rundown (`StageStream.c:305-321`); the retained output does not distinguish those causes. The actor receipts instead show parent task exit 0 and duplicate `exit-worker` NativeCode 0 / completion ExitCode 0. The child-last-close trace window was never reached after the parent trace parser stopped the case.

The harness now keeps the loss-free condition strict. It uses the base trace mode during setup, turns on lifetime-event recording only for the parent/child close windows, clears immediately before each close, and disables before reading or doing any status query (`Test-StagedInvariantSuite.ps1:3893-3898, 4007-4027, 4162-4176`). A bounded helper retries only the observed busy HRESULT, up to 8 attempts at 10 ms intervals, and requires the exact control acknowledgment (`:924-945`). The frozen API cannot filter event production by file object, so the harness narrows the time window and filters lifetime assertions to the SYSTEM-verified physical object while still rejecting any global trace loss (`:1197-1232, 3728-3741`). If a frozen snapshot still reports loss, A04 remains unqualified; there is no loss allowance.
