SafeUpload Phase 4 invariant suite and release gate -- design v2
2026-10-05. Design only. No build, test, VM experiment, or qualification run.
This is a self-contained revision of the accepted 2026-10-04 design v1. It
retains its observer, workload, storage, outcome, lifecycle, mode, latency,
and release corpus, while applying the later binding MVP-PLAN.md decisions
at lines 380-403. Those decisions govern whenever older wording conflicts.

1. Binding scope and rule

Inputs: MVP-PLAN.md (Goal, Phases 3-5 and all end-of-plan decisions), accepted
phase3-design-v1.txt (especially section 7), boot-start-run13-readout.txt
(including run 15 addendum), STAGED-WRITES.md, Test-StagedBootStart.ps1,
Invoke-DebuggeeExperiment.sh, Invoke-Staged*Qualification.py,
Test-StagedAdmissionDiagnostic.ps1 variants, and StagedTestAgent.ps1.

Qualify one folder on a local fixed NTFS volume, Windows 10 22H2 19045.2965
only. Driver is installed boot-start, with policy seeded and verified before
the activating reboot; installer must not demand-start it. Standard users
are the adversarial writers. Administrators, SYSTEM, other kernel drivers
and higher-altitude filters are trusted. Observer runs elevated, in a
different process from every writer, with no owned-stream/private-view
identity. Actual service runs as LocalSystem with its SafeUpload service SID.
Use the real owned upper stream/cache, private noncached backing, immutable
seal, inspection, journal and authenticated one-use publication path.

Every MVP case sets and reads back TEST_DISABLE_TAINT in live policy Flags.
Normal builds retain taint and reject that bit. Holds, failure injection and
diagnostic controls exist only in SAFEUPLOAD_STAGING_PROTOTYPE; no such build
is user-receivable. Protocol remains v18. No recovery scan, trust retry or
Unknown reset is allowed. Actual dismount retires only that volume's history.
Loss about an identified file marks that entry Unknown; a lost rename/name
or unbound section-capacity event widens to its instance. Ambiguous teardown,
lost completion whose scope cannot be bounded, or missing machine-wide
identity sets machine-wide Unknown until reboot. An exact section-capacity
Unknown stays sticky until reboot even after the slot drains. These states
withhold protection/promotion claims at the narrowest provable scope; they
do not deny ordinary paging or unrelated known-outside-volume I/O. Late
attachment and failed/timed-out canaries leave Untrusted until reboot and
claim no protection.

The admission epoch swap commits the added scope and gates new writable
opens/section creation into a candidate file. A pre-existing physical writer
may still write through its handle, retained section, mapped view or cached
pages; its paging I/O is never refused by the registry. Such a file is
Activating and explicitly does not yet carry a Protected byte claim. It
promotes only after the gate is in place, all relevant writers/sections/
transactions, shared cache, and in-flight nonpaging mutating I/O are gone,
and the same file ID/SOP and final Free(F) check are serialized with the
promotion. Free(F) means H=0, S=NO (no data section or shared cache map),
C=0, T=0 and W=0, plus no unresolved live overflow marker on the instance
and no applicable Unknown. A file held indefinitely stays Activating and is
reported with its holder when known. A failed identity/cache proof, lost
completion or live ambiguous marker withholds promotion; it never becomes a
Protected claim by timeout or scan. Stable data written by the old writer
before that proven protection transition forms the pre-protection baseline.
The observer must capture its complete raw image, directory, identity, and
allocation at that boundary. A later unexplained delta of a Protected file
is FAIL or INCONCLUSIVE according to observation, never rebaselined.

The old v1 cutoff flush, paging denial, DirtyAfterCutoff latch, loss warning,
and post-swap byte prohibition are retired. A05 now tests the Free(F)/W
linearization, especially completion of writes that outlive cleanup. A02/A03
post-swap stores can legitimately reach disk while Activating; no fixture
labels those bytes an approved publication. This changes the coverage
window, not the rule that Protected destination bytes require a real permit.

Review 4's intermediate per-marker OUTSIDE classification and dynamic
section-spill recovery are also retired. A live overflow SOP marker blocks
promotion on its instance until quiescent, even if its file appears outside
the current scope. The fixed section ledger has 64 slots; overflow admits
the acquire and sets sticky Unknown at the exact entry if identity binds,
otherwise at the instance. Capacity Unknown does not recover before reboot.
Fast-I/O PREPARE_MDL_WRITE is disallowed so the cached write retries through
a counted IRP write. Ledger loss never becomes an I/O refusal by itself.

2. One suite, three components

Proposed implementation files (not created by this design):
  StagedInvariantObserver.psm1: sole raw/reader observer and predicate library;
    one embedded native interop/NTFS decoder, compatible with PowerShell 5.1.
  StagedInvariantCases.psd1: immutable data table, no second observer per case.
  Test-StagedInvariantSuite.ps1 plus Invoke-StagedInvariantQualification.py:
    guest lifecycle/case runner and thin host provenance/verdict adapter.

Each expanded table row has CaseId, revision, fixture/storage variant, outcome,
actor SID/session, initial policy/scopes, setup/actions/barriers, expected
state timeline, exact operation status classes, journal/notification timeline,
allowed directory transitions, latency operation classes, and cleanup list.
Expand variants into distinct IDs; never omit a row because enforcement is
absent. Discovery-only runs may record NOT_READY but cannot qualify.

Reuse the checkpoint wrapper, baseline helper, helper service lifecycle and
exact-source qualification pattern. One case ID + mode per checkpointed run;
its repetitions are internal to that case. All modes use Prepare -> reboot
with changed boot identity -> AfterBoot -> restore -> restoration reboot
with changed identity -> Finalize -> separate Get-StagedBaseline call.
Use boot-start-prefixed experiment names to select the existing wrapper's
reboot flow. Adapt its case-specific success sentinels once for this suite;
do not forge BootStartX4AndE1 or launch a parallel checkpoint mechanism.

Before checkpoint: independent BaselineClean=True and guest Write-VolumeCache
success. Preserve disk-only external checkpoint, active overlay/backing chain,
source manifests, signed/unsigned SYS hashes, signer, Inspector/fixture/app/
service package hashes and exact harness/table/module/helper/wrapper bytes.
Require all four normal/feature Debug/Release WDK builds, PREfast,
DriverRecommendedRules, ApiValidator, zero warnings/errors, and current agent
tests for changed agent source. Use hash-qualified guest names and reject
collisions. Preserve an old fixed-name service ZIP by its hash before staging
another; verify the extracted executable/tree, not only its ZIP name.

Prepare fixtures outside any active scope, then seed product BootPolicy.
Record owner/ACLs and exact 16,656-byte record readback, PendingScopes absent,
Start=3 while staging, then Start=0, ErrorControl=1, FSFilter Anti-Virus,
FltMgr dependency, Type=2. Resolve volume identity after reboot; an old
HarddiskVolumeN prefix is not assumed stable. Ordinary/runtime runs also
boot the feature driver; demand-loading to save time would invalidate trust.

Startup probes durably write readiness and their result outside the scope
(WriteThrough + Flush(true)); require filter ready, VALID BootPolicy,
newly-mounted setup flag, passed canary and trusted volume before the measured
attempt. Capture actual boot identity and monotonic ordering, not SSH return
alone. Service events and diagnostic status are obtained through the service
or a read-only prototype diagnostic channel: do not stop the service merely
to reuse Invoke-InspectorAsSystem, which currently requires agent absence.

3. Observer contract

All functions return typed records, not console prose. Errors preserve native
code, complete exception chain and phase; no error becomes an empty byte array.
Use SHA-256 uppercase hex, integer byte offsets/lengths, UTC for correlation,
and QPC ticks/frequency plus boot ID for ordering within a guest boot.

Public API (names/signatures define the implementation contract):
  Open-InvariantObserver(VolumeGuid, ScopePath, EvidenceDirectory, CaseId)
    -> Context: read-only raw-volume handle, serial/GUID/device/mount identity,
       sector/physical alignment/cluster/MFT-record sizes, NTFS decoder version.
    Validate fixed NTFS, target build, no reparse/hard-link/ADS/case-sensitive
    fixture ambiguity, standard-user writers, separate observer identity.
  Capture-InvariantBaseline(Context, DestinationNames[], ExpectedImages)
    -> Baseline: every existing destination identity and allocated run,
       raw containers, complete logical image, parent-directory metadata and
       names/IDs, absence proofs for new names, hashes and geometry.
    ExpectedImages are independently generated fixture bytes, not driver data.
    Flush legitimate setup before capture; require raw bytes match them.
  Register-InvariantPublication(Context, ApprovalRecord, SealedImage)
    -> ApprovedImage: independently hash held immutable inspection snapshot;
       require its length/digest = journal Approved + actual service permit
       grant, transfer ID, destination generation, policy/epoch generation,
       exact temp/final paths, expiry, service SID/PID and attempt ID.
    Record grant before any public temporary write. A grant without matching
    approval/snapshot is a failure, not an allowed image. Never approve a
    fixture token from StagedPublicationProbe as inspected service output.
  Capture-InvariantSample(Context, Baseline, Phase, OperationSequence)
    -> Sample: full current and retained-original extents/records, raw logical
       images, raw directory view, fresh readers, stability/coverage status,
       raw artifacts and hashes, state/journal/event sequence references.
  Test-NoUnapprovedByte(Baseline, ApprovedImages[], Samples[], MutationLedger,
                       ExpectedTimeline) -> assertion records + verdict.
  Close-InvariantObserver(Context) -> checked disposal result.
    Export one result only after cleanup and independent restoration are known;
    preserve partial artifacts on exceptions/crash.

3.1 Extents, aligned I/O, and identity

Use native CreateFileW/ReadFile/DeviceIoControl/SafeHandle, not File.Open with
extra arguments. Read raw volume by GUID, GENERIC_READ, share READ|WRITE|DELETE,
OPEN_EXISTING, FILE_FLAG_NO_BUFFERING|FILE_FLAG_WRITE_THROUGH (0xA0000000).
Query geometry/alignment; allocate aligned native buffers, round transfer
offset and size to the required sector alignment, then slice the requested
range. Verify buffer/offset/length alignment, checked 64-bit LCN arithmetic,
returned lengths and every native status. Raw volume offsets are relative to
the volume; do not add the physical disk partition offset again. Write-through
on a reader does not flush another writer or bypass a disk's hardware cache.

Page FSCTL_GET_RETRIEVAL_POINTERS from VCN 0 through every returned NextVcn;
ERROR_MORE_DATA continues from the last NextVcn, with progress/bounds checks.
Store VCN, NextVCN, LCN, cluster count, allocation/EOF/valid-data lengths,
attributes, full FILE_ID_INFORMATION, NTFS record reference/sequence, stream
name and volume identity. Read every allocated cluster in bounded chunks,
including allocation beyond EOF, not just the first LCN or marker prefix.
Reconstruct bytes in VCN order. Negative LCN is not an address.

Cross-check retrieval pointers against raw NTFS attribute runlists and size
fields. Bracket each sample with identity/runlist/directory-index captures;
accept only a stable identity/layout or a specifically accounted publication
transition. Retry an unstable capture at most 10 times within 2 seconds and
record all attempts/gaps. Exhaustion is INCONCLUSIVE, never an unchanged read.
No exception can excuse a recorded forbidden byte. Stop at mutation barriers
for stable checkpoints; do not lock/dismount the live protected volume just
to observe it. Observer must never flush the subject's dirty cache to make
an Activating observation succeed.

Keep old destination handles read-only with delete sharing across replacement,
plus a new path lookup on every sample. Observe the old physical file until
its last reader closes and the new ID/extents after replacement. Allocation
movement/new temp files/EOF growth/resident conversion trigger complete new
run capture; before extents are never reused as the after map. Freed clusters
remain archived as historical storage, not assigned to a new file identity.
Any unaccounted allocation or mutation is coverage failure; never baseline a
newly discovered file after it has already received attacker bytes.

3.2 Resident data, directories, sparse and compressed data

File length alone is not a residency test, including a 4 KiB marker. No
retrieval pointers can mean resident or empty, not "zero allocated data".
Implement one read-only NTFS container decoder for files and directories:
  - Validate raw NTFS boot geometry and bootstrap $MFT's unnamed $DATA runlist
    from its initial record. Follow bounded attribute lists/extension records
    and the MFT runlist, not MftStartLcn + recordNumber across fragmentation.
  - Use FSCTL_GET_NTFS_VOLUME_DATA / FSCTL_GET_NTFS_FILE_RECORD as address/identity
    cross-checks, not content authority. The latter can return a lower in-use
    record: insist on the requested record number and sequence. Match the raw
    record with full queried file identity, its FILE_NAME parent/name and the
    parent index reference. Verify USA sector fixups, signatures, attribute
    bounds, sequence numbers and extension-record base references.
  - Resident unnamed $DATA: raw-read all sectors of the identified MFT record
    and extensions through $MFT's physical runs; apply fixups to a copy;
    extract precisely the resident value offset/length. Archive complete raw
    sectors and decoded data separately. The resident value, not an arbitrary
    marker found somewhere in $MFT, must match the known fixture digest.
  - Nonresident $DATA: raw runlists must agree with retrieval pointers and the
    reconstruction must match the known baseline. Conversion between resident
    and nonresident is observed on both sides, never treated as absence.
  - Directory baseline/sample: capture the scope and each affected parent MFT
    record, resident $INDEX_ROOT, complete $INDEX_ALLOCATION runs and $BITMAP,
    their extension records and INDX fixups. Decode only active index entries,
    including DOS/Win32 names and file-reference sequence. Record normalized
    listing, ID, size, attributes, timestamps, security ID and owner/DACL
    cross-check; preserve raw metadata changes separately. Grow an index with
    enough fixture entries to exercise nonresident directory storage.
  - Sparse unnamed data: LCN=-1 holes reconstruct as zeros; read every actual
    allocation, including preallocation beyond EOF, and record the hole map.
    Compression tail holes must not be mistaken for sparse logical zeros.
  - Compressed unnamed data: use attribute compression-unit size and runlists,
    gather the entire unit's allocated clusters, distinguish full uncompressed,
    wholly sparse and partially allocated compressed units, decode NTFS LZNT1
    with output bounds to the unit's logical size. Archive physical units and
    logical digests. The raw compressed bytes cannot be compared directly to
    a plaintext marker or SHA-256. Validate decoder independently in self-tests.

The observer supports these representations even if MVP admission refuses a
mutation on them. Unsupported compression format, EFS, malformed records,
unresolvable attribute list, mismatch or unreadable MFT/index is INCONCLUSIVE;
do not silently force a representation change and claim the original passed.
Require demonstrated resident and nonresident fixtures, fragmented runs,
zero length, sparse, compressed and representation conversion self-tests on
the VM. Main data-path fixtures are uncompressed, nonsparse, cluster-multiple
images; include separate small/resident and sparse/compressed refusal cases.

3.3 Fresh readers and byte predicate

Every sample also opens/closes a fresh buffered file reader and a separate
fresh native reader with NO_BUFFERING|WRITE_THROUGH and aligned transfers.
Both share READ|WRITE|DELETE and query identity before/after; hash the entire
EOF, with aligned last transfer and checked EOF short-read semantics. They
are supplemental: resident/compressed NTFS may still use internal metadata
cache, and the filter can refuse an Activating read. Record explicit expected
read denial there; raw observation is still mandatory. After Protected or
Released, both readers must match the allowed complete image. Held old
readers across POSIX replacement must keep the prior approved image.

Allowed destination images are (a) trusted setup baseline, (b) the complete
independently observed physical image and metadata at the actual, proven
Activating -> Protected promotion, and (c) service-approved images with
matching real permit records. Case-specific pre-scope P is a known stimulus,
not a fixed post-swap image: a retained old writer may turn it into U while
the file is Activating. Preserve both P and every observed intermediate
image; take the protection baseline only after final Free(F), W=0, exact
identity/SOP and raw stability. This baseline is not a service approval and
cannot be minted from an unexplained Protected mutation. For a Protected
final name, require a whole-image digest/length equal to that baseline or
the current permitted version; arbitrary mixtures of individually approved
bytes/versions fail. At atomic replace, old or new complete image is
permitted, not a torn combination or stale generation.

The public publication temporary is also destination storage. It is allowed
only after approval and permit grant: at each copy checkpoint its written
ranges must equal the same approved snapshot at the same offsets. Compute
per-range hashes from that snapshot plus its full digest; log copy offset/
length, file ID and lower completion, then require the complete digest before
rename. Unwritten ranges must be known zeros or unchanged captured storage,
with no attacker bytes. Never whitelist all bytes merely because a temp name
looks like the publisher's. Permits admit one temp create and consume one
POSIX rename; expiry/revoke/disconnect removes further authorization.

Compare every allocated container, not only EOF: retained file allocation
outside EOF must remain baseline or explicitly zeroed/approved padding.
For new allocation require zero initialization or approved padded content,
observed at its allocation/write checkpoint; unknown slack cannot pass.
Sparse holes must remain holes/zeros unless an approved image specifies the
change. Archive all MFT/INDX sectors; judge resident values and active names
semantically because legitimate NTFS timestamps/LSN/fixups can change unrelated
metadata bytes. Report every raw difference; require the table's exact allowed
name/ID transitions, and reject attempt payloads in attribute/index slack.
Do not equate unrelated bytes in a shared MFT sector with destination data.

Each attempt has a unique case/trial/offset-tagged payload, including changed
prefix, middle and tail blocks. Search all captured containers for its
forbidden blocks as an additional leak alarm. Digest + offset/identity
comparison is the acceptance predicate; marker absence alone is insufficient.

3.4 Temporal coverage and evidence

Sample baseline; before/after every operation/barrier; epoch swap; every
old-writer write and its lower completion; last cleanup/release; final W/Free(F)
snapshot and promotion; seal/inspection/block;
permit grant; temp-copy progress/flush; replacement lower completion;
Released; reconnect; and final quiescence. Run a continuous observer at a
target 10 ms cadence concurrently and record actual gaps/durations, full
passes only. Continuous polling alone cannot prove that a transient write
never occurred between samples.

Therefore also require a loss-detecting prototype mutation ledger at the
actual lower-admission/completion boundary: sequence, file/volume/SOP identity,
epoch, operation/paging bit, offset/length or metadata class, native result,
permit attempt and a digest of the submitted payload where applicable.
Account every destination lower mutation against trusted setup, a recorded
old-writer operation while that exact file is Activating, or actual permitted
approved output after Protected. Ledger entries must distinguish the state
and gate generation at lower admission and completion, especially an admitted
noncached write whose completion follows cleanup. A pre-existing physical
writer's paging/nonpaging I/O is admitted in Activating; a new scoped writer
must be refused by its prescribed gate before lower. After promotion, an
unpermitted lower mutation is FAIL even if a later write erases it. Lost
entries/overflow/missing post completion are INCONCLUSIVE for the byte proof
and block promotion where identity or W cannot be established. This ledger
complements independent raw reads; it is not the content oracle and cannot
mint approvals. Holds coordinate PASSIVE fixture/service work only; never
block a paging callback waiting for PowerShell.
Run unheld repetitions as well, so diagnostic holds do not supply protection.

Archive raw .bin containers/images plus stdout/stderr/trace/notification/journal
artifacts. Exactly one authoritative JSON per expanded case per mode/run,
with trials[]: schema/table revision, verdict/reasons, platform/boot/QPC,
input hashes, checkpoint links, taint/trust/policy state, operation results,
baseline/samples, extent maps before/after, resident/MFT/index locations,
logical and raw hashes, approvals/permits, journal generations/states,
notifications/audit, hand-back checks, latency arrays, coverage/disposal and
independent restoration. Use decimal strings for 64-bit IDs/ticks if JSON
consumers cannot preserve integers. Write a flushed temporary JSON then
atomically publish it; keep partial artifacts if no final JSON is possible.

4. Case table and exact common assertions

The following contracts are assertions inherited by every row, not optional
checks. Names below refer to physical/raw directory listing from the observer;
writer-private listing is separately checked against existing overlay tests.
For every row inspect notifications through the real authenticated product
pipes (interactive app session for justification), not console strings alone.
Correlate transfer ID, immutable digest, principal/session, destination and
generation. A reconnect may redeliver an identical event; forbid contradictory
events and duplicate publication, not harmless identical notification replay.

Outcome contracts for rows that create a private version:
  APPROVE: before permit, final bytes/listing are B (or name absent), no public
    temporary. Journal Allocated -> Sealed -> Inspecting -> Approved ->
    Publishing -> Released in order; sealed length/digest immutable. Actual
    inspected benign fixture, permit and one replacement produce exactly A.
    Names become final + no lingering temp; Released notification identifies A.
    No Blocked event or hand-back copy. End: Protected, Released.
  BLOCK: sensitive fixture generates Blocked, no Approved/Publishing/Released
    or permit. Final bytes/listing stay B/absent, no public temp. Real Blocked
    notification gives the verified hand-back path. Journal stays Blocked
    while justification is available; retain the snapshot until verified
    hand-back AND window closure. End: Protected; blocked version retained
    through that window, with audited cleanup only afterwards.
  JUSTIFY: first satisfy BLOCK and verify its hand-back. Submit through actual
    product client/UI as the owning standard user/session for the current
    exact version. Override audit precedes Approved (justified_version), then
    Publishing/Released via a new valid permit. Final is exactly that blocked
    snapshot digest, not an edited version. Released event matches; hand-back
    remains that same snapshot and no second unexpected copy is created.
  STALE-JUSTIFY: block v1, allocate/edit v2, justify unknown ID, superseded v1,
    wrong session/principal and replay a consumed request in separate variants.
    Exact rejection reason/audit, no stale permit/release/public-byte change;
    v1 hand-back digest preserved. Only an explicit approval of latest v2 may
    produce Released. Destination-generation barrier survives restart.

Hand-back contract H, mandatory for every BLOCK-derived row: new file under
per-user SafeUpload\_bloqueados (outside protected/synced trees), full bytes/
length/SHA-256 equal the sealed snapshot, ACL readback grants only that user
and SYSTEM, no inherited grants, no reparse component/hard-link alias and
single link. Verify access as owner and denial as a second standard user.
Record safe relative-to-verified-handle creation and no overwritten existing
file. Copy/verification failure must audit and retain staging, never notify
a successful copy or delete it. Close the justification window explicitly,
then prove cleanup occurs only after both conditions. Test before and after
service restart. A blocked destination never changes because H succeeds.

Denial contract D: protected final bytes, size, allocation and active names/IDs
unchanged; no public temp, no new journal transfer,
no approval/release/hand-back. Operation has a real ACCESS_DENIED/write-protected
or transition STATUS_RETRY result from the prescribed gate, not a sharing/open
failure in setup. State/status report the expected reason. Do not apply D to
an old physical writer while its file is Activating: that writer may mutate
the pre-protection image. D applies to new scoped writer admission and to
unpermitted mutations after Protected. A missing exact denial ledger, raw
sample, or disposal proof is INCONCLUSIVE. No generic catch counts as D.

Activating contract G: exact file ID/path, generation, H/S/C/T/W and known opener/
acquirer PID appear in the paged status and service event; a duplicate holder
PID is not inferred from the opener. New writable open/section and publication
into the held file satisfy D; existing physical writer handles, mapped views,
cached pages and paging I/O continue while Activating and are recorded as
pre-protection mutations. Do not turn an expected Activating read refusal
into an observer exemption: raw capture and its exact status remain required.
Policy-applied means the generation committed, not that every held file is
Protected. After the last reference and in-flight mutating completion,
require H=C=T=W=0, S=NO, same file ID/SOP, no shared cache map or data section,
no unresolved live marker, and a successful required cache/valid-data
barrier before the final serialized promotion and Protected event. Capture
the complete raw image at that stable transition. A barrier/identity failure
withholds promotion; it cannot silently turn a changed Activating image into
Protected. No scan telemetry or refresh timer participates. If a real holder
persists through reconnect, status remains Activating with exact reason.

4.1 Required Phase 4 workload rows

C01 Cached write. Setup B or absent final, initially Protected/registry absent;
standard user opens cached owned writer. Write whole patterned image, flush,
keep reader/handle, then close. Run APPROVE, BLOCK, JUSTIFY outcomes. While
mutable and before seal, raw final is B/absent and private read matches edit;
seal cannot precede last required upper reference/cache/rundown drain. Apply
outcome and H; final listing exactly specified by outcome. Phase 3: immediate
Protected, create/write epochs, existing owned-stream retirement/publication.

C02 Mapped write. Same outcomes, create PAGE_READWRITE section on owned stream,
close source handle while view lives, store, flush and keep section/view.
Private mapped bytes change, raw final/listing remain B/absent; no Sealed,
Approved or Released while references prevent conservative seal. Also retain
section with no view, create late view, then release all. Apply outcome and H
only after retirement. End as outcome. Phase 3: Protected section admission,
C pairing and private paging I/O, not physical grandfathering.

C03 Overwrite. Existing B, held independent physical reader shares DELETE.
Open overwrite/truncate, change EOF and write A; test ordinary overwrite and
supersede separately, APPROVE/BLOCK/JUSTIFY each. Before permit B's whole
allocation/EOF/listing unchanged; private EOF reflects edit. After approved
POSIX publish new path identity/image is A, old held reader/raw identity B.
Blocked keeps B. Journal latest generation only; notification/outcome/H exact.
End as outcome. Phase 3: Protected destructive-create and publication epochs.

C04 Replacement save. B exists; user writes private sibling temporary, holds
old target reader, then native FileRenameInfoEx REPLACE_IF_EXISTS|POSIX save.
Run APPROVE/BLOCK/JUSTIFY and ordinary replacement with an open private target
(expected explicit refusal) separately. Namespace prepare/commit generations
reserve source and target; private overlay shows target, source tombstone.
Physical B persists before permit, no unapproved user temp/target appears;
after approval only target A and no service temp, old held reader B. Durable
source tombstone forbids stale source publication after reconnect. Apply H.
Refusal variant keeps both mappings/generations consistent and no release.
Phase 3: rename/namespace and publication tokens, destination generations.

C05 Rename into folder. External source U, Protected target absent or B;
attempt rename by standard-user old physical handle. Expect D: source remains
same ID/U, target B/absent, journal unchanged, no release/H. Positive variant
uses an owned source in another protected sibling under the same policy,
then private native rename into target and APPROVE/BLOCK/JUSTIFY. Apply C04
source/target reservations and outcomes; no physical source deletion is
assumed before approval. If the existing owned path retains an approved public
source, require that documented retained source image, not invented MoveFile
semantics. Unsupported rename routes must refuse explicitly. Phase 3: both
names/ancestors checked under current+pending policy, epoch to lower completion.

A01 Pre-scope handle. Boot-attached trusted volume; open physical writer while
folder Unscoped, write known P and retain the handle, then add scope. Capture
P before the epoch swap and G with H>0 afterwards. Through that same old file
object, exercise cached/noncached writes and supported EOF/allocation updates
with uniquely tagged U; account their lower completions and observed raw
intermediate images while Activating. In separate variants exercise
disposition/rename/link routes with exact expected state/status and no false
Protected claim. New writable opens/sections and service publication into
the held file satisfy D; no service journal release/H occurs from old-writer
data. Close the last handle, drain W, prove Free(F), capture the resulting
whole image/metadata as the protection baseline, then require Protected.
Run APPROVE from the real service to prove only a permitted image changes it
after promotion. End Protected/Released. Phase 3: registry history, H/W,
Activating admission and serialized promotion.

A02 Pre-scope mapped view. Create a physical writable view Unscoped, write P,
close the source handle, add scope, require S=YES and G. Run no-later-store
and uniquely tagged post-swap U variants. Stores, FlushViewOfFile and paging
writes from the retained view remain admissible while Activating; capture
actual raw P -> U changes and ledger completions rather than demand a paging
denial. New writable section creation/open into that file satisfies D.
Retain the view through service reconnect in one variant: no premature
Protected status, journal release, or permit. Release view and section,
wait for true Free(F)/W=0 and the exact barrier, then capture final stable
image as the protection baseline and require Protected. If references remain,
end Activating and report the holder. A subsequent unapproved U written after
the Protected event is FAIL. Phase 3: S/cache lifetime and promotion boundary.

A03 Retained section. Create a physical PAGE_READWRITE section Unscoped with
no view, close its file handle, prove the section remains live and S=YES (do
not assume H=0; it may retain the file object). Add scope and require G; map
the first view from that retained section after the swap without relying on a
new acquire callback. Run no-store and uniquely tagged late-store variants;
the retained section's CPU stores/paging I/O are pre-protection mutations,
with exact ledger/raw evidence and no service publication. A new section
acquire/open satisfies D. Keep one late view through reconnect and prove no
premature promotion. Release all references, prove S=NO and final Free(F),
capture the resulting baseline, then require Protected. Phase 3: retained
S reference, targeted recheck, no scan.

A04 Duplicated handle. Unscoped writer, DuplicateHandle into another standard-

5. Modes, repetitions and latency

Identical expanded table and predicates in all modes; mode changes lifecycle
and verified configuration only:
  ordinary: no configured or active Verifier; feature boot-start/trust intact.
  runtime: feature boot-start plus volatile Driver Verifier 0x13B on
    SafeUpload.sys, read back active flags before/after case. Startup probe
    must arm/read back runtime checks before its attempted I/O for R03;
    report separately that DriverEntry itself ran without runtime checks.
  boot: configure standard Driver Verifier for SafeUpload.sys, oneboot as in
    run 13/15, querysettings before reboot and active /query after reboot.
    Record exact flags, Filter Verifier/diagnostics and no stop. For rows
    requiring another in-case reboot, rearm boot checks and verify again.

Do not confuse /querysettings with active /query. Verifier exit 2 is successful
reboot-required configuration only when exact settings read back; exit 1 is
failure. Real /volatile /faults replaces flags with 0x4 and /flags resets
fault filters: prefer prototype deterministic injections to preserve the
three-mode matrix. Additional real low-resource windows are labeled LRS-only
and cannot substitute for a qualifying 0x13B run. Reset then restoration
reboot is required even if configured flags appear cleared.

Correctness repetitions: one fully coordinated trial for every boundary,
then 100 unheld trials per repeatable variant, deterministic seed recorded.
Use fresh file identities for held-writer and sticky Unknown tests; rebooted isolated
trials when global state prevents reuse. Boot R03 retains its single earliest
attempt plus 100 startup denials in the same state. Respect existing 128
owned versions/16 MiB bounds and Phase 3 registry limits; split repetitions
across separate checkpointed runs before exhaustion rather than silently
testing resource failure. Capacity rows alone intentionally exhaust them.
Missing repetitions/samples cannot be pooled away across cases or modes.

Latency is absolute, no relative slowdown threshold. Use QPC immediately
around native calls and service request/completion, preserve raw samples,
status and phase. Per expanded row and mode collect >=100 unheld samples
per exercised bounded operation class: writer open/deny, cached write,
section create, native rename/replace, flush/close, policy apply without
external holders, status request, justification accept/reject, and service
publication after authorization. No sample formatting, file coordination,
PowerShell startup or observer wait inside native timing. Retain cold/first
sample separately and include it in max; no trimming, retries or subtracting
an unfiltered baseline. For mapped stores measure stores and subsequent
flush/section retirement separately; store time is not disk enforcement time.

For every class sort n durations, p95 = sample ceil(0.95*n), max = largest;
require p95 <=250 ms and max <=1000 ms. Single first-boot sample must also
meet max; the 100 denial samples supply its class's p95. Gate checks all
classes individually, not a fast pooled average. Capture approved/blocked
decision-to-terminal-result duration as well as each publisher call; require
the same budget for automatically completed saves after references release
and, for justification, after the user submits. Report complete application
save-to-notification latency, sealing/inspection/publication components and
reader/observer cadence. Human think time, intentionally retained sections,
test holds and the injected 30-second drain timeout are tagged scenarios,
not normal latency samples; counterpart unheld calls are still mandatory.
Never subtract a measured test hold to manufacture a passing sample. A real
unheld operation over budget fails even if the bytes were safe. Record guest
CPU/vCPU/affinity/priority/disk/Verifier and load; do not assume Phase 1's
primitive-cost p95 proves end-to-end latency.

Harness pitfalls to resolve once, in shared code:
  - PowerShell 5.1 has no six-argument File.Open. Use FileStream constructors
    for durable JSON/copies; native CreateFileW for unbuffered reads.
  - [string] arguments turn $null into "". Test IsNullOrEmpty/IsNullOrWhiteSpace
    for optional paths, preserve explicit empty native arguments with checked
    quoting, and never treat an empty path/hash/exit code as valid evidence.
  - MethodInvocationException wraps UnauthorizedAccessException/Win32Exception.
    Walk/record InnerException chain; recognize exact expected native denial,
    not the outer message or every exception from WriteAllBytes/Dispose.
  - Scheduled-task errors do not propagate to SSH. Redirect stdout/stderr,
    catch into durable completion data, cache Process.Handle before waiting,
    reject null ExitCode, verify LastTaskResult, stopped task state and unique
    run-scoped readiness/completion. SYSTEM policy writer requires correct
    System.Security.AccessControl types; timeout is not silent success.
  - Verifier exit 2/settings versus active flags and reset-reboot handling
    follow section 5; never infer activation from an accepted command alone.
  - Wrapper's CLIXML filter has hidden PRE_RUN errors. Preserve unfiltered
    stdout/stderr alongside readable output, extract errors explicitly, require
    unique PRE_RUN_OK/phase sentinels and complete case JSON, inspect PIPESTATUS.
    HARNESS_RETURNED and wrapper exit status are not the verdict. Define helpers
    before use. No duplicate/stale sentinel or missing result can pass.
