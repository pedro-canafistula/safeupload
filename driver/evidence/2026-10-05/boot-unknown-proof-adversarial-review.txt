## Findings

**Qualification blocker if “first” means earliest Unknown event.** `StageRegistryQueueDeferredUnknown` stores `OriginSite` in the referenced work item (StageWriters.c:4846-4885), and `StageRegistryUnknownWorker` later calls the first-pair recorder (4816-4834). A later direct mark can reach the instance context and win `InterlockedCompareExchange64` before an earlier queued mark's worker runs. The packed pair is atomic, but it records first successful context publication, not event chronology. Minimal bounded fix: label/document the exported fields and MVP note as “first recorded/published reason and origin site”; state that deferred work preserves its source callsite but scheduling can change which mark wins. Do not infer the oldest trigger from this field without adding explicit event ordering evidence.

**Coverage is narrower than “any Unknown cause.”** The recorder runs when a per-instance context is successfully obtained directly (StageWriters.c:749-754) or by the deferred worker (4816-4819). If `FltGetInstanceContext` fails at <= APC_LEVEL, the direct branch does not record the pair; if deferred queueing fails, the existing path falls back to global Unknown without a per-instance pair (772-785, 811-818, 4853-4892). Entry-local non-rename loss also returns before instance propagation (StageWriters.c:788-800; cleanup caller 2388-2400). The admission-status API defaults `InstanceWritersUntracked` to 1 when context retrieval fails (StageAdmission.c:183-209), so consumers must require successful `ContextStatus` before interpreting a zero pair as “no source.” The producer sets the per-instance `WritersUntracked` only after recording the pair on successful direct/deferred context paths (StageWriters.c:768-770, 4818-4835), which supports the intended narrower successful-context capture. Minimal bounded fix: scope prose to successful per-instance context marks and explicitly treat failed context/queue and entry/global-only paths as un-attributed by this field; do not claim it explains all global or entry Unknown state.

**Site value is a source line, not a stable identifier.** The `Stage.h` wrapper and local macros pass `(ULONG)__LINE__`; the feature output emits only `firstUnknownSite` (StageAdmission.c:204-209; Inspector/main.c:1065-1078). There is no file identifier in the field. For this exact source pin, the callsite list can be looked up and the author note correctly requires the matching source; the line number is not portable across revisions and should never be interpreted without that pin. If output is meant to be independently decoded without consulting the pin, add a file/site ID or globally unique callsite ID. Current documentation's same-source warning is necessary and should remain.

## Checks that passed by source inspection

The direct recorder obtains an instance-context reference before touching it and releases it after the updates (StageWriters.c:749-771). Deferred instance work owns a temporary instance reference; deferred entry work references the entry, then snapshots/references its live instance while serialized with retirement, and releases both resources in the worker/error paths (4799-4843, 4846-4894). The worker is explicitly placed in PAGE and Filter Manager documents `FltQueueGenericWorkItem` workers run at PASSIVE_LEVEL; direct `FltGetInstanceContext` use is guarded to <= APC_LEVEL, matching Microsoft's documented IRQL limit. The new context field is explicitly 8-byte aligned (Filter.h:275), and `InterlockedCompareExchange64` performs the indivisible first-wins update; its destination requires 64-bit alignment. Context creation explicitly zeroes the full instance context (Context.c:321-350), so zero is a valid unrecorded sentinel.

The feature-only guards cover the added context member and admission-volume wire fields; the normal `SAFEUPLOAD_STAGING_PROTOTYPE=0` layout remains unchanged by this diff. The feature `C_ASSERT`s give 208-byte/6672-byte volume-status sizes versus the normal 192-byte/6160-byte sizes (Protocol.h:1203-1213). Inspector format-string and argument additions are guarded together; W-trace protocol entries and parser schema are untouched. This is source inspection only; matching feature compile properties across filter and Inspector and exact-size runtime exchange still require the stated normal/feature builds and test.

Primary documentation checked: [Microsoft `InterlockedCompareExchange64`](https://learn.microsoft.com/en-us/windows/win32/api/winnt/nf-winnt-interlockedcompareexchange64) requires 64-bit alignment; [Microsoft `FltGetInstanceContext`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltgetinstancecontext) is <= APC_LEVEL and requires releasing successful context references; [Microsoft `FltQueueGenericWorkItem`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltqueuegenericworkitem) queues at <= DISPATCH_LEVEL and invokes its worker at PASSIVE_LEVEL.
