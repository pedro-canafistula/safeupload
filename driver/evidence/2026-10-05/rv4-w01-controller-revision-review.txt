Remaining bounded source/parent concern

The script checks that `$Target` has the expected filename and independently verifies its FileId, but it does not require its canonical full path to equal `Join-Path $FixtureRoot ('rv4-w01-target-'+$runGuid+'.bin')` (`Assert-Pins`, lines 96-108). The stimulus opens that exact child path itself and verifies it stays under the fixture root, so the actual write path is constrained. Still, an accidental caller can pass a different path to the Inspector probe/raw-target selection if it is a same-file hardlink. More importantly, the stimulus does not check the opened file’s hardlink count; an owned-root hardlink to an existing user file would make a write through the owned path mutate the same user file. The stated parent contract says it provisions an owned target, but does not expressly prove exclusive creation/no outside hardlinks. Minimal closure is: normalize and require the controller target path to equal the exact fixture-root child path, and have the trusted SYSTEM parent create the target exclusively from the expected image and prove link count is one before invocation (or add a reliable file-standard-info link-count check in the stimulus). Do not run unless the parent can establish that fixture provenance. This is a parent ownership prerequisite rather than evidence that the current code necessarily modifies a user file.

PowerShell 5.1 mechanics

The revised script was actually parsed by Windows PowerShell 5.1.19041.6456 via `Parser::ParseFile` only: report `output/mvp-continuation/rv4-w01-controller-ps51-parse-revised.json` pins both pre/post script hash to the reviewed SHA, zero parse errors, and no script execution. That does not test process/writer behavior. One small known-runtime reliability point remains at launch (`Start-Process` line 168): the source reads `$process.Id` and later waits/checks `$process.ExitCode` but never eagerly caches `$process.Handle`. Other Windows PowerShell 5.1 harnesses in this repository do `$null=$p.Handle` before `WaitForExit` (for example `Test-StagedInvariantSuite.ps1:185-187` and `Test-StagedDuplicatedHandle.ps1:57`) specifically to avoid a null exit code. Add `$null=$process.Handle` immediately after launch, before waits/exit inspection. This can only turn a successful probe into false inconclusive today, since the script never emits PASS, but it avoids a known evidence failure.
