## Integration checks

The Unknown addition is isolated to feature-only instance state, status fields, and read-only reporting. It leaves the W ring, record layout, W ticket code, and CLEAR implementation unchanged. `StageAdmissionTraceReset` resets only ring/counter/watch state; the new per-instance first-context-publication pair remains sticky for that instance and is not reset by trace CLEAR. The final Unknown comments correctly limit attribution to a successful context publication, require successful `ContextStatus`, and exclude failed context/queue, entry-local/global-only cases. Thus CLEAR cannot erase or relabel that boot evidence, and the Unknown pair does not contaminate W ticket pairing.

The trace control path retains the reviewed sequence: DISABLE/CLEAR publishes a new off epoch, waits for recorder rundown, then refuses while a ticket remains or `LostEntries` changes; reset occurs only after both checks pass (StageStream.c:294-329). W Begin acquires the recorder permit before core W increment and retains it through ticket-or-loss publication (StageWriters.c:2593-2599, 2621-2703), then drops it before the IRP proceeds. W End captures actual callback status/Information/flags before retiring the core token, recording W_END, dropping the extra entry reference, and decrementing outstanding (2746-2760, 2818-2834). An absent completion remains explicitly `STATUS_PENDING` with the pre-lower-retirement bit, not a lower-completion receipt (2824-2829).

Rename passes the same mutating-I/O context into the rename context (StageStream.c:3391-3395; StageWriters.c:2852-2861). Its post path captures completion fields before completing the rename and ending the ticket (StageStream.c:3565-3571; StageWriters.c:1937-1950). I found no new double-end, lost ticket, freed entry, or CLEAR/rundown race introduced by the added first-Unknown field or protocol comments.

Policy generation is sampled independently with `SafeUploadCurrentPolicyGeneration`, whose implementation is an interlocked read of the policy-generation field (Policy.c:1189-1197); the W snapshot comment states it is outside StateLock and not a coherent whole-record tuple (StageWriters.c:2526-2552). The corrected `ActivationGeneration` access remains aligned/interlocked at all shown operational sites (StageWriters.c:133, 165, 2540-2541, 4435, 5588, 5662, 5694). H/W/state/generation/policy do not form one atomic snapshot: the `LOCKED` flag is only the StateLock/W boundary, and H writers are not all serialized by it. A fixture must continue using an externally stable boundary plus cleanup/lower receipts for an H=0/W=1 claim.

## Additional control-transition boundary found during integration pass

A concurrently issued W operation can be absent from an otherwise loss-free trace across ENABLE/CLEAR. `SafeUploadStageWritersBeginMutatingIo` snapshots `SafeUploadAdmissionTraceControlState` at `StageWriters.c:2597` and only holds recorder rundown if `SafeUploadStageAdmissionTraceBegin` succeeds at 2598-2599. That helper acquires rundown and rejects if the state changed (`StageStream.c:156-168`). Consider a callback that reads the old enabled state and is preempted before acquire; CLEAR turns the state off, sees no rundown holder or ticket/loss, clears and re-enables; the callback resumes, its old-generation acquire is rejected, and it continues the core W transition with `observerPermitHeld == FALSE`. The symmetric transition can happen for a callback that observed disabled before ENABLE and proceeds after it. These failed admission attempts do not increment `LostEntries`.

This is not introduced by the Unknown instrumentation, and it does not block a controlled W01 case if the external fixture proves there are no target/background writes crossing CLEAR or ENABLE: clear/enable must finish before triggering the selected writer, and writers must be quiescent across those transitions. The parser README says a complete window models CLEAR before the finite trial and calls for independently bound controller/epoch evidence, but the controller evidence should explicitly include this quiescence boundary. Without it, the source cannot prove that every actual write in the trial was offered a W ticket. A self-contained source fix would need to account for pre-op observation attempts before control transitions (and drain those attempts); the existing rundown begins only after a successful acquire.

## Final disposition

The copied Unknown and W-ledger source pins match the isolated reviewed pins. I found no new lock-order, context-lifetime, ticket ownership, rename transfer, Unknown-pair/CLEAR coupling, or protocol incompatibility from combining them. The concurrent control-transition gap above remains a conditional limitation on claiming an exhaustive loss-free W window; external quiescence evidence or a future observer-admission fix is required. The prior W-ledger limits on H/W tuple coherence, opaque cross-filter callback identity, lower receipts, cleanup overlap, raw data, and runtime qualification remain unchanged.
