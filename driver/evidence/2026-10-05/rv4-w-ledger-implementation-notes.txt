Entry size is 232 bytes; batch size is 1960 bytes.
- `driver/SafeUpload.Minifilter/Stage.h`: test-prototype recorder-loss, W completion capture, and outstanding-ticket interfaces.
- `driver/SafeUpload.Minifilter/StageStream.c`: carries callback data into the existing W begin site, captures actual post result and flags, and makes disable/clear close recorder rundown before testing outstanding tickets. It also compares the loss count across that off/drain window. A W_END that retires during the window writes durable LostEntries before releasing its ticket; clear detects that delta and returns busy without resetting it. Disable/clear do not erase a missed pair and report `STATUS_DEVICE_BUSY` on an active ticket or loss race.
- `driver/SafeUpload.Minifilter/StageWriters.c`: fixed 128-slot static nonpaged test observer wrapper around the existing W context. It acquires recorder rundown after parameter validation and before core W accounting, holds it only through bounded begin/wrapper setup, and releases it before the IRP is sent down. This makes the observer epoch the successful permit; the host must enable tracing before stimulus and keep it enabled for the whole stimulus. Pool exhaustion increments LostEntries while that original permit remains held. The wrapper owns the existing token, holds an extra registry entry reference through post, preserves the same wrapper across rename attachment, records a matched ticket at post/draining, and releases the existing token through the original path. The observer pool is bounded and does not fail or alter product I/O accounting. Activating status samples W with H/state while holding the existing entry StateLock; ActivationGeneration is an independent atomic sample.

## Snapshot meaning and interpretation

The event's entry snapshot holds the existing per-entry StateLock while sampling H, W, RegistryState, UnknownReasons, volume serial, and file ID. The flag means the lock was held during this bounded sample; it does not make the entire record a seqlock snapshot. W begin/end mutations serialize on this lock. H, RegistryState, and UnknownReasons are independent atomic samples; H writers do not all take StateLock, and the source audit does not establish that every state/reason writer takes it. ActivationGeneration is also independent: all reads and writes now use aligned Interlocked operations, but the generation can change concurrently with the StateLock-protected W sample. Treat these values as sampled context, not a coherent tuple. A fixture-controlled stable boundary plus lower-hold/W receipts is still required for H=0/W=1 claims. `EXACT_ID` is set only for a bound registry entry. `POST_RETIRE` means W was decremented before the snapshot; it is an observed post-retirement state, not a claim that every field equals its value at the exact W decrement or that the global policy generation changed atomically with the entry. PolicyGeneration is the independently sampled current semantic epoch. Marker/spill tickets carry no exact registry identity and remain INCONCLUSIVE for entry-specific claims.

The trace ring remains bounded and loss counters are authoritative. Reader qualification must reject any LostEntries, cursor gaps/overwrites, unmatched ticket sequences, non-exact identity when exact identity is required, absent post-captured flag, or pre-lower-retirement flag. The opaque callback-data address is upper-filter-local evidence only; this source does not prove it stable/unique across the separate lower filter. Pair lower records using independently observed same-request rules with exact FO/SOP identity and write offset/length; do not use the pointer alone as cross-filter proof. Offset/length are raw `FLT_PARAMETERS.Write` values and do not prove the committed raw range. W status is a snapshot, not a separate W_END receipt.

## Revision after fresh adversarial review

The prior pool-full path released recorder rundown before trying to reacquire it for LostEntries. It now increments LostEntries directly while still holding the original recorder permit. Begin acquires that permit after validating Data/Instance/FileObject/IRQL and before core W accounting; it holds the permit through the bounded context lookup, W/marker accounting, and optional wrapper + W_BEGIN recording. It releases once on stream-context lookup failure or at the normal function exit. It does not hold the permit through the IRP lifetime and does not change I/O completion, admission, Unknown, or enforcement policy on observer loss. A tracked writer for which no completion context could be produced records loss under the same permit. A callback that cannot acquire a permit is outside the observation epoch; the host must enable tracing before stimulus and leave it enabled through the stimulus. This source change is intended to close the reviewed pool-full/reset interleaving; no deterministic test harness for these Windows kernel rundown helpers was present in the isolated worktree, so no mock or runtime race test was added.

The lower filter fixture, lower-result receipt, raw-byte observer, temporal proof, and Inspector changes remain separate work. This source increment by itself does not establish W01/W02 qualification or a PASS.
