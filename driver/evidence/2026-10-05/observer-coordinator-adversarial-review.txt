Observer corpus coordinator adversarial review
Date: 2026-10-05
Reviewed: current uncommitted Invoke-StagedObserverCorpus.ps1 and
Invoke-StagedObserverCorpusQualification.py, with the retained committed corpus
and StagedInvariantObserver contract as comparison. Read-only; no VM, builder,
commit, or network mutation.

Disposition
-----------
The coordinator pins and stages the exact corpus/observer bytes, waits for its
child, writes a completion record, hashes/reads back the guest ZIP, and the host
checks wrapper restoration before it can return ObserverCorpus=PASS. The host
also reconciles case inventory, result counts, raw stdout, exit code, and
completion status. That is useful lifecycle evidence, but the host's PASS
validator does not yet validate the core reader and per-sample content contract.
Its own synthetic PASS archive has no Readers arrays and unchanged synthetic
sample images, yet is accepted. This is the principal false-positive blocker.

The PowerShell 5 generic-list binder issue reported by the builder is addressed
in the current working files: the guest archive manifest uses
`$entries.ToArray()` (Invoke-StagedObserverCorpus.ps1:93) and the corpus summary
uses `$script:Results.ToArray()` (Test-StagedInvariantObserverCorpus.ps1:546).
Those are the exact mechanical fixes for the observed `@($list)` binder
ArgumentException. Do not treat those fixed lines as an outstanding blocker.

Required findings
-----------------
1. **Host PASS validator accepts missing readers and unchanged samples.**
   `validate_pass_evidence` checks image/artifact refs and that the declared
   raw manifest covers ZIP `.bin` files (Qualification.py:199-233), but never
   validates `Readers`, their buffered/unbuffered pairing, held-retained
   identities, or Before/After identity and digest against the image. It also
   only requires named sample JSON to exist and carry status/sequence fields
   (192-198); it does not verify that each sample image differs from its
   baseline at the expected bytes, that old/new identities are correct, or
   that recorded first/middle/last evidence is present. `self_test()` proves
   the gap: its synthetic PASS fixture omits Readers entirely and reuses the
   same image for baseline and every sample (388-420), then
   `inspect_archive()` accepts it as PASS (468-471).

   Required fix: make host PASS validation independently require the corpus
   contract's fresh reader pair for every present Current image, a held reader
   for every Retained image, stable matching full identity and length/digest,
   and case-specific expected sample transitions/raw artifacts. Add synthetic
   rejection controls for absent readers, stale unchanged mutation samples,
   wrong replacement FileIds/retained bytes, and identity/digest mismatch. The
   guest source hash does not make these outputs self-validating; the host's
   validator currently advertises an independent evidence gate but can accept
   contradictory PASS output.

2. **Collision/error recovery can write into an unowned evidence directory.**
   Coordinator checks for existing RunGuid paths and throws at lines 145-147,
   but the catch handler (222-229) attempts to create
   `coordinator-error.json` and archive any existing `$evidenceRoot` whenever
   `$archive` is absent. It does not track whether this invocation created that
   root. A reused RunGuid with an existing evidence directory therefore
   mutates/archives prior-run evidence after correctly detecting a collision.
   The same catch writes `coordinator-error.json` before calling
   `Assert-NoReparseTree` (224 before 228), so a reparse-root/tree rejection
   can cause the recovery path to write through the very reparse path it
   rejected.

   Required fix: track exclusive creation/ownership of fixture/evidence roots
   and only run recovery writes/archive for roots created by this invocation;
   perform no recovery write until ownership and reparse checks pass. Collision
   detection must leave existing paths untouched.

3. **Timeout kills only the PowerShell process but continues destructive
   cleanup.** At coordinator lines 165-169, timeout calls
   `$process.Kill()` (the child PowerShell process) and waits for that process
   to exit. The corpus launches `fsutil.exe` and `compact.exe` as native child
   processes (committed corpus lines 318 and 346); Windows process termination
   does not by itself guarantee descendant termination. After only checking
   `$process.HasExited` (coordinator 170), the coordinator archives and deletes
   the entire fixture tree (199-204), even when `$timedOut` is true. A surviving
   native child could still access or mutate fixtures during/after deletion.

   Required fix: run the guest child in a kill-on-close Job Object/process
   tree, verify descendants have exited, and on timeout leave owned fixture
   state intact with recovery required instead of deleting it. Preserve and
   archive only after all writers are known stopped.

4. **Host wrapper timeout drops available guest archive collection.** On
   `subprocess.TimeoutExpired`, host adapter writes a timeout verdict and
   returns immediately (Qualification.py:548-560). It does not attempt archive
   retrieval or retain a post-timeout gate/archive probe. The generic wrapper
   timeout path may already have written recovery evidence and a coordinator
   archive may exist on the guest, so this branch can leave completed raw
   evidence uncollected. Recovery must still be treated as pending; this is an
   evidence-preservation gap, not permission to resume guest work.

   Required fix: keep timeout verdict and recovery stop, then collect any
   already-complete immutable archive/gate through a bounded read-only recovery
   path after confirming the remote writer stopped; never delete guest state
   just to make collection succeed.

Contract checks that did not show a false PASS
---------------------------------------------
* Normal coordinator flow copies and re-hashes the frozen corpus/observer,
  hashes its own script, runs one child with fixed arguments, and has finite
  timeout/wait branches (coordinator: 142-183). It archives before deleting
  fixture/evidence roots, verifies archive entries against pre-archive hashes,
  retains the ZIP, and only then removes the exact staged inputs (83-134,
  197-211). Host adapter compares guest archive SHA to the guest completion
  sentinel and verifies ZIP CRC, duplicate names, path safety, manifest
  inventory, every ZIP entry hash, summary case counts, stdout, completion,
  and independent pre/post restore markers (Qualification.py:280-358,
  562-604).
* The corpus status semantics remain bounded to driver-off stimuli. Child
  exit 2/timeout maps to INCONCLUSIVE, and host enforces child exit/status/count
  consistency before exporting ObserverCorpus status. `Phase4Suite` remains
  NOT_QUALIFIED.
* Guest `New-VerifiedArchive` checks the manifest against each ZIP entry and
  hashes each referenced entry; host repeats ZIP integrity and archive-manifest
  validation. The generic wrapper then performs its independent final baseline
  and process-creation-audit restore check. No source-level false PASS was
  found in those specific gates.

Limitations
-----------
The current host validator's acceptance of its own synthetic PASS fixture is
an objective validator gap; it does not prove that a real unmodified corpus run
will omit readers or unchanged checks, because the pinned corpus source checks
those locally. However, a host result called PASS must reject missing or
contradictory retained evidence itself. No runtime or builder behavior was
tested in this review.
