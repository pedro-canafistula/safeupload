Blockers and bounded fixes

1. Draining lower post is not rejected. At `Test-StagedW01Diagnostic.ps1:242-245`, the controller verifies lower status, information, callback-data address, and generation, but it only records `PostFlags`. The actual lower `FaultPostWrite` stores `Flags` (`Fault.c:256-267`), including whether the callback is running with `FLTFL_POST_OPERATION_DRAINING`. The plan explicitly requires genuine post flags and a non-draining completion. Require the draining bit to be clear before setting `$postComplete`, and preserve/report the raw flags. Otherwise a draining callback can satisfy the controller's success-shaped lower result while invalidating the intended operation interpretation.

2. Protected-control claim is only a precheck, not a before/after invariant. Lines `184-186` check a separate entry once for Protected, same volume, no unknown reasons, and W=0. There is no later protected-control read, no comparison against its pre-run generation/state/identity, and no check of its H. The final note at `264` delegates “control” cross-checking to the host, while the plan at line 14 says the host must compare a Protected control that stays unchanged. Capture the full exact control entry before arming/activation and after the final trace, including ID/serial/state/H/W/generation/unknown flags, save both raw Inspector outputs, and have the host require equality (or retain a clearly independent equivalent receipt). As written, this script cannot evidence the unchanged-control assertion.

3. The H=0/W>0 claim is a sampled overlap, not a coherent tuple. Lines `214-229` sample the upper status and lower held status repeatedly; the second check brackets a raw capture, and the exact lower operation remains held. This is useful evidence and does not itself fabricate the cleanup overlap. However, H and W are not one atomic locked snapshot (plan line 16 documents this), and the script does not itself correlate the status samples to the same `file_cleanup`/upper W ticket or exact FO/SOP. The held upper trace is only saved at line 229. Keep this explicitly provisional and require the host to bind a real cleanup for this file/FO and the exact W_BEGIN/W_END/lower operation, then establish the observed H=0/W>0 interval while the lower callback is held. If that join or opening/lifetime exclusion is unavailable, report INCONCLUSIVE; do not promote the page samples alone to proof.

4. Whole-window foreign W is not rejected by the invoked parser. Lines `192-195` correctly make the target writer quiescent across enable/CLEAR; the plan explicitly limits that claim to the controlled target. But the host validator at `Validate-StagedWTrace.py:152-155` skips every non-`w_begin`/`w_end` event, and returns `PAIRED_W01_SUCCESS_STATUS` once the one expected pair matches (`214-218`). Thus a foreign/background W or other row can exist in the cleared window without the parser rejecting it. The plan itself says the host must reject any foreign W and must not discard control/raw artifact writes (line 16), but it does not supply that audit. Add a bounded whole-window event/counter audit or make the independent host acceptance procedure explicitly enumerate and account for every non-target W/event and reject unexplained writes. The output from the W-only parser alone is insufficient.

Review correction / follow-up (same reviewed pins; source verification after parent feedback)

A. Definite lower callback-data mismatch missed in the initial review. `Fault.c:487-498` zeros `FaultWriteLowerCallbackData` on arm. The only write to it is `FaultPostWrite` at `Fault.c:264-268`. `FaultWriteFillReply` simply returns that value (`Fault.c:424-448`). Therefore while the callback is held, before post, `status.LowerCallbackData` is necessarily zero. Controller line `208` requires it nonzero and will reject the intended held state. If that check is removed alone, line `243` still compares the post callback-data address against `$status.LowerCallbackData` captured before release, also necessarily zero, so a valid post pointer will fail. This makes the current fixture unable to complete its intended case. Minimal fix: at held time require the source-produced held facts (CurrentHeld, generation, exact armed FO, range, NOCACHE/nonpaging); do not invent a lower callback-data receipt before post. After post, require a nonzero lower callback-data value and keep it as the post receipt. Host correlation to the upper W ticket must use fields actually present at each point (same target file ID/serial, exact FO/SOP where available, PID, range, arm generation and chronology); do not assume the opaque upper and lower callback-data addresses are equal without independent evidence.

B. Corrected upper-validator characterization. The validator does not accept a foreign `w_begin`/`w_end`: it checks each W row's exact file ID, serial, PID, range and flags, and enforces exactly one pair (`Validate-StagedWTrace.py:152-179, 203-213`). My earlier wording that it accepts foreign W rows was too broad. The real limitation is narrower: it skips every non-W event (`152-155`), so a producer event such as an unowned/background nonpaging write, or other non-W rows relevant to proving isolation, is not accounted for by its `PAIRED_W01_SUCCESS_STATUS` result. The complete-window foreign-write concern remains only for such non-W rows; acceptance needs separate whole-window event/counter review as the plan already says.

C. Raw observer output is durable at artifact level, but the returned baseline/sample records are not persisted by this controller. The controller uses `$baseline`, `$before`, `$heldSample`, and `$after` in memory; only baseline SHA is copied into the final event at line `156`, and after sample Status/completion at line `262`; the before object is not subsequently used or serialized, and held object's raw hash is checked then discarded. `StagedInvariantObserver.psm1:493-505` writes binary artifacts and `manifest.ndjson` entries containing artifact path/kind/length/hash. `Save-IOImage` returns richer identity/layout/metadata (`507-520` onward), and `Capture-InvariantBaseline/Sample` return images, readers, phase, timing, and statuses (`713-745`, `793-837`), but the script never writes those whole records. Thus artifacts plus manifest preserve bytes and hashes but do not preserve which returned reader/capture statuses, IDs, layouts, sample timing/phase, or baseline/held/after records the controller used. Minimal fix: serialize each successful baseline and BeforeWrite/HeldBeforeLowerRelease/AfterLowerCompletion record, plus the failed/error record on exceptions, into immutable evidence files and hash them in the final manifest; or explicitly make the independent host recapture and validate all metadata from raw artifacts. Do not claim the current small `Events` summary is a complete raw-observer record.

These corrections supersede the corresponding broad foreign-W wording and add the definite pre/post callback-data blocker. No source/runtime behavior was executed.
