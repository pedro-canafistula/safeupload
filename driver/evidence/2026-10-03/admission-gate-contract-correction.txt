Admission-gate callback contract correction
Date: 2026-10-03
Reviewer: delegated Luna security/design review

Correction
----------
The earlier late-attach reviews overstated the section-create status finding.
They said the driver could not return STATUS_ACCESS_DENIED for a
policy-denied writable section and treated that as a P1 contract violation.
That categorical conclusion is withdrawn.

Microsoft's generic minifilter pre-operation contract says a filter completing
an operation must set its final NTSTATUS and that the value cannot be
STATUS_PENDING. The FS_FILTER callback contract says a non-success status
causes the request to fail and directs filters to return an accurate error.
The section-specific parameter page says SyncTypeOther cannot fail and
documents STATUS_INSUFFICIENT_RESOURCES when memory is insufficient for
SyncTypeCreateSection; it does not say this is the only allowed failure.
Together, these contracts indicate that STATUS_ACCESS_DENIED is
contract-consistent when it accurately represents a policy refusal on
SyncTypeCreateSection. The section-specific page does not explicitly name that
status, so the exact behavior still needs a disposable target-stack test.
Never fake STATUS_INSUFFICIENT_RESOURCES as a policy decision.

The decisive privacy blocker is the lifetime of already-created writable
views. Windows documents that closing a file or mapping handle succeeds even
while a view remains mapped, and that modified pages can be written lazily
after the view is unmapped or trimmed. A process can write through a live view
pointer without issuing file I/O at the store. Section acquire/release
callbacks describe section creation/release activity; they do not provide a
documented path-scoped rundown of all extant user views across processes.
Therefore a gate that blocks new handles or section creation cannot by itself
prove an older writable view has drained. This is an inference from the
documented contracts, not a claim that Windows could never add such an API.

The same limit crosses destination types. Microsoft documents that
MapViewOfFile works with remote files and that writable mappings on different
computers are not coherent. MUP filters do not control all providers or other
SMB clients, and a general sync-client pause is not a documented universal
handle/view rundown. FSCTL_LOCK_VOLUME is volume-wide, fails while files are
open, flushes cached data, and does not support SMB 3.0. A combined boot-start
minifilter, per-volume rundown, network filter, and broker therefore still
does not prove the full destination DoD unless every relevant process,
redirector, server, and sync provider cooperates in closing or unmapping views.

Smallest useful evidence step
-----------------------------
On a disposable fixed-local-NTFS VHDX, create a writable mapped view before
publishing the proposed gate; keep the view alive while closing the mapping
and file handles; write through the pointer after gate publication; and use an
independent raw-volume observer to detect later pageout. Separately verify
that the candidate's STATUS_ACCESS_DENIED result blocks a newly requested
SyncTypeCreateSection on the target build. These tests can validate callback
behavior and reproduce the old-view lifetime gap; they cannot establish
universal USB, SMB/UNC, or sync-client coverage.

Disposition: preserve the original universal destination scope. No cutover is
approved or claimed; normal staging remains compiled out and taint enforcement
remains active. This note is a correction to the earlier section-status
finding, not a resolution of the old-view, late-attach, policy-transition,
failed-inventory, SMB, USB, or sync-client gaps.
