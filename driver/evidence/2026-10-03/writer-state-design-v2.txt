Writer-state admission design v2 (proposal; supersedes writer-ledger-design-v1.txt where they differ)
Date: 2026-10-03
Status: PROPOSAL. Nothing here is implemented. What is VERIFIED is limited to retained-section-findings.txt.
Owner-approved direction, unchanged: boot-start filter; process taint is not a protection mechanism;
fail closed on the protected scope and open elsewhere; universal destination scope kept; "protection of a file
begins when it has no writer that existed before it entered scope" (Activating state).

1. What changed from v1 and why
--------------------------------
v1 kept a per-file history ("a writable section was created") and had no safe rule to clear it. The adversarial
review (writer-ledger-design-v1-luna-review.txt) called that fatal. Experiments (retained-section-findings.txt)
showed the operating system already maintains the missing state: MmDoesFileHaveUserWritableReferences reads YES
for a stream with a writable section even with no view, and NO promptly (<= ~0.5 s) after the last writable
section or view is gone, including a handle duplicated into another process, cached streams, and a view kept
after its section handle closed; copy-on-write and read-only sections read NO. View creation itself is
invisible to a filter (0 of 8 events) and a writer's file object closes at handle close, so neither events nor
file-object lifetime can serve. v2 therefore prefers OS-maintained STATE to reconstructed HISTORY:

2. Writer-free predicate
------------------------
Free(F) := H(F) = 0  AND  S(F) = NO  AND  C(F) = 0  AND  T(F) = 0, for a stream F (volume + FileId + stream name),
evaluated only while admission of NEW writers to F is closed, so it is monotone and terminates.
  H(F) open file objects holding write access. Event-sourced: +1 at a successful create that granted
       write/append/delete-on-close rights, -1 at that file object's IRP_MJ_CLEANUP (observed immediate at last
       handle close). Complete only if the filter saw every create: boot start, attach at mount.
  S(F) MmDoesFileHaveUserWritableReferences on a valid SECTION_OBJECT_POINTERS of F. Queried, not remembered.
       Called off the I/O path (worker, PASSIVE_LEVEL) through an attribute-only open by file ID below the instance
       (the explicit-probe mechanism exercised in all runs). VERIFIED behavior on one build only (see 7).
  C(F) writable CreateSections admitted (acquire) but not yet completed (release). Closes the race between an
       S(F)=NO sample and a section creation already past the gate. Pairing rules and teardown loss are UNVERIFIED.
  T(F) transacted (TxF) writers not yet committed or rolled back. OPEN (see 6).

3. Per-file states and transitions
----------------------------------
Unscoped -> (policy adds F's scope) -> Activating -> (Free(F) and cached data flushed) -> Protected.
Activating and Protected refuse NEW write opens and NEW writable sections for F (accurate failure status; never a
fake resource error); the old writers finish under the rights they were granted. The agent is told, best effort,
which file is held in Activating and by which process. No timeout may promote a file. Per-file denial of service by
a long-lived old writer is accepted and bounded to that file.

4. Policy changes without scans
-------------------------------
Pending policy is published; every admission path (create, write-open, section, rename/link, set-information,
delete, selected FSCTLs, publication) takes one admission epoch that selects current-or-pending atomically and is
held to lower completion; the epoch is drained before the pending policy becomes current. New opens and sections
in an added scope are therefore staged and inspected from that instant. Pre-existing files are classified from a
bounded REGISTRY of streams with H > 0 or a writable section created since they were last proven Free; a stream
absent from the registry has no writer by construction. The registry is pruned by polling S(F) off the I/O path.
No file-system enumeration of the scope is needed, so the over-cap and failed-inventory states of the scan design
disappear. Registry overflow marks the volume Untrusted (fail closed for scopes on it), never silently drops.

5. Abnormal conditions
----------------------
Untrusted volume: the filter attached after user processes could have written (late or manual attach, or a
completeness check failed). Protected scopes on it fail closed for new writes and mappings until reboot. No taint
fallback, no effect outside the scope. Start-up self-test (canary): create a retained writable section on a
temporary file and require S = YES, release it and require NO; on failure do not enable staging (Untrusted).
Re-run on every volume attach. This turns "behavior observed on build X" into a runtime-checked precondition.

6. Review findings: disposition
-------------------------------
  P0 section lifetime ........ RESOLVED on the tested build by S(F) (observed, not documented); canary + per-build
                               qualification matrix required.
  P0 raw disk writes ......... ACCEPTED LIMITATION: physical-drive writes bypass the file-system stack. Refuse
                               write opens of volume devices on volumes with protected scopes; state the
                               administrator-level boundary in the threat model.
  P1 TxF ..................... OPEN. Fail closed: refuse transacted write opens in scope; pre-existing transacted
                               writers need enlistment-based tracking or the file stays Activating. Must be designed.
  P1 policy vs mutation ...... ADDRESSED in design (epoch, section 4); linearization argument and tests still to do.
  P1 stream identity ......... OPEN: volume+FileId+stream identity and alias handling (hard links, rename, reparse,
                               short names, ADS) specified only for registry streams; tests required.
  P1 Untrusted late attach ... PARTLY IMPROVED: S(F) can be queried on demand for any file, but a paging write of
                               an unclassified stream still cannot be attributed on the I/O path. Keep Untrusted.
  P1 boot start .............. UNCHANGED from v1 plus: durable boot policy before the agent, fail-closed on scope
                               without blocking unrelated paths, ErrorControl, resume from hibernation/fast startup.
  P1 SMB/sync ................ UNCHANGED: local-writer guarantee only; remote writers and other computers are
                               outside; MUP/redirector coverage to be qualified.
  P1 Activating DoS .......... ACCEPTED, per file.
  P2 failed creates, fast I/O, context reuse, EFS, VSS, copy-on-write, image sections: copy-on-write and
     read-only sections VERIFIED not to stall (read NO); the rest remain to be qualified.

7. Unverified premises and next experiments (each observe-only first, checkpointed, independent restoration)

  X2  H(F): corpus of handle duplication/inheritance, failed/cancelled/reparsed creates, delete-on-close,

  X3  C(F): acquire/release pairing, including failed section creation and instance teardown.
