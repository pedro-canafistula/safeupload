Scope
-----
Read-only Luna security rereview of the policy-rejection-only harness, including
the exact SetPolicy failure signature, package/hash binding, extraction ACLs,
path/reparse validation, launch and cleanup ordering, and Windows PowerShell
5.1/.NET Framework API compatibility by source inspection.

Result
------
The exact ERROR_NOT_SUPPORTED exception and both FilterPort.SetPolicy and
MinifilterInterceptor.TryPushPolicy stack-frame checks are appropriately
specific. The package is opened once with FileShare.Read; the script hashes
that held stream and passes the same stream to ZipArchive. The service tree is
created under CommonApplicationData with Administrators/SYSTEM ACLs on the
root, every subdirectory, and every file. Its ancestors, owners, mutation
grants, reparse points, and exact staging ACLs are checked before extraction,
before each service launch, and before recursive cleanup. Unverified cleanup
retains the tree and reports failure.

The ancestor check permits specific create-only rights above CommonApplicationData
to avoid rejecting the likely stock Windows C:\ root create-file/create-folder
ACE, while requiring trusted owners and rejecting mutation grants from other
principals. CommonApplicationData itself rejects untrusted child-creation rights.
The check conservatively screens allow ACEs; it does not simulate Windows
effective token access and may reject an allow ACE neutralized by a deny ACE.
That behavior is fail-closed.

Final rereview found no remaining source-level blocker. The reviewer found the
PowerShell 5.1/.NET Framework API usage compatible by inspection, including the
Directory.CreateDirectory(String, DirectorySecurity) and FileStream constructor
that apply security at creation. No parser, WDK build, or VM execution was run.
This review is not runtime or full-scope privacy evidence. The removable and
network policy flags remain unchanged, and the broader destination-scope gate
remains open.
