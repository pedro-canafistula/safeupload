Scope
-----

The feature-gated Agent API sends one bounded raw status control over the
already service-owned FilterPort. Its only command values are ActivatingStatus
(19), EpochStatus (20), and VolumeObserve (23). It adds no connection path and
no reset, trust, mutation, path-probe, or legacy deadline control. A successful
FilterSendMessage receipt retains exact input and returned bytes, HRESULT,
returned length, UTC times, and Stopwatch timestamps. Stopwatch values are ticks
whose scale is Stopwatch.Frequency; a consumer persisting the ticks must persist
that frequency too. Native failure returns an empty reply byte array. Malformed
or short successful output remains raw but is explicitly marked invalid. If a
successful call reports more bytes than the fixed output capacity, the bounded
buffer bytes are retained and marked truncated; no wire decoding occurs.

The managed feature mirrors verify the 16-byte control and the status payload
sizes/selected offsets before FilterPort connects. The output buffer is limited
to the exact reply size for the selected command: 36,136 bytes for Control 19,
32 bytes for Control 20, and 6,672 bytes for Control 23. Synchronous send calls
share a per-port gate and Dispose rejects new sends and drains accepted sends
before closing the handle. The blocking FilterGetMessage receive path does not
use this gate.

Corrected Control 19 producer bound
-----------------------------------

The older design note
`live-admission-evidence-rpc-design.txt` pairs a 4,096-entry ceiling and 128
pages with 40 MiB per-capture / 280 MiB per-seven-hook-run raw-data caps.
Current producer constants do not support that ceiling:

* `driver/SafeUpload.Minifilter/Protocol.h:292` sets
  `SAFEUPLOAD_WRITER_REGISTRY_TOTAL_LIMIT` to 4,096.
* `Protocol.h:294` defines the compact limit as four times the total limit,
  or 16,384.
* `Protocol.h:295` defines `SAFEUPLOAD_WRITER_REGISTRY_ALL_LIMIT` as the sum,
  or 20,480.
* `driver/SafeUpload.Minifilter/StageWriters.c:5844` rejects only a start index
  greater than `SAFEUPLOAD_WRITER_REGISTRY_ALL_LIMIT`, so 20,480 is inclusive.

With 32 entries per page, this permits 640 pages, not 128. At 36,136 returned
bytes per page, a full pass is 23,127,040 bytes. Five full snapshot attempts
would return 115,635,200 bytes (about 110.3 MiB) for one capture; seven such
captures would return 809,446,400 bytes (about 772 MiB). Therefore the old raw
data caps need a deliberate design-owner decision: raise/recalculate them, or
keep them as lower operational caps and report any capture that reaches them as
incomplete. The FilterPort API itself does not page-walk or buffer a capture.
It accepts Control 19 start indexes only through 20,480 and sends one page per
call.
