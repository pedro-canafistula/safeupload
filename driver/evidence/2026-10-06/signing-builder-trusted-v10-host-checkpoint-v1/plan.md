# Trusted V10 healthy-parent host checkpoint (prepared; not executed)

This separate package prepares a system-disk checkpoint for the V10 trusted signer on builder UUID `C6440689-D11C-4C63-A463-F3722B7DDB69`. It uses the verified healthy retry2 disk as both the current disk and immediate parent, and proposes one fresh qcow2 child at the exact path pinned by the frozen V10 plan. The failed retry1 disk remains retained and must be absent from the current and new child backing chains.

The package binds the frozen V10 plan and source manifest, the frozen V13 verifier manifest, V13's actual PowerShell 5.1 parser/fixture/read-only-baseline PASS readout and all of its raw evidence pins, the verified retry2 host and guest baseline, and the captured trusted-V10 host preflight. The initial domain XML is copied byte-for-byte from that actual inactive XML. The proposed child XML is generated by replacing exactly the one `vda` source path; a static XML check confirms no other input XML bytes changed. The volume definition retains qcow2 format and requires child mode `0600`, owner UID `958`, and group GID `958`.

`execute-checkpoint.py` refuses to call libvirt until it verifies the exact execution-manifest hash, every local and external input pin, the frozen V10 source manifest, all 42 rows in the V13 source manifest, V13's root readout fields, the fixture marker/empty fixture stderr, the successful retry2 lineage, the captured current host preflight, and the exact XML/volume relationship. Its `preflight` phase performs fresh read-only checks: exact UUID and running vda parent, unchanged persistent/live configuration outside the permitted vda source, no domain or vda block job, exact parent device/inode/mode/UID/GID, absence of the new child, and a live QMP backing chain through Recovery3 that excludes retry1. It also checks that another libvirt domain does not use the healthy parent.

The `shutdown` phase repeats those live checks before requesting graceful shutdown. The `create-start` phase requires the domain to be off and the child absent; it captures a fresh full parent stat, creates only the new child volume, verifies the child and volume permissions/backing path, defines the exact child XML, rechecks parent immutability, and starts the domain. The `verify-host` phase requires QMP to show the child immediately over retry2, retry1 absent from the full chain, retry2 uniquely read-only, and the parent's full stat unchanged with mode/ownership still `0600:958:958`. An explicit `restore-definition-before-start` phase can restore the initial retry2 definition only while the VM remains shut off and before the child has started; it never deletes the child or changes parent permissions.

The package makes no firmware, TPM, NVRAM, or RAM checkpoint assertion and no full-VM rollback claim. It performs no certificate-store, key, trust, artifact-signing, build, or driver-install operation. Host phases have not been run during authoring. Root must review this exact package, and the independent Bridge review must pass, before any mutating phase is invoked. After host verification, root must separately rerun the pinned read-only V13 baseline on the cold child and capture its readout before considering subsequent work.
