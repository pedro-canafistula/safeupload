Security findings
-----------------

The feature is behind the explicit `SafeUploadAdmissionEvidence=true`
property and `SAFEUPLOAD_ADMISSION_EVIDENCE` compilation symbol. The normal
configuration does not set that property. Feature types, service registration,
FilterPort sender interface, and interceptor binding are conditionally
compiled. Binding occurs only after policy acceptance, only in the staging
path, and uses the already-owned FilterPort. The endpoint does not open a
second minifilter connection or modify policy.

The server requires a LocalSystem process to bind. It creates one first
instance of a byte-mode local named pipe, rejects remote clients, applies an
explicit SYSTEM/Administrators DACL, and checks the client's token after the
bounded request read. Requests are length-bounded before allocation, use
strict identity parsing, and are limited to live hooks 2 through 7. The sender
allowlist contains Controls 19, 20, and 23. It excludes mutating Control 13
and the path-based Control 17. Driver dispatch for Control 23 disables the
legacy canary-deadline mutator.

The reply path copies raw arrays defensively and hashes the bytes actually
captured before parsing. It records HRESULT, reply availability, returned
length availability, validation errors, timestamps, request identity, and
binding identity. Failed native calls do not expose the output buffer as a
reply. Frame writes are bounded and cancellable; the run ledger reserves
requests before sampling and makes incomplete captures terminal per target.
Target and volume matches remain independent `Absent`/`Unique`/`Ambiguous`
assessments, and selected activating-entry fields exist only for a unique
match. Every summary sets `ReadyClaim=false`; the endpoint does not define a
privacy pass.

The frozen capture client requires an already-open target handle and a service
process identity tracked by its caller. It rechecks the target volume GUID,
volume serial, and FILE_ID_INFO tuple before send and after capture; it verifies
the named-pipe server PID and rechecks the tracked process birth time, image
path, image SHA-256, and image file identity. It sends exactly one request for
hooks 2 through 7, rejects hook 1, never retries or reconnects, and preserves
request-delivery ambiguity after an attempted write.

Raw request and response bytes and the JSON receipt are created exclusively
beneath a unique direct child of canonical Program Files on fixed NTFS. The
helper rejects reparse ancestors, validates trusted ancestor owners and
mutation rights, creates files with CREATE_NEW and no sharing, and verifies a
protected DACL containing only SYSTEM and Builtin Administrators full control.
It rechecks the directory and file ACL/path conditions after capture, flushes
files durably, and retains raw bytes locally without printing frame contents to
console or general logs. Raw Control 19 can contain file names and opener PIDs;
those bytes therefore remain sensitive local evidence. The helper does not
delete artifacts automatically.

The D transport uses an asynchronous local-pipe request write under the
monotonic capture deadline. On timeout it cancels, disposes the pipe, records
delivery as indeterminate, and observes any later task fault without waiting
past the production deadline. Reads poll PeekNamedPipe at most every 10 ms,
read no more than bytes already available, and persist/hash each returned
chunk before parsing. Errors 109 and 233 are treated as terminal pipe closure.
The local self-check covers roundtrip, unsupported ReadTimeout/WriteTimeout
setters, delayed fragments with early EOF and partial-byte retention, a silent
peer deadline, and a backpressured write whose disposed pipe leaves an
indeterminate delivery state. The self-check's prior C run does not qualify
revision D; D's exact-host PowerShell 5.1 run remains pending.

Microsoft .NET Framework referencesource confirms the transport choice:
`Stream.WriteAsync` dispatches through BeginWrite/EndWrite, and asynchronous
PipeStream uses overlapped pipe I/O. Cancellation is checked before dispatch;
disposing the pipe is needed to abort an in-flight write. PipeStream treats
both ERROR_BROKEN_PIPE (109) and ERROR_PIPE_NOT_CONNECTED (233) as EOF. This
source comparison supports the design but does not replace the pending D
self-check. See [Stream.cs](https://github.com/microsoft/referencesource/blob/main/mscorlib/system/io/stream.cs)
and [PipeStream.cs](https://github.com/microsoft/referencesource/blob/main/System.Core/System/IO/Pipes/PipeStream.cs),
accessed 2026-10-06.

Limits remain material. Cancellation cannot interrupt synchronous
`FilterSendMessage`; a blocked native call can overrun the capture deadline
until the next asynchronous output boundary. Control 23 covers currently
attached instances, and its GUID observation is not atomically correlated
with Control 19's volume-serial/FileID match. The interceptor still publishes
`ProtectionActive=true` and the ServiceReady event after accepted policy push;
that existing UI/service readiness mismatch is outside this endpoint change.
None of these observations closes either byte-privacy gate or qualifies USB,
UNC/SMB, sync-client, crash/recovery, Verifier, stress, or latency behavior.

Capture, build, and prior-run provenance
----------------------------------------

The reviewed source-preparation path snapshots tracked `agente` project files
and exact-hash-allowlisted new C# files. It rejects unsafe/case-colliding
paths, symlink traversal, hardlinked inputs, non-regular files, and changes
between its two reads. It checks HEAD and the project inventory again, builds
a deterministic stored archive and SHA-256 manifest, and records the capture
tool hashes. Local preparation reports zero network operations. The driver
then verifies the caller-held provenance before delivery.

The matrix script verifies the builder hostname and UUID; its orchestrator
also checks the recorded network adapter. SSH requires strict host-key
checking. The uploaded PowerShell build tool is hash-checked on the builder.
It checks the manifest and archive hashes, rejects duplicate or unexpected
archive entries, verifies all extracted file hashes, and builds each of four
fresh normal/feature Debug/Release profile trees. It uses warnings-as-errors,
requires complete all-passing TRX counters, rechecks inputs after builds, and
only publishes Release outputs. It does not install or start the service.
