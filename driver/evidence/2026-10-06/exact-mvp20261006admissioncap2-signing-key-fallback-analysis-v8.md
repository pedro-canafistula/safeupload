## V8 guard and challenge

The key ACL guard requires a protected, canonical DACL with exactly three ordered explicit non-inheritable Allow ACEs: Creator Owner, SYSTEM, then BUILTIN\Administrators. Each ACE must have the captured `FileSystemRights.FullControl` value (`2032127`), with no other mask accepted. V8 does not normalize or write the ACL. The typed owner SID must equal `S-1-5-32-544`. It captures the typed group SID, raw owner/group display names, full SDDL, DACL protection/canonicality, and ordered raw ACE rows, then requires exact parity at every later checkpoint. No `Set-Acl` call or ACL-writing API is present.

The creator pins the exact builder (`DESKTOP-O1LP5DG`, UUID `C6440689-D11C-4C63-A463-F3722B7DDB69`, vika SID `S-1-5-21-316478115-1595729549-2803163825-1001`) and requires enabled Administrators membership in the exact mint process. It creates a 3072-bit RSA code-signing certificate in `LocalMachine\My` using Microsoft Software KSP, `KeyExportPolicy=NonExportable`, DigitalSignature-only key usage, exactly one code-signing EKU, CA=false, and 90-day validity. It verifies the original certificate and PFX/CER hashes remain unchanged. Before public CER export, it validates the complete six-store thumbprint inventories and ACL, performs a fresh random in-memory sign/verify challenge, checks the same ACL again, then exports only a public CER and writes V8 public metadata. It never exports private key material. A failure is preserved with the original exception, before/failure ACL snapshots, public store inventories, and matching certificate metadata; do not use a key from a failed attempt.

After the restricted key-bearing system-disk checkpoint is created, host-verified, cold-booted, and independently inventoried, the V8 cold-challenge script repeats the pinned builder and enabled-Administrator checks. It pins the creation-metadata and public CER hashes/thumbprint, verifies the original certificate and PFX/CER hashes, requires all six certificate-store inventories to equal the mint evidence, validates the same machine CNG container and nonexportable RSA-3072 key, and compares the current descriptor against both mint snapshots. It signs and verifies another fresh challenge in memory, then repeats ACL/store checks. It emits no challenge or signature bytes and performs no trust, source build, or artifact signing.

The checkpoint claim remains limited to the builder system disk and signer state. It is not a full VM, firmware, TPM, or RAM backup. The existing NVRAM is reused; `testsigning` and firmware configuration remain unchanged. The parent image must remain byte-pinned and read-only, the child must retain exact host ownership/mode and QMP backing-chain evidence, and root must verify the original baseline twice before mint. A successful key challenge does not close the separate VM qualification/restoration gate.
