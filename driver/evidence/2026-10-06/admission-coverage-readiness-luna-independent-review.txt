Blocking finding: tracking Unknown can race the Control 24 snapshot
-------------------------------------------------------------------
Severity: readiness correctness blocker (stale receipt can say Ready).

`StageAdmissionCoverageReadInstance` copies `WritersUntracked` and
`RegistryUnknownReasons` into its instance record (StageAdmission.c 431-438). The
writer census later samples global Unknown and returns a registry sequence pair
(StageWriters.c 6095-6125). Control 24's final stable predicate compares that
returned pair at StageAdmission.c 714-730, but does not take a new registry
sequence/global-Unknown sample after the census.

Meanwhile `StageRegistryMarkUnknownAt` mutates the global and instance
unknown-reason state, `WritersUntracked`, and/or `WriterGlobalUnknown` at
StageWriters.c 795-839 without advancing `RegistryChangeSequence` or bracketing
`AdmissionCoverageSequence`. The deferred worker independently writes the
instance unknown fields at StageWriters.c 5013-5049 without either sequence
change. Thus, if a tracking loss is published after its instance record or the
writer census has been sampled but before finalization, the receipt can retain
zero unknown values and equal sequence endpoints, then set the Stable and Ready
state. The service can publish that stale Ready decision and announce its
one-shot Ready event. This is not a demonstrated byte leak: the protected create
and writable-section admission helpers recheck the current instance/global gate
and deny matching operations when they observe Unknown. It is a false readiness
claim, contrary to the requirement that uncertain coverage cannot be Ready.

Required repair: version every per-instance and global tracking-loss publication,
including deferred/high-IRQL paths, with a sequence visible to Control 24; take a
post-census sequence and global-Unknown sample at finalization so any overlapping
loss yields Pending/Degraded. Preserve IRQL-safe publication and the current
fail-closed create/section behavior. Add a targeted interleave test for an
instance Unknown and a global Unknown transition between instance census,
writer census, and receipt finalization.

Contract gap: unknown epoch bits are accepted
---------------------------------------------
The defined epoch bits are Pending `0x1`, FailedClosed `0x2`, and Finalizing
`0x4`. Native finalization at StageAdmission.c 739-748 only tests those known
bits. The managed evaluator at AdmissionCoverage.cs 213-216 also tests only
those known bits. A receipt with the same unknown epoch bit in both start/end
fields (for example `EpochFlags == EpochFlagsEnd == 0x8`) can therefore pass
those checks and proceed toward Ready. The managed evaluator rejects unknown
receipt flags and policy flags, so omission of an epoch mask is inconsistent
with its other strict parsing and with the readiness design's unknown-flag rule.

Required repair: treat `(EpochFlags & ~0x7) != 0` as non-Ready in the native and
managed paths, and add a managed evaluator case with unknown epoch bit `0x8`.

Bounded passes observed in source
---------------------------------
- Control 24 checks policy generation/flags, boot state, policy-scope sequence,
  epoch generation/flags, topology and admission-coverage sequences, complete
  accepted scopes, unique prefix resolution, supported-volume/canary/trust gates,
  future-mount readiness, and activating writer-entry counts. Managed evaluation
  binds the first observed native generation to the accepted scope set and
  requires complete/stable/future-gate/registry-complete receipt flags; query
  failure maps to Degraded. The service publishes Pending before the polling
  loop; policy startup applies the candidate, commits/removes durable pending
  scopes, and sends the final policy acknowledgement before binding the accepted
  coverage set.
- Protected create and unowned writable-section gates run before the
  authenticated-service fast path. Unresolvable target names widen to a possible
  matching volume rather than becoming an outside-scope allow. The gate requires
  fixed NTFS, stable volume identity, all canary checks and cleanup success,
  sticky passed trust, and no per-instance or global writer Unknown. Removable
  and network instances remain unsupported/Degraded until their own gate exists.
- Canary trust is granted/revoked only for `NEWLY_MOUNTED` instances in
  StageAdmission.c 942-962. Preserve that condition: a passing late-attach
  diagnostic does not make an already-attached Degraded instance Ready.
- The UI labels Ready as destination admission gates ready, and renders Pending
  and Degraded separately. This status is an admission-readiness claim only.
