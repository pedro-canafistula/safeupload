# V10 trusted signer checkpoint package — review only

This package proposes a fresh, limited disk checkpoint of the healthy V8 signer after the successful V10 LocalMachine Root trust operation and READY4 artifact-sign proof. It does not use the failed retry1 disk or the earlier V9 trust-failure recovery guard. No VM, key, trust, signing, or build operation has been run while preparing it.

The proposed read-only parent is `/var/lib/libvirt/images/win10-clean.safeupload-signer-key-bearing-v8-retry2-20261006.qcow2`. It is the current healthy disk whose V10 trust receipt, independent trust readout, and successful artifact-sign proof are pinned in `inputs.json`. The new child name is `/var/lib/libvirt/images/win10-clean.safeupload-signer-trusted-v10-20261006.qcow2`; it must not already exist when root performs the later host preflight. The expected immediate parent of the existing signer disk is the independently recorded Recovery3 image. The retained failed retry1 disk is explicitly excluded from the new child chain.

The lineage starts from the verified original V8 key-bearing checkpoint and its cold-boot verification, then the independently restored healthy retry2 sibling, V10 machine-root trust, and the exact signed-copy proof. It does not treat V9 failure-capture evidence as a source of trusted state. The V10 trust receipt proves only the approved LocalMachine Root insertion with the expected merged CurrentUser Root view. Its independent readout confirms the other stores, key ACL, original files/certificate, and testsigning state. The signed proof then records SignTool exit 0, `AuthenticodeStatus=Valid`, the exact V8 thumbprint, unchanged unsigned bytes, no signer-side trust change, and the same six-store inventory.

The independent post-sign readout is complete and pinned: the raw two-record JSONL is `driver/evidence/2026-10-06/signing-artifact-proof-v10-post-sign-independent.stdout.json` (SHA-256 `abbd29d85a527798722bf7c48432fff6165825651bf5510a32dc9e34b26a0282`), its stderr capture is `driver/evidence/2026-10-06/signing-artifact-proof-v10-post-sign-independent.stderr.txt` (SHA-256 `a3639af5e23464fc391dae127fd5493f02c8178068a35866d9c7fdd35dcd623f`), and its root exit/readout record is `driver/evidence/2026-10-06/signing-artifact-proof-v10-root-readout.json` (SHA-256 `155ce22a721fb17b2200bc788c60d63fb06fcda5786720550cda1fc75f7820e5`). The root record reports artifact workflow exit 0 and independent remote exit 0, pins the raw JSONL, stderr, and original root run, and confirms the exact signed artifact and no state mutation. The cold-baseline verifier requires all three files, checks their exact hashes and key fields, and requires the post-sign record to agree with the five-file public proof package. The readiness reviewer must approve this exact frozen package. The host preflight must independently capture the live domain XML, UUID, disk source, state, jobs, target-child absence, parent stat, and existing backing chain. Stop on any mismatch. The package intentionally remains `ReadyForExecution=false` until review and live-state gates are satisfied.

The future checkpoint operation is limited to the `win10` system disk and signing state. Gracefully stop only the pinned VM; preserve its current disk as parent without chmod/chown or in-place edits; create a fresh qcow2 child with that exact parent; change only the VM's `vda` source; verify the child is mode `0600`, owner/group `958`, and the parent opens read-only in QMP. The active chain must be child → trusted retry2 parent → Recovery3, and must exclude retry1. Verify the parent's device/inode/size/mtime/mode/UID/GID before and after. Do not claim firmware, TPM, RAM, or shared NVRAM was checkpointed. Never remove either disk or automatically roll back after a failure; preserve all artifacts and stop for review.

Stage the exact pinned trust readout, cold-challenge readout, post-sign JSONL, post-sign stderr capture, post-sign root readout, and five-file public proof directory as read-only baseline inputs on the guest. Keep the four readout files separate from the exact five-file public proof directory. Run the package's read-only `baseline-check-v10.ps1` on the proposed child after its cold start, passing those explicit paths. It verifies the exact six-store state against the V10 receipt and mint baseline, all independent readout hashes and exit results, the public proof bundle and signature, original certificate/files, testsigning=No, no build actors, and the exact ordered machine-key ACL against both mint snapshots and V10 trust snapshots. Capture a second identical read-only baseline after a clean guest restart before any build. A second baseline must match the first on identity, stores, signer, file hashes, key ACL, and testsigning; only timestamps and process observations may differ. The prior retry2 guest readouts showed the guest `AfterBoot` timestamp earlier than `BeforeBoot`; preserve that clock/NTP caveat and infer no ordering from guest wall-clock values. Do not change guest time/NTP to make timestamps appear monotonic.

The existing V8 cold-challenge script is deliberately not reused for a trusted-state challenge: it requires all stores to equal the pre-trust mint inventory and would reject the approved Root delta. A new in-memory trusted-state challenge is not required by this package because the post-trust artifact proof already records successful use of the exact machine key. If the independent reviewer requires a fresh cold-boot challenge, prepare and review a separate V10-specific challenge source whose six-store baseline is the exact V10 receipt; do not edit or run the frozen V8 challenge.

No build or driver-install authorization is implied by this checkpoint plan. It establishes a reviewable, preserved signer baseline only. The signed artifact remains an uninstalled public output until separately approved.
