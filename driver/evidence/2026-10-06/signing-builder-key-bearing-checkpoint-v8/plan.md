# V8 key-bearing cold checkpoint (prepared; not executed)

This package is a guarded system-disk/signing-state checkpoint for builder UUID `C6440689-D11C-4C63-A463-F3722B7DDB69`. It uses the previously validated Recovery3 disk as both initial and immediate parent, and creates one restricted qcow2 child for a cold boot. The helper preserves the V7 safety checks: exact UUID and normalized domain configuration, graceful shutdown before volume creation, exact parent-stat checks, child owner/mode checks, explicit definition restoration to Recovery3 before any pre-start failure recovery, and QMP confirmation that the immediate qcow2 backing node is read-only.

The key-bearing package records no firmware, TPM, or RAM checkpoint and makes no full-VM rollback claim. It performs no trust import and no artifact build/sign. The separate pinned V8 cold-challenge script may be run by root only after host checkpoint verification and two exact guest store/baseline reads; it signs and verifies only a random in-memory challenge and emits no private material or signature bytes. Stage the pinned V8 challenge script and its pinned helper beside each other in the existing guest evidence directory, verify both guest-side hashes, then invoke the command in `cold-key-challenge-command.txt`. The guest baseline readout records boot time and requires the exact vika SID with enabled Administrators membership.

The metadata file, actual public CER, creator and challenge sources, root readout, and independent split public rereads are pinned in `inputs.json`; actual CER bytes match the V8 mint evidence hash. The execute helper checks `ReadyForExecution` before any libvirt command. `ReadyForExecution` records that the package inputs are complete; root retains control of every checkpoint phase and the separate cold challenge. No checkpoint phase was run while authoring this package.
