Repair review
-------------
1. The false-Ready path is closed in the current source. Tracking-loss
   publication now brackets the affected entry, instance, global, alias-probe,
   canary-timeout, and stream-context Unknown transitions with the admission
   coverage sequence/in-flight counter and advances `RegistryChangeSequence`.
   Deferred high-IRQL publication takes an additional coverage ticket before
   queueing; the worker keeps it until per-instance Unknown is visible and
   advances the registry sequence, or widens to global Unknown if the target or
   context is gone. Queue failure widens synchronously while the caller's
   coverage ticket remains held. Control 24 samples the current registry
   sequence and global Unknown after the writer census and requires that sample
   to be stable and equal the census endpoints/value, in addition to equal
   coverage endpoints and zero setup, teardown, and coverage in-flight counts.
   An overlapping loss therefore cannot produce a stable Ready receipt.

   The managed contract tests cover a changed registry endpoint, a nonzero
   coverage-change ticket, and global Unknown. They test receipt evaluation;
   they do not schedule a deterministic kernel interleave between census and
   finalize. I found no existing native diagnostic hook for that schedule. The
   code-level close is supported by the explicit version/ticket protocol, but
   no native interleave execution is claimed here.

2. Native finalization rejects every epoch flag bit outside Pending `0x1`,
   FailedClosed `0x2`, and Finalizing `0x4`. Managed evaluation applies the
   same known-bit mask and maps unknown bits to Degraded. The managed test uses
   `EpochFlags == EpochFlagsEnd == 0x8` and expects Degraded.

   Final compiler-adapter re-review: `StageAdmission.c` now uses a `UINT32`
   local for the current global-Unknown output passed by address to the
   `PUINT32` API. The type matches without a cast, and the post-census current
   registry-sequence/global-Unknown equality checks and final coverage-ticket
   stability predicate remain present. This is a compile-type correction only;
   no build result is asserted by this review.

No readiness trust boundary was relaxed in this repair. The create and
