# V13 amendment: inventory adapters and post-sign store normalization

This is a separate, read-only verifier amendment. Frozen V10, V11, and V12 packages remain unchanged. V13 is not yet approved for execution; its pure PowerShell 5.1 fixture must pass on the builder before the parent read-only baseline is rerun.

The retained V12 baseline failure is `Store inventory missing Cert:\CurrentUser\My` at `Get-Thumbs` line 184. In V12, the reached comparison is the live `Get-StoreInventory` result against the V10 trust receipt (`$stores = Get-StoreInventory`, then `Assert-InventoryEqual $stores $trust.AfterAllStoreThumbprints`). `Get-StoreInventory` returns `[ordered]@{}`, which is an `OrderedDictionary`; V12 `Get-Thumbs` searched `$Inventory.PSObject.Properties[$Store]`. The actual failure readout records `HostCheckpointAttempted=false`, `TrustModified=false`, and `ArtifactSigningAttempted=false`. This observed failure concerns the live dictionary lookup. The post-sign JSONL record is schema-checked in V12 but is not an input to that failed `Get-Thumbs` call.

V13 adds exact ordinal inventory-key enumeration/value lookup for both `IDictionary` instances such as `[ordered]@{}` and property-backed JSON `PSCustomObject` values. The inventory schema check requires the exact expected key set and count, rejects missing, extra, duplicate, or differently-cased keys, and requires every store value to be an array of 40-hex-character thumbprints. `Assert-InventoryEqual` applies that strict six-store schema to both operands before comparing sorted uppercase thumbprints. This keeps the live `Get-StoreInventory` comparison on the same six `Cert:\` paths while making the actual OrderedDictionary representation readable.

The pinned post-sign JSONL record uses six unprefixed names (`CurrentUser\My`, `CurrentUser\Root`, `CurrentUser\TrustedPublisher`, and their `LocalMachine\...` counterparts). V13 applies a fixed six-entry mapping from those exact names to the corresponding `Cert:\` paths, validates both source and normalized key sets, and compares the normalized post-sign inventories to the pinned V10 trust receipt. This is an explicit independent consistency check; it is not described as the cause of the captured V12 failure.

`inventory-ps51-fixture-v13.ps1` is designed to run only against the pinned V13 source and pinned metadata, trust-receipt, and post-sign JSONL files. It parses the baseline with the PowerShell AST and dot-sources the exact extracted definitions of the inventory functions under test. It exercises the pinned JSON `PSCustomObject` inventories, the actual post-sign short-key object, and a memory-only `[ordered]@{}` shaped like `Get-StoreInventory`. It also checks that missing/extra keys, wrong post-sign key names, scalar values, and a changed but well-formed thumbprint fail at the expected comparison. It does not query certificate stores, access the signing key, write files, import trust, sign, build, or interact with a VM.
