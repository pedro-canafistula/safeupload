# Trusted V10 healthy-parent host checkpoint V2 (prepared; not executed)

This versioned package proposes a limited system-disk checkpoint from the verified healthy V8 retry2 parent to the fresh trusted-V10 child. It preserves the frozen V1 package and adds no certificate, trust, key, artifact-signing, build, or driver-install action. Host execution remains disabled pending root and independent Bridge review.

The package validates the frozen V10 `inputs.json` as JSON and reads its `DiskScope`; it pins the V10 Markdown `plan.md` separately by SHA-256 and verifies its required scope statements as text. It never parses the Markdown plan as JSON. The helper checks that parent, child, Recovery3 lineage, excluded retry1 path, child mode/UID/GID, parent QMP read-only requirement, and system-disk-only/no-full-VM-rollback scope agree with the frozen V10 JSON inputs.

The domain configuration uses two different comparisons. The persistent/inactive definition must exactly match the pinned inactive XML, and the prepared child definition must differ by one exact text replacement of the `vda` source path. After definition, the complete persistent XML is compared with that prepared child definition. For live XML, V2 pins the captured live preflight XML and compares fresh live dumps to it after a narrow, explicit runtime projection: positive runtime ID, numeric source indexes, UUID network portid, interface target `vnetN`, `/dev/pts/N` serial/console source and tty, connected/disconnected on the exact SPICE channel, and informational backingStore nodes are validated then omitted. Aliases, bridge `virbr0`, resource partition, DAC labels, graphics, and every other field remain compared. V2 does not compare the raw live dump to inactive XML. The live `vda` source is asserted separately at every phase, and after cold start QMP must show `vda` on the trusted child with the exact full QMP backing chain obtained before shutdown prefixed by the new child (child → retry2 → Recovery3 → the pinned remaining ancestors), with retry1 excluded.

Before shutdown, the helper repeats fresh UUID/state/source checks, requires no domain job and an empty QMP `query-block-jobs` result, verifies the expected healthy parent stat/ownership, confirms the target child is absent, and checks no other domain uses retry2. It keeps the healthy parent at `0600:958:958`, captures a fresh parent stat after graceful shutdown, creates one qcow2 child, verifies its permissions/backing path, defines only the exact prepared child XML, and starts the domain. Before issuing `virsh start`, it durably writes a start-attempt marker; the definition-restoration phase refuses to run if that marker exists, including when a start command failed or its result was interrupted. Restoration first requires the full inactive definition to match the prepared child XML and preserves both disks.

The package does not assert firmware, TPM, RAM, or shared NVRAM checkpointing and does not claim full VM rollback. Root must separately rerun the pinned read-only V13 baseline twice on the cold child before considering further work. No host or VM phase has been invoked while preparing V2.

Every phase except read-only `preflight` requires an external review attestation whose supplied SHA-256 is checked at invocation time. The attestation must report `INDEPENDENT_REVIEW_PASS`, exact helper and execution-pins hashes, and both root and Bridge verdicts as `PASS`; it is not source-hash pinned into this package, avoiding a circular manifest.
