## V3 signer lifecycle verdict

**The V3 create, trust-add, and trust-rollback scripts pass static review with execution preconditions. No key, certificate, trust entry, signer pin, build, or artifact was changed during this review.**

The create script enumerates all six logical `CurrentUser`/`LocalMachine` `My`, `Root`, and `TrustedPublisher` stores with terminating errors before mint and after mint. It checks that the only post-mint store delta is the new certificate in `LocalMachine\My`. The certificate checks constrain the self-issued identity, RSA and SHA-256/RSA OIDs, exactly one CA=false Basic Constraints extension, code-signing-only EKU, DigitalSignature-only usage, 3072-bit Microsoft Software KSP key, machine and non-ephemeral key state, and nonexportability. It compares the post-mint ACL to the original plus at most one exact, explicit vika Read ACE while preserving owner, group, protection state, existing ACEs, SYSTEM, and Administrators. Public-certificate export is hash-pinned and the private key is only used for an in-memory challenge.

The builder trust script writes only to vika `CurrentUser\Root`, checks the exact CER hash/thumbprint/subject/EKU and matching private certificate in `LocalMachine\My`, and rejects any other six-store thumbprint change. The debuggee script writes only to `LocalMachine\Root` and `LocalMachine\TrustedPublisher`; its expected inventory explicitly includes the same new thumb in logical `CurrentUser\Root` and `CurrentUser\TrustedPublisher` views. It retains the original signer and requires testsigning to remain enabled. Rollback removes only the exact new thumb from the same target stores, checks those projected views disappear, compares every other inventory entry, and verifies testsigning remains unchanged. Microsoft documents the LocalMachine-to-CurrentUser store projection [here](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/local-machine-and-current-user-certificate-stores); the observed builder baseline also has equal Root and TrustedPublisher thumb sets in those logical views.

One fail-closed evidence caveat remains in the create script: its post-mint `catch` performs a fresh six-store enumeration before it can write failure metadata. If that enumeration itself fails, the error terminates without the JSON failure record. This does not enable trust, build, or signing, but the operator must preserve process stdout/stderr and restore the independently verified pre-fallback checkpoint on any post-mint error.

The exact-build helper retains fresh signed-output absence, source/copy hash equality, unsigned-artifact preservation, conditional SignTool `/sm` for `LocalMachine`, and an Authenticode `Valid` plus exact-thumbprint gate. Its shell caller currently invokes the helper without `-CertificateStoreLocation LocalMachine`, so the helper defaults to `CurrentUser` and omits `/sm`. Before using the fallback signer, update and review that caller, pass the exact verified new thumbprint, and require its summary gate to pass. `Invoke-ExactSourceBuild.sh` already rejects summaries without `exit=0`, `signature_valid=True`, and a nonempty signed hash; the missing explicit store argument is the concrete caller defect.

Before any key mint, root must independently verify both pre-fallback VM checkpoints, exact UUIDs and backing disks, restrictive storage permissions, restorability, and the complete certificate/testsigning baselines. After mint, verify the metadata, ACL, public CER hash, and key-bearing checkpoint before importing trust. Signer pins must stay unchanged until the new certificate is minted and independently verified. Before calling the new signer usable, pass its exact thumbprint and LocalMachine scope through every approved signer caller and obtain builder and debuggee signature results of `Valid` with that exact thumbprint. The existing Matrix E pass need not be repeated solely because the signer changes.
