Implemented
-----------

StagedInvariantCases.psd1 now has Ready single variants for A01 (pre-scope
write handle), A02 (pre-scope writable view with its source handle closed),
and A03 (pre-scope PAGE_READWRITE section without a view, followed by the
first view after the runtime scope update). Other store patterns, handle
forms, rename/allocation variants, and reconnect repetitions remain deferred.

Test-StagedInvariantSuite.ps1 creates P as the standard-user actor while the
boot policy has no scopes, captures P from raw NTFS extents before changing
the policy file, and starts the real SafeUploadAgent service to apply the new
scope through its pending-policy/SET_POLICY path. It records admission epoch
generations, exact file-ID/path Activating evidence, service pipe status,
contract-D open and PAGE_READWRITE section probe results, tagged old-holder
writes, raw pre-promotion changes, lower write-completion ranges, holder
release, the exact Free/Protected entry, and the promotion trace. It captures
the raw image at promotion, performs an unapproved standard-user write, and
compares every allocated DATA extent against that promotion image. The
ForbiddenByteCount therefore excludes all pre-protection changes. A-specific
restore logic also recovers a test SafeUploadAgent service if normal cleanup
fails. A cases use `marker.txt` with `.txt` enabled in the runtime Agent
policy. For the post-promotion write, the test requires a Blocked journal
transfer and validates its authenticated StagePath under the product staging
root with the allocator GUID filename. The host adapter has an A-case gate
that does not apply the seed-case Predicate or latency requirements.

Evidence limits and deferred proof
----------------------------------

These limits produce explicit INCONCLUSIVE assertions; no product files were
changed to hide them.

* The service's current pipe status is sampled while the holder remains live,
  including after the old-holder writes. StatusNotification has coverage and
  policy generation but no file ID or H/S/C/T/W values. NotificationRecord
  persists a Status kind without the status fields. The current harness cannot
  prove a loss-detecting per-file readiness event sequence over every instant
  of the holder interval, so NeverReadyWholeHolderInterval remains
  INCONCLUSIVE. The folder is the only runtime scope and marker.txt is its
  only A-case fixture file; service readiness is aggregate for that accepted
  scope. A cases use `.txt` with the Agent's plain-text extension enabled.
  Sources: agente/SafeUpload.Agent.Core/Contracts/AgentNotification.cs:72-83,
  agente/SafeUpload.Agent.Service/Notifications/NotificationRecord.cs:112-119,
  agente/SafeUpload.Agent.Service/Interception/MinifilterInterceptor.cs:658-724.
* Promotion evidence explicitly sets TEST_DISABLE_TAINT to unavailable
  (0xffffffff); Inspector has no live policy Flags readback. The required
  live TEST_DISABLE_TAINT policy evidence remains INCONCLUSIVE. Sources:
  driver/SafeUpload.Minifilter/Protocol.h:1042-1084 and
  driver/SafeUpload.Inspector/main.c:1737-1746.
* The W admission trace records exact file ID, offset, length, status, and
  lower completion, but no payload digest. The harness correlates successful
  lower ranges with each tagged operation and records raw pre-protection
  extent changes; it cannot cryptographically bind lower bytes to the
  user-mode payload digest. Exact payload-content correlation is deferred.
  Source: driver/SafeUpload.Inspector/main.c:602-617.
* For A02/A03, the original write-capable source handle must be closed. The
  new-section probe therefore records the source-open result separately from
  the PAGE_READWRITE CreateFileMapping result and checks section-acquire
  counters. If the read-only source open is denied or the counters do not
  isolate a section callback, the section-denial assertion is INCONCLUSIVE;
  Win32 5 by itself is not attributed to minifilter admission. The retained
  old view/section behavior and new writable-open denial are tested
  independently.
* Post-promotion owned-stream proof uses the exact destination and standard-
  user actor PID in the authenticated journal delta, together with the
  raw-destination comparison. The journal schema does not include the target
  file ID; that identity link is established by the raw observer and the
  original activation evidence, not claimed as a journal field.
  The stage file's contents and ACL are not independently read by the test
  coordinator; the SYSTEM-private ACL is source-backed by StagedTransferAllocator
  but is not a runtime ACL observation.
* A cases use a supported `.txt` destination for the post-promotion write. A
  terminal Blocked journal state is required for the valid synthetic CPF test
  vector; Approved, Publishing, Released, or a still-transient state cannot
  pass this proof. The boot canary and seed cases retain `marker.bin`.
