NEW FINDINGS (ranked)
[BLOCKER] driver/SafeUpload.Minifilter/StageStream.c:2100 - A policy expansion is invisible to the physical mutation gate. During the candidate scan, an old handle to an existing candidate-only file is treated as out of scope; a mutating FSCTL/write can reach NTFS before the swap. The pending policy is consulted only for section admission. Check current-or-pending scope atomically in StageAdmit and StagePhysicalMutation, or refuse mutations during transition.
[BLOCKER] driver/SafeUpload.Minifilter/StageStream.c:2029 - An ADS escapes an exact-file scope. For policy prefix “file”, normalized “file:stream” fails the component boundary check (only '\\' is accepted); the alias helper strips the stream but returns early for a single-link file without comparing its base name to policy. Create/write/FSCTL against that ADS goes physical. Match the base path with Name->Stream removed before admission and mutation checks. Policy.c:81-87; StageAlias.c:100-103, 155-165.
[BLOCKER] driver/SafeUpload.Minifilter/StageStream.c:2095 - Protected non-NTFS scopes are passed through. StagePhysicalMutation returns SUCCESS_NO_CALLBACK before name/alias checks for every non-NTFS filesystem; StageUnownedMutatingFsctl then allows it. An old handle on a policy-protected SMB/removable/non-NTFS destination can issue a mutation (including redirector copy controls) directly. Refuse protected unsupported volumes or gate their namespace before this return.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:1955 - FILE_DELETE_ON_CLOSE is bypassed for directory opens and FILE_OPEN_BY_FILE_ID. DIRECTORY_FILE returns before name admission. The by-ID path treats a normal 64-bit ID plus DELETE-only access as non-writable, then falls through at 1996 without reaching the new check; DELETE-only legacy create also passes. A delete-on-close open of a protected empty directory or protected file by ID can delete it at cleanup. Resolve/check ID targets or refuse delete-on-close on these paths.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:2100 - Reparse mutation of an ancestor of a protected prefix is allowed. The gate checks ProtectedName, not TouchesProtectedNamespace; a pre-opened parent directory outside the prefix can receive SET_REPARSE_POINT/DELETE_REPARSE_POINT and redirect or remove the protected namespace. Use the ancestor-aware namespace predicate for reparse-changing FSCTLs.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:2175 - Several fallback FSCTL identities are wrong: ENCRYPTION_FSCTL_IO is function 54, DELETE_OBJECT_ID 40, WRITE_RAW_ENCRYPTED 55, OFFLOAD_WRITE 154, and DUPLICATE_EXTENTS_TO_FILE_EX 250; the fallbacks use 108, 39, 147, 307, and 313. If the target WDK lacks one of those macros, the real mutator misses the switch while an unrelated code is denied. Correct values and assert numeric codes. The active WDK #ifndef branches were not inspected.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:2217 - The default-allow list omits per-file state/metadata mutators such as FSCTL_SET_ZERO_ON_DEALLOCATION, FSCTL_MARK_HANDLE, FSCTL_WRITE_USN_CLOSE_RECORD, FSCTL_SET_PURGE_FAILURE_MODE, FSCTL_SET_REPAIR, and FSCTL_DELETE_EXTERNAL_BACKING. [MAJOR] driver/SafeUpload.Minifilter/StageStream.c:2245 - Unsafe-context resolution fails open. A nested/kernel-originated mutating FSCTL with non-NULL IoGetTopLevelIrp (or non-PASSIVE callback) increments FsctlUnresolved and reaches the filesystem. A user process cannot directly set IRQL or the top-level IRP; whether it can trigger a relevant nested kernel caller on the target stack is unverified. [MAJOR] driver/SafeUpload.Minifilter/StageStream.c:2284 - Writable-section protection has a swap TOCTOU: it checks current policy, releases that lock, then checks pending policy. A swap between checks clears Pending and lets a candidate-only writable section through after the pre-scan. Make current-plus-pending matching atomic across the swap.

VERIFIED
- The feature registration includes FILE_SYSTEM_CONTROL and DEVICE_CONTROL; dispatch gates only selected USER_FS_REQUEST FSCTLs. Fast I/O is disallowed before the FSCTL complete path. Completing an IRP with STATUS_ACCESS_DENIED is valid here, including METHOD_NEITHER, because the callback does not touch its user buffers.
- StagePhysicalMutation denies filesystem-type/name-query failures when those queries fail; it passes non-NTFS and checks current protected name plus hard-link aliases on NTFS. Directories match by name; ADS exact-file matching is not base-stream-aware. A volume handle's outcome depends on name and FileStandardInformation query results; raw device IOCTLs bypass this helper. Pipes/non-NTFS pass; ordinary safe-context name-query failure denies. The FSCTL wrapper instead allows unsafe-context cases before the helper.
- Path-based rename/link and SET_INFORMATION disposition/POSIX delete paths reach namespace or physical-mutation gates; supersede/overwrite creates are staged or refused. The new delete-on-close gate still has the early-exit gaps above.
- The changed normal driver callback table remains the non-staging table; the new FILE_SYSTEM_CONTROL switch arm is not registered there and is otherwise a no-op. Invoke-BuilderBuild.sh changed outside the feature guard, but that is build tooling, not driver behavior.
- Available local winioctl-compatible definitions confirm the fallback function-number discrepancies listed above; they do not establish what the builder’s WDK defines.
