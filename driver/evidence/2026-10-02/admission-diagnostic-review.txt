Findings, ranked most severe first

[BLOCKER] driver/SafeUpload.Minifilter/StageStream.c:439 - The synchronous FltCreateFileEx2 probe runs inline in protected pre-create before StageCreate, so the diagnostic can delay the original I/O and can wait on filesystem/oplock work - a protected open with an outstanding oplock holds the original create in this callback, while Disable waits for the probe's rundown reference and unload waits for callbacks - remove the synchronous probe from this observe-only slice or redesign it so the original I/O never waits and cannot be perturbed.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:1983 - The probe runs before StageCreate establishes whether the target exists or whether the volume is supported - FILE_CREATE of a missing protected file and a protected path on a non-NTFS volume still issue a failed lower open before the existing create path - probe only after a reliable existing-target check, otherwise skip it.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:450 - The probe forces FILE_NON_DIRECTORY_FILE and omits the original FILE_OPEN_REPARSE_POINT semantics - when a protected create addresses a reparse point itself, the probe can follow it and report the referent's file object/SOP and MmDoes result instead of the request's target - preserve equivalent target semantics or skip reparse/directory cases whose identity cannot be proven.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:1927 - The file-ID path probes a copied name before StageCreate revalidates ExpectedView at line 813 - a concurrent rename/replacement can make the probe open a new occupant of the stale name even though StageCreate then rejects the stale view - skip file-ID probes or validate a stable object identity before opening by name.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:385 - Paging-write and section-sync observations synchronously call FltGetStreamContext and FltGetInstanceContext instead of the specified nonblocking nonpaged hash lookup - if context lookup contends while a filesystem/MM resource is held, the callback can stall or deadlock, and it violates the hook's no-blocking-work constraint - remove these lookups from the hook path and use only a proven nonblocking lookup or report context as unknown.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:375 - Every event sets AdmissionRecordState to zero, and the Inspector prints the state as the constant "not_tracked" - paging and section events therefore cannot report the admission-record/hash hit or state required by the design - implement the nonpaged hash lookup and serialize its result, or revise the slice contract before treating this trace as evidence.
[MAJOR] driver/SafeUpload.Inspector/main.c:38 - The Inspector defines SAFEUPLOAD_STAGING_PROTOTYPE as 1 when the build did not define it, so the ordinary Inspector project always compiles the feature protocol and commands - a normal Inspector build accepts --admission-trace-* and sends controls unsupported by a normal driver, contrary to the feature-only build boundary - require the same explicit feature build define and leave it undefined/zero in normal builds.
[MINOR] driver/SafeUpload.Minifilter/StageStream.c:310 - ReadBatch snapshots the reservation counter before slot publication and advances NextCursor when the slot is not yet committed, without counting that omission - a reader that samples sequence 1 before its writer publishes it advances to cursor 2, then permanently misses the later-published event while LostEntries can remain zero - use a committed high-water mark or leave the cursor at an in-progress sequence and make retry/loss explicit.
