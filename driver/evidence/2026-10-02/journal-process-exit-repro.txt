Focused unfiltered Windows 10 debuggee harness reproduction.
No filter loaded, original ADA9... installed driver unchanged.

Start-Process powershell.exe -PassThru with redirected stdout/stderr;
child sleeps 750ms then exits 7. Attach with Get-Process -Id <child>;
WaitForExit(5000), then read attached ExitCode.

Observed:
  HandleCached=False; AttachedExitCode=; Null=True
  HandleCached=True; AttachedExitCode=7; Null=False

The only change in the second control is [void]$attached.Handle before waiting.
The actual probe waits for a .ready file, so its wrapper can retain this public
handle before releasing it. The fix is limited to that new wrapper; shared
service helpers and production code are unchanged. This is an observation of
the VM's Windows PowerShell/.NET Process behavior, not a kernel lifetime or
filesystem architecture claim. A nonzero control prevents accepting a null
status as success. Windows builds/module versions are the recorded debuggee
19045.2965 baseline; this does not qualify every PowerShell/.NET version.
