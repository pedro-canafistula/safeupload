SafeUpload staged-write admission — design v2
Date: 2026-10-02
Scope: analysis only; SAFEUPLOAD_STAGING_PROTOTYPE builds on Windows 10 19045.2965, NTFS, FltMgr 10.0.19041.1. Normal builds stay unchanged, as the existing registration has separate feature and normal callback tables. [Filter.c:129-164] No runtime experiment is claimed here.

DESIGN

Goal and boundary
- Cover the two confirmed physical-write leaks: a writable section predating attachment and one predating the first policy / later scope expansion. Existing evidence records both cases and says staging remains unqualified. [driver/STAGED-WRITES.md:109-123,197-236]
- Replace round-1 option 3. An unowned paging-write fence cannot identify scope by name and would hit unrelated files; denying paging writes also does not hide dirty mapped pages from cached readers. [driver/STAGED-WRITES.md:273-294]
- Use one admission record per NTFS stream, a per-file user-mapped-reference proof, and a fence only after a stream has been identified as protected. If the identity/proof/callback contract is not available, refuse protected access and keep staging disabled for that instance.
- Hard gate: this per-stream design alone does NOT close the first write from an already mapped pre-attachment file when no protected create/policy scan has yet identified that stream. Paging I/O has no safe name lookup, and a SectionKey has no path by itself. Late/manual attach cannot be called safe from per-file on-demand proofs alone; a tested attach boundary or complete race-safe admission mechanism is still required. Do not claim leak (a) blocked until the original ordering passes without inserting an artificial protected open before the old view writes.
- “Newly mounted means no earlier sections” remains a hypothesis, not a premise. InstanceSetup flags distinguish attach cases, but the current callback ignores Flags and always attaches after setting only VolumeKind. [driver/SafeUpload.Minifilter/Filter.c:439-514; Context.c:224-295]

State and exact records
1. Extend SAFEUPLOAD_INSTANCE_CONTEXT in Filter.h:216-220 with SetupFlags, AttachClass {NewMountCandidate, LateOrManual, Detached}, AdmissionState {Quarantined, ReadyForPerFileProof, Transition, CoverageLost, Dismounting}, a nonpaged KSPIN_LOCK, a 64-bucket admission hash/list, record count/limit, and active protected-create / section-sync / publication counts. Initialize every field in SafeUploadSetInstanceContext; pass Flags from SafeUploadInstanceSetup. That routine stays bounded: allocation, flag copy, classification only; no wait, filesystem scan, or IPC. Current setup is PASSIVE_LEVEL. [Filter.c:457-514; Context.c:224-295]
2. Add feature-only SAFEUPLOAD_ADMISSION_RECORD in Filter.h beside the context types: LIST_ENTRY hash and instance links; volatile LONG References, State, PolicyGeneration, ActiveWrites, Revision; PFLT_INSTANCE Instance (referenced); PSECTION_OBJECT_POINTERS SectionKey; FILE_ID_INFORMATION FileId; BOOLEAN FileIdValid, AliasSetComplete, NameDirty, UserWritableRefsSeen; UNICODE_STRING plus WCHAR NameBuffer[SAFEUPLOAD_MAX_PATH_CHARS]. States are Observed, Probing, ProtectedFenced, MappedQuarantine, Unknown. SectionKey is only a documented pointer key; no FCB internals/offsets are read.
3. Add one AdmissionRecord pointer to the existing SAFEUPLOAD_STREAM_CONTEXT (Filter.h:254-317). The FLT_STREAM_CONTEXT is the per-stream lifetime anchor; the record is also indexed by (instance, SectionKey) so paging/acquire callbacks need no name query or stream-handle context. Existing stream contexts are registered and cleaned in Context.c:63-139; make cleanup unlink the record and drop context/table references. FLT_STREAMHANDLE_CONTEXT is deliberately not the anchor: both repros close the source file handle while retaining the writable view. [Test-StagedPreAttachmentMapping.ps1:62-74; Test-StagedPolicyTransitionMapping.ps1:155-168]
4. Hash ownership: one reference from the stream context, one while indexed, plus callback/policy-scan references. Removal unlinks under the instance spin lock; free only after references reach zero, then dereference Instance. Bound records at 4096 per instance; exhaustion marks CoverageLost. Never retain a raw SectionKey after context cleanup. Policy scans copy the record name/ID under its passive lock, release it, reopen/query, then compare Revision before publishing. Any stale identity or incomplete alias enumeration is Unknown and fails closed.
5. Store one normalized name and stable NTFS FILE_ID_INFORMATION, not an unbounded alias array. On policy change, enumerate the physical stream’s hard links using the existing bounded NTFS alias machinery; evaluate every name against the candidate policy. More than 64 links, incomplete parents, unresolved name, reparse/identity mismatch, or unsupported stream contexts marks alias scope unknown and rejects that policy update. The repo’s alias path already fails closed on partial/excess enumeration. [driver/STAGED-WRITES.md:17-26]

Creation, mapping and write call sites
1. In StageAdmit (StageStream.c:1437-1537), after normalized name/scope classification and before StageCreate (currently line 1530), acquire a short-lived admission token and probe an existing physical target with documented FltCreateFileEx2 using READ_ATTRIBUTES and read/write/delete sharing. Use the current instance so the probe obtains that stream’s SectionObjectPointer; do not hold the instance/index/policy lock over the open. For a missing target, use the existing StageCreate path; no old file section can belong to the missing object. For unsupported FS, unresolved ID/name, no stream-context support, null SOP, failed identity check, or allocation failure: protected writer create completes with STATUS_DEVICE_NOT_READY (allocation failure may be STATUS_INSUFFICIENT_RESOURCES); never falls through to a raw writer.
2. For an existing protected stream, attach/get the FLT_STREAM_CONTEXT, insert its record into the SOP hash as Probing, then call MmDoesFileHaveUserWritableReferences on the probe’s SOP at PASSIVE_LEVEL. This API is documented for IRQL <= APC_LEVEL and detects writable user views after handles close. [driver/STAGED-WRITES.md:297-305] Result 1 sets MappedQuarantine and refuses the protected create with STATUS_SHARING_VIOLATION; result 0 sets ProtectedFenced and permits StageCreate. Unknown/error refuses with STATUS_DEVICE_NOT_READY. Keep the per-stream fence after admission: old raw file objects must not write around the new staged object.
3. Before the proof, wait boundedly for preexisting unowned SyncTypeCreateSection acquire/release pairs on this instance to drain. Every such callback increments a nonpaged counter before looking up SectionKey; allowed creates decrement on release. Once Probing is indexed, new writable section creates for that SectionKey fail with STATUS_INSUFFICIENT_RESOURCES. SyncTypeOther always passes. This closes the proof-to-admission race if the documented callback pairing and SOP identity hold; otherwise keep the instance unavailable.
4. Extend SafeUploadStageDispatch before its current StageStreamForObject/legacy split (StageStream.c:1618-1649). Owned STAGE_STREAMs still take StagePreOperation. For an unowned target, look up (Objects->Instance, TargetFileObject->SectionObjectPointer) in the admission hash using only nonpaged state. If ProtectedFenced or MappedQuarantine, deny raw IRP_MJ_WRITE (paging and nonpaging) with STATUS_MEDIA_WRITE_PROTECTED before SafeUploadPreWrite; count it. This is a per-record fence, never a volume-wide paging fence. A protected record also denies new writable SyncTypeCreateSection with STATUS_INSUFFICIENT_RESOURCES; SyncTypeOther cannot be failed. [current owned section-sync status path: StageStream.c:1185-1193; unowned paging fallthrough: 1618-1649; callback limits: STAGED-WRITES.md:183-195]
5. Every successful physical IRP_MJ_CREATE, including out-of-scope/no-policy writable opens, must acquire a post-create callback and install/update the stream context + record before the handle returns to user mode. Add this wrapper in StageAdmit/SafeUploadStageDispatch and SafeUploadStagePostOperation (StageStream.c:1627-1629,1672-1681); compose any legacy SafeUploadPreCreate completion value in a tagged completion record. If record/context/name/identity publication fails, cancel the just-opened file with FltCancelFileOpen and mark CoverageLost. Current legacy SafeUploadPreCreate can skip post-create on the cheap/no-agent path; SafeUploadPostCreate creates a cache context only on eligible paths. [Filter.c:1228-1285,1403-1405,1534-1539]
6. For pre-attachment objects, a protected create’s physical probe installs the stream record before the MmDoes proof; the old file object must resolve to the same SectionKey in subsequent section/write callbacks. Do not infer success from a fresh buffered reader. If callback identity differs or no paging callback arrives, the late-attach capability is unsupported and cannot be activated.

Policy transition and lock/rundown order
1. In SafeUploadSetPolicy (Policy.c:217-237,327-344), finish/validate the candidate snapshot first. Today this path only swaps the snapshot/increments PolicyGeneration and frees the prior snapshot; it has no staging admission transition. [Policy.c:327-344; Communication.c:698-712] Acquire a new PASSIVE admission-policy mutex to serialize policy pushes. Atomically set per-instance Transition; if any protected StageCreate/service-allocation token, affected section-sync pair, or publication token is active, restore the old state and return STATUS_DEVICE_BUSY immediately. Do not wait while an agent call is in flight.
2. With Transition set, StageAdmit rejects creates matching either current or candidate protected scope with STATUS_DEVICE_BUSY; rename/link to/from either scope is refused. Paging callbacks consult only already-recorded scope/state. At PASSIVE, walk referenced records, evaluate stored names and the complete alias set against the candidate snapshot (no name query in paging/acquire/release), mark each newly protected stream Fenced before proof, wait its in-flight physical writes to complete, reopen by stored name, verify FileId, then call MmDoes. Any failure/unknown identity rejects the update and leaves the old snapshot/generation active; already-fenced records stay fenced or become Unknown, never roll back to raw-writable on an error. A found mapping is recorded and fenced; policy may commit, but all protected opens on that stream continue to refuse until a later proof says no user-writable refs remain.
3. Commit only after the scan: take SafeUploadPolicyLock exclusive briefly, swap snapshot and increment PolicyGeneration, release it, then reopen admission. Never call StageCreate, FltCreateFileEx2, MmDoes, alias enumeration, FltSendMessage, or wait while SafeUploadPolicyLock is held. Existing policy readers take/release this lock inside Policy.c:630-668; current Communication invokes SafeUploadSetPolicy at 698-712.
4. Lock order: admission-policy mutex -> instance state/hash spin lock only for reference/state changes -> drop spin lock -> one record passive lock for copying -> drop it before any file/NTFS call -> SafeUploadPolicyLock only as the final short swap. No reverse acquisition. StageNamespaceResource/StageStream Resource remain inside StageCreate’s existing order; StageCreate currently holds StageNamespaceResource across SafeUploadStageAllocate and backing open (StageStream.c:356-379,487-500,548-556), and allocation waits in FltSendMessage at PASSIVE (StageProtocol.c:178-252; Communication.c:326-433). The new admission token is a counter, not a held lock. Policy push sees that token and returns DEVICE_BUSY rather than waiting or taking StageNamespaceResource, preventing a service-allocation deadlock. Do not add SafeUploadPolicyLock or admission mutex around the IPC wait.
5. Raw physical writes that already passed before a fence carry a tagged post-op record and an ActiveWrites reference; fence first, then wait for completion at PASSIVE before policy commit. Update SafeUploadStagePostOperation to distinguish that tag from the existing STAGE_STREAM PagingRundown completion (currently lines 1672-1681). Publication create/rename gets an active token through the successful rename post-op; failure to pin it means refuse the permit. Existing permit checks are at StageStream.c:1523-1525,1604-1608.

Attach, detach, unload, dismount and restart
- InstanceSetup copies Flags only; it does no IPC/synchronization (callback restrictions: STAGED-WRITES.md:183-195). NEWLY_MOUNTED sets NewMountCandidate, not Ready, until the race test proves the ordering. Automatic-existing and manual attach are LateOrManual and remain Quarantined; per-file probes can fence a stream once observed but cannot prove there is no unobserved pre-attach stream. No all-volume scan or volume-wide fence is claimed, so late/manual staging stays disabled until a separately proven admission boundary exists.
- QueryTeardown passes only when the instance has no admission records, active write/section/publication tokens, mapped-quarantine records, or unknown coverage, in addition to the existing owned-stream check. Current detach checks StageStreamCount only; unload drains/counts owned streams/file objects only. [StageStream.c:1375-1409; Filter.c:518-553]
- On IRP_MJ_VOLUME_DISMOUNT mark Dismounting and refuse new protected admission; do not clear records until callbacks drain and contexts clean up. Reattach/remount creates a fresh instance and repeats flag classification/proof. Whether a forced dismount can outlive mapped sections is an experiment, not assumed safe. Current feature registration includes volume dismount and teardown callbacks. [Filter.c:129-153]
- Voluntary unload uses SafeUploadStagePrepareUnload, but mandatory unload cannot be declined in current SafeUploadUnload. [Filter.c:331-393] Keep staging unavailable if mandatory unload/reload with a live view cannot be fenced; no driver-only guarantee is claimed for forced unload.
- Service disconnect/restart never clears record/fence state or converts a physical object to writable. Existing staged allocation already fails if no valid service response; policy remains in the driver until replacement/free. [StageProtocol.c:249-253; Policy.c:327-344; Communication.c:427-440]
- IRQL plan: InstanceSetup, InstanceQueryTeardown, create pre/post, SafeUploadSetPolicy, FltCreateFileEx2, alias enumeration and MmDoes probes run at PASSIVE_LEVEL (current create/policy contracts: Filter.c:1188-1193,1432; Policy.c:226; MmDoes limit: STAGED-WRITES.md:297-305). Stream-context cleanup is <= APC_LEVEL and must only unlink/drop refs without waiting (Context.c:107-139). Paging-write and acquire/release callbacks use nonpaged fields, spinlocks and interlocked counters only; their exact maximum IRQL/pairing for this target stack is UNVERIFIED. Non-create post-op may run at elevated IRQL, so it only drops tagged references/counters with interlocked operations; create post-op is PASSIVE_LEVEL. No paging/acquire/release path does a name query, resource wait, or MmDoes call.

SELF-ATTACK
1. Old writable section predates attachment and writes immediately after attach, before any protected open/policy proof: OPEN. No record identifies its SOP as protected; name queries are unsafe in paging I/O. The current pre-attachment repro uses this order. [Test-StagedPreAttachmentMapping.ps1:77-103]
2. Writable handle predates attachment, but a protected create probes before it calls CreateFileMapping: CLOSED only if old-object callbacks share SectionKey and Probing blocks section creation; NEEDS EXPERIMENT for NTFS identity.
3. Duplicate or inherited pre-attach handles: CLOSED by stream/SOP record rather than per-handle tags; NEEDS EXPERIMENT that duplicated file objects expose the indexed SOP.
4. Image sections: if MmDoes returns 1, admission overblocks safely; writable image-section behavior and read-only return value NEED EXPERIMENT.
5. Mapping starts between proof and admission: CLOSED by inserting Probing first, counting in-flight section-sync pairs, draining, then calling MmDoes; callback pairing/order NEEDS EXPERIMENT.
6. Open protected file by file ID: unknown writable IDs already fail in StageAdmit; known IDs resolve to stable FileId/SOP or refuse. [StageStream.c:1461-1492] CLOSED for unresolved writable IDs; read-only-to-writable interaction NEEDS EXPERIMENT.
7. Open via hard-link alias: re-enumerate each NTFS link; partial or >64 aliases reject. CLOSED for bounded complete enumeration; alias identity needs experiment.
8. Open via short name/case alias: normalize at create and verify FileId; unresolved/mismatch refuses. Whether NTFS resolves every short-name spelling NEEDS EXPERIMENT.
9. Mapped file object has no stream context: hash lookup uses SOP, not handle context; null/different SOP marks CoverageLost. NEEDS EXPERIMENT; open if runtime incorrectly treats it as covered.
10. Delete-pending or rename during proof/policy scan: mark NameDirty; candidate-scope rename/link refused; revision/FileId mismatch aborts. NEEDS EXPERIMENT that post-op identity update works.
11. Oplock break during physical probe: no admission/index/stream lock held over open; probe timeout/failure returns DEVICE_NOT_READY. Reentrancy/latency NEEDS EXPERIMENT.
12. Dismount/remount or stack attach after mount: old instance enters Dismounting; new one is LateOrManual unless new-mount flags/order verified. Falsifiers are mount while filter loaded, remount, or later attach. NEEDS EXPERIMENT.
13. Policy push races create/map: active protected-create token returns DEVICE_BUSY; candidate path opens refuse during Transition; Probing/fence blocks identified stream. NEEDS EXPERIMENT under callback races.
14. Stream-record publication races policy scan: revisioned records and transition admission prevent candidate publication; mismatch aborts swap. NEEDS EXPERIMENT under concurrent creates.
15. Publication rename overlaps policy push: token remains through successful rename post-op; policy push returns DEVICE_BUSY. Existing pre-op permit alone is insufficient; new post-op pin NEEDS EXPERIMENT.
16. Service restart with no policy/client: existing raw fence stays; protected staged creates fail closed if allocation cannot answer. CLOSED for fail-open downgrade; recovery availability NEEDS EXPERIMENT.
17. Paging-write refusal: scoped fence can keep physical bytes unchanged only if callback is delivered and refusal blocks writeback. It cannot hide dirty pages from cached readers. [STAGED-WRITES.md:273-294] Physical result NEEDS EXPERIMENT.

DIAGNOSTIC SLICE (observe-only; no denials)
- Add feature-only bounded nonpaged ring (256 entries, overwrite oldest) plus cumulative counters. Entry fields: sequence/timestamp, event, PID, instance pointer, TargetFileObject pointer, its SectionObjectPointer value, IRP major/minor and IrpFlags (including IRP_PAGING_IO), IRQL, MmDoes attempted/result or SKIPPED, stream/admission-context present, record state, SetupFlags, VolumeKind. Never store file content or full path. Ring append uses interlocked slot reservation; callback probes do no blocking-lock acquisition, allocation, name query, IPC, wait, or status change. The separate record-presence lookup uses only the nonpaged hash spinlock.
- At the current unowned paging-write fallthrough in StageStream.c:1623-1649, record target FO, SOP, IRP flags, context/hash hit, and whether paging-write callback arrived. Do not call MmDoes above APC_LEVEL; record SKIPPED. Current unowned paging IRP_MJ_WRITE falls through. [StageStream.c:1623-1649]
- Add an observe-only branch for unowned ACQUIRE/RELEASE_FOR_SECTION_SYNCHRONIZATION next to StageStream.c:1626-1669. Record SyncType, PageProtection, FO, SOP and context. If IRQL <= APC_LEVEL and SOP nonnull, call documented MmDoes and record result; otherwise SKIPPED. Always return existing pass-through result; never deny SyncTypeCreateSection or SyncTypeOther in this slice. Current owned path is at 1185-1197; callback failure rules are STAGED-WRITES.md:183-195.
- At protected StageAdmit immediately before StageCreate (StageStream.c:1494-1537), observe-open the target with READ_ATTRIBUTES, record probe FO/SOP and MmDoes result, close it, and compare later paging/section records. Do not attach a fence or change create result. Probe/open failures are logged as observations. Cost is one extra kernel open and one MmDoes call per protected create; possible oplock/share/latency effects are recorded.
- In InstanceSetup, record raw Flags, classified volume kind, and derived attach class at Filter.c:439-514; no wait or IPC.
- Retrieval: add feature-only SAFEUPLOAD_CONTROL_GET_ADMISSION_TRACE with bounded batch cursor in Protocol.h and Communication.c, and `SafeUpload.Inspector --admission-trace`. Existing GET_COUNTERS is 184 bytes and already uses the port/short-lived inspector mode, but has no pointer/event payload. [Protocol.h:252-254,476-645,699-703; Communication.c:574-617; Inspector/main.c:367-430,552-555] Ring snapshot uses sequence-before/copy/sequence-after; omit torn/overwritten entries and report lost count. Normal-build protocol and behavior remain unchanged.
- The four unknowns map to evidence as follows: pre-attach callback/FO/SOP = paging ring; writable vs read-only closed-handle MmDoes = two probe variants; SOP equality = compare probe and writeback entries; cache vs disk = paired readers below. Observe-only establishes the no-refusal baseline. The supplied fact already predicts that a paging refusal cannot hide dirty data from the cached reader; uncached bytes under refusal remain unverified and require the separate scoped test-only refusal in TEST PLAN, not this slice.

UNVERIFIED LIST

- Whether READ_ATTRIBUTES FltCreateFileEx2 on NTFS yields the same SectionObjectPointers as the old mapping file object; whether SOP address is stable across aliases/reopens and while stream context exists.
