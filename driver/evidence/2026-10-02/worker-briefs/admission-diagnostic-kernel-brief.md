## 3. Requirements and amendments to the v2 diagnostic spec
a. Feature build only: all new code lives under the same compile-time guard the existing staging code uses (find it with grep; the MSBuild property is SafeUploadStagingPrototype). Normal builds must compile byte-for-byte unchanged in behavior; do not touch normal-build-only paths.
b. DEFAULT OFF. A runtime control message from the Inspector enables, disables and clears the diagnostic. While disabled, every hook is a single volatile load and branch. No existing control message layout or protocol version changes; add new control codes only.
c. Observe-only: no hook may change an NTSTATUS, completion path, flags, target, or ordering. The ONLY extra I/O is the protected-create probe in (g), and only when the diagnostic is enabled.
d. Ring: fixed 256 entries in nonpaged memory allocated once when enabled (or statically), overwrite oldest, interlocked slot reservation, per-entry sequence number so the reader can detect torn/overwritten entries (sequence before/copy/sequence after), cumulative counters, and a "lost" count. Hooks never allocate, wait, take resources, query names, send IPC, or call anything not valid at the hook's IRQL. Entry fields (no file content, no paths): sequence, timestamp, event kind, PID, IRQL, instance pointer value, TargetFileObject pointer value, its SectionObjectPointer pointer value (documented FILE_OBJECT field; read it, never dereference deeper), IRP major/minor, IrpFlags (IRP_PAGING_IO etc.), MmDoes result (or SKIPPED), whether an owned stream/stream context exists, SetupFlags, VolumeKind, SyncType/PageProtection for section sync, NTSTATUS of the probe open when applicable.
e. Hooks: (1) the existing unowned IRP_MJ_WRITE fall-through for paging and nonpaging writes (StageStream.c ~1618-1649): record only. (2) Unowned IRP_MJ_ACQUIRE_FOR_SECTION_SYNCHRONIZATION and RELEASE_: record SyncType, PageProtection, FO, SOP; always return the existing result; never fail either SyncType. (3) SafeUploadInstanceSetup: record raw Flags, volume kind, and which of automatic/manual/newly-mounted it was (use only documented FLT_INSTANCE_SETUP_FLAGS names). No wait, no IPC. (4) Protected create probe, below.
f. AMENDMENT: MmDoesFileHaveUserWritableReferences must NOT be called from the paging-write or section-sync hooks (those callbacks can run with file-system/Mm resources held; deadlock risk). Record MmDoes as SKIPPED there. It may be called only from the PASSIVE_LEVEL protected-create probe.
g. Protected-create probe: in StageAdmit (StageStream.c ~1494-1537) after the scope decision classifies the path as protected and the target exists, and immediately before the existing StageCreate call, if the diagnostic is enabled: open the same target with documented FltCreateFileEx2 below the current instance, desired access FILE_READ_ATTRIBUTES only, full share access, no create side effects (open-existing only), record the probe file object's SectionObjectPointer pointer value, call MmDoesFileHaveUserWritableReferences on it (PASSIVE_LEVEL, documented IRQL <= APC_LEVEL), record the result and NTSTATUS, then close the probe handle and dereference the file object. Failure of any probe step is recorded and otherwise ignored; the create then proceeds exactly as before. Do not hold any lock over the probe. State in the code comment that this is the only extra I/O and why.
h. Retrieval: add feature-only SAFEUPLOAD_CONTROL_* codes (names of your choice, in the existing style) for Enable, Disable, Clear, and ReadBatch(cursor) returning a bounded batch that fits the existing message buffer limits; and Inspector commands `--admission-trace-enable`, `--admission-trace-disable`, `--admission-trace-clear`, and `--admission-trace` which prints one JSON object per entry (stable field names) plus a summary line with counters, lost count and cursor.
