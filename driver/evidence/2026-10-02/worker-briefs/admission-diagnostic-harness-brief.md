## 3. Variants (selectable with -Variant <name>; one named variant per invocation; -Variant All runs them sequentially, each fully restored before the next)

### 3.0 Hard facts about the Inspector connection (verified in source by the orchestrator; design around them)
- The feature port accepts ONLY a LocalSystem primary token (Communication.c ~254-263), and MaxConnections is 1 (Communication.c ~127). The SSH session runs as the `vika` administrator, so EVERY Inspector call must run as SYSTEM: implement a helper `Invoke-InspectorAsSystem -Arguments <...> -Timeout <s>` that registers a one-shot scheduled task as SYSTEM (copy the pattern in driver/scripts/StagedTestAgent.ps1: task name MUST start with `SafeUpload-StagedTest-` so the existing leftover-task checks find it, launcher script in $env:TEMP, stdout/stderr redirected to files, PID/exit code captured, task stopped and unregistered and launcher removed in `finally`), waits for completion with a timeout, and returns exit code, stdout and stderr. Copy the Inspector exe to a fixed path under Documents (hash it and compare with -ExpectedInspectorSha256; make that a mandatory parameter too).
- Because MaxConnections is 1, the real agent and the Inspector can NEVER be connected at the same time. Before every Inspector call assert zero SafeUpload.Agent.Service processes; before starting the agent assert no Inspector process. A disconnect clears only the client port and publication permits; the POLICY STAYS in the driver after the agent stops (the existing transition harness relies on this). So the sequence "agent starts, pushes policy, signals ReadySignal, agent stopped" leaves the policy active for the rest of the run.
- Trace state lives in the driver (not tied to the Inspector connection), so enable it with one short Inspector call BEFORE the interesting events and read it with another short call afterwards.
- The explicit probe (`--admission-probe <X:\path>`) opens the file at the volume-instance level and does NOT depend on policy or on an agent; it needs only the loaded feature driver and an enabled trace.
- Third-review conditions (orchestrator decisions): (1) the explicit probe does not defend against reparse points, so BEFORE loading the driver the harness must verify that no component of any fixture path, from the drive root down to the file, has the ReparsePoint attribute (check each ancestor with Get-Item -Force and fail the run if one does; Documents may be redirected on some machines) and must refuse any path containing ':' after the drive letter; (2) a probe's lower open can in principle stall: every Inspector call must have a timeout (default 60 s). If any Inspector call times out, treat the run as FAILED: stop the Inspector task, do not call it again, run the normal restoration `finally`, and print `InspectorTimeout=<command>`; the orchestrator will revert the VM checkpoint if restoration fails; (3) never run the Inspector while an agent is connected.
