B — explicit-probe conclusion: NEEDS-CHANGE

The probe holds no StageNamespaceResource, control mutex, or trace rundown
across FltCreateFileEx2. The only held objects are referenced volume/instance
objects; a slow open blocks the Inspector's FilterSendMessage thread. However,
SafeUploadPortMessage does not acquire ChannelRundown (Communication.c:489-916;
that rundown is for FltSendMessage at :396-481). Port disconnection does not
provide a cancellation request to FltCreateFileEx2. Filter.c:411-415 calls
FltUnregisterFilter before StageFree and relies on it to wait for callbacks;
a lower open stalled on an oplock/filter/filesystem can therefore pin callback
completion and a mandatory unload. Use a bounded, cancelable lower open whose
cancellation is drained before teardown, or remove the explicit lower open.

Also reject reparse traversal and ADS before opening: walk path components and
skip any reparse component (including ancestors), reject ':' in the relative
path for the default stream probe, and record a reason-coded skip. Otherwise
the pointer/MmDoes result can describe a different object/stream than expected.

New findings, ranked most severe first

[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:484 - Synchronous
FltCreateFileEx2 has no timeout/cancel path and runs inside the message callback
- if a lower filter/filesystem waits indefinitely (for example on an oplock),
FilterSendMessage never returns and FltUnregisterFilter can wait on this active
callback, so forced unload can hang - use a bounded, cancelable lower request
and drain cancellation before teardown, or remove this probe.
[MAJOR] driver/SafeUpload.Minifilter/StageStream.c:495 - FILE_OPEN_REPARSE_POINT
opens the final reparse object, while intermediate junctions can still be
followed/cross volumes - probing a symlink to a mapped file can report the
link's FO/SOP and MmDoes=NO for the wrong object, and an ancestor junction can
route the extra create to another instance - reject every reparse component
before the open, or explicitly define and safely implement follow semantics.
[MINOR] driver/SafeUpload.Minifilter/Communication.c:761 - relative path accepts
':' - `X:\dir\file:stream` is opened as an alternate stream, so its FO/SOP and
MmDoes result need not describe the default data stream - reject ADS syntax at
both protocol and Inspector boundaries, or explicitly label/support stream probes.
