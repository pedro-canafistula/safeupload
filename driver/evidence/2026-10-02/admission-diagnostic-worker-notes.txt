Scope and behavior
- Implemented the feature-build-only trace in the minifilter under
  SAFEUPLOAD_STAGING_PROTOTYPE. Its runtime state starts at zero (disabled).
- The callback hooks record unowned paging/nonpaging writes, unowned section
  acquire/release callbacks, and InstanceSetup flags/classification. They do
  not set I/O status, return a different callback result, or change flags.
- MmDoesFileHaveUserWritableReferences is called only in the PASSIVE_LEVEL
  protected-create probe. Paging and section-sync observations say "skipped".
- The probe uses FltCreateFileEx2 below the current instance with
  FILE_READ_ATTRIBUTES, full read/write/delete sharing, FILE_OPEN, and no EA,
  allocation size, ECP, or driver create context. Its status/result is only
  recorded. Probe handles and returned file objects are closed/dereferenced on
  every path. A rundown reference spans the probe; no trace lock is held.
- Ring storage is static nonpaged data (256 entries); callback writers reserve
  a global sequence and claim a slot with interlocked operations. A busy slot
  drops that entry and increments LostEntries. Replacements also increment the
  lost count. Readers compare sequence before and after copying and omit torn
  or overwritten slots. Control/read operations serialize reset and rundown.
- No admission-record table exists in slice 1; AdmissionRecordState is emitted
  as "not_tracked". The stream-context field reports present/absent/unknown.

Control and output contract
- ENABLE=5, DISABLE=6, CLEAR=7, READ_BATCH=8. Control messages require the
  existing protocol version, exact struct size, matching command, and zero
  reserved field. Enable/disable/clear reject output buffers. Read requires an
  exact 32-byte request and exact 1104-byte output buffer; cursor and snapshot
  bounds are checked before the ring is read. Batches contain at most eight
  entries. Cursor/snapshot zero on the first request selects the current
  retained snapshot.
- Inspector commands: --admission-trace-enable, --admission-trace-disable,
  --admission-trace-clear, and --admission-trace. The last prints one JSON
  object per entry and then a JSON summary. Entry keys are sequence,
  timestamp, event, pid, irql, instance, targetFileObject,
  sectionObjectPointer, major, minor, irpFlags, mmDoes, streamContext,
  ownedStream, admissionRecordState, setupFlags, volumeKind, attachClass,
  syncType, pageProtection, syncParametersValid, probeAttempted, and
  probeStatus. Summary keys include all cumulative counters, lostEntries,
  cursor, and snapshotSequence.
