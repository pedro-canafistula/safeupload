SafeUpload staged-write admission epoch — design analysis
Date: 2026-10-02
Scope: feature build only (SAFEUPLOAD_STAGING_PROTOTYPE); Windows 10 19045.2965, NTFS, FltMgr 10.0.19041.1. No source changes or runtime tests in this analysis.

CURRENT ADMISSION (verified; 13 lines)
1. Feature builds register the stage dispatcher for create, write, section-sync, modified-page-writer, cache-flush and related operations; normal builds keep the smaller legacy callback set and skip paging writes. [driver/SafeUpload.Minifilter/Filter.c:129-164]
2. InstanceSetup currently records only volume kind and returns STATUS_SUCCESS even when that kind is unknown; its instance context has no admission state or epoch. [driver/SafeUpload.Minifilter/Filter.c:484-514; driver/SafeUpload.Minifilter/Context.c:253-295; driver/SafeUpload.Minifilter/Filter.h:216-220]
3. Scope is the bootstrap path plus current policy prefixes / removable / network flags. No policy means policy scope matches nothing. [driver/SafeUpload.Minifilter/StageProtocol.c:101-133; driver/SafeUpload.Minifilter/Policy.c:630-668]
4. On create, StageAdmit normalizes the name; a protected path enters StageCreate, while a nonprotected path falls through to the legacy create callback. [driver/SafeUpload.Minifilter/StageStream.c:1494-1537,1623-1629]
5. StageCreate asks the service to allocate a private version, opens its backing, and binds the admitted FILE_OBJECT to SafeUpload's FCB and SECTION_OBJECT_POINTERS. [driver/SafeUpload.Minifilter/StageStream.c:457-500,523-548]
6. Writes and paging writes for that owned object are handled/routed to the private backing. Writable sections are checked on the owned object. [driver/SafeUpload.Minifilter/StageStream.c:1066-1077,1185-1197]
7. If StageStreamForObject finds no owned stream, paging IRP_MJ_WRITE currently falls through: only nonpaging writes take the physical-mutation/legacy path. [driver/SafeUpload.Minifilter/StageStream.c:90-103,1623-1629,1643-1649]
8. Leak (a) is confirmed: a writable view made before attachment, with its file handle closed, changes the protected physical file after attachment. The report says that view has no newly admitted stream object. [driver/STAGED-WRITES.md:109-123,173-181]
9. Leak (b) is confirmed: a view made while attached but before the first policy push remains live through a later policy expansion and changes the newly protected physical file. [driver/STAGED-WRITES.md:197-218,227-236]
10. Policy replacement builds a snapshot, swaps it under SafeUploadPolicyLock, increments PolicyGeneration, and frees the old snapshot; Communication calls SafeUploadSetPolicy. No staging-epoch transition is in that path. [driver/SafeUpload.Minifilter/Policy.c:217-237,327-344; driver/SafeUpload.Minifilter/Communication.c:698-712]
11. The existing drain/purge is for an owned STAGE_STREAM with its own section pointers; it is not a volume scan or proof about arbitrary preexisting file objects. [driver/SafeUpload.Minifilter/StageStream.c:1291-1309]
12. A pending owned rename freezes that stream until exchange acknowledgement; owned stream writes recheck state under its resource. [driver/SafeUpload.Minifilter/StageStream.c:635-700,788-800,883-900]
13. Callback limits recorded in the write-up: InstanceSetup is PASSIVE_LEVEL and must not synchronize or IPC; CreateSection may fail only with STATUS_INSUFFICIENT_RESOURCES; SyncTypeOther cannot fail; name queries are unsafe in paging/acquire-release paths. [driver/STAGED-WRITES.md:183-195]

DESIGN OPTIONS

Option 1 — per-file first-open admission and promotion
Mechanism: attach an epoch/path record to every file object seen at create, including currently out-of-scope opens. On policy expansion, close admission, find records whose files enter scope, and promote only after their old writable sections are gone; use the existing owned-stream create path for new opens. Candidate APIs: FLT_STREAMHANDLE_CONTEXT / FltSetStreamHandleContext, FltGetStreamHandleContext, FltFlushBuffers, CcPurgeCacheSection. The repo uses stream-handle contexts and uses flush/purge only for owned-stream retirement. [driver/SafeUpload.Minifilter/Context.c:469-545; driver/SafeUpload.Minifilter/StageStream.c:1293-1309]
Leak coverage: can address (b) only if every relevant FILE_OBJECT and live section is represented and promotion proves the old view cannot write. Does not address (a): the preattachment FILE_OBJECT has no newly admitted owned stream, as confirmed in the write-up; the feature dispatcher only finds streams it owns. [driver/STAGED-WRITES.md:173-180; driver/SafeUpload.Minifilter/StageStream.c:90-103,1623-1629] A directory scan alone would not prove its live section is gone.
Races / locks / lifetime: serialize create and transition with an epoch gate; hold no push lock across service IPC. Store the name/identity at create; do not query names in paging I/O. A handle context cleared at cleanup may be too short-lived for the repro, which closes the handle but retains the view. Need a record lasting through final section/file-object lifetime. New opens racing promotion must either join the old generation and be included or fail closed. Publication must drain/serialize with the same transition.
Failure / user effect: if a context cannot be allocated, section state is unknown, flush/purge fails, or a candidate file cannot be promoted, reject the protected create or policy expansion (DEVICE_NOT_READY / INSUFFICIENT_RESOURCES); service reports policy not active. Never silently enable staging for that file.
Uncovered / cost / test: no repo-proven way to enumerate arbitrary file objects or prove no user-writable section remains; promotion therefore cannot be qualified yet. Changes: Context.c, Filter.h, StageStream.c, Policy.c, Communication.c. Test the policy-transition repro expecting unchanged bytes after expansion; preattachment repro is expected to remain REPRODUCED, demonstrating this option's gap. Add concurrent open/map/close around policy push and publication.

Option 2 — volume quiesce, flush/purge, then open a clean epoch
Mechanism: set each instance QUARANTINED; deny every unowned paging write at IRP_MJ_WRITE and stop protected admission; enumerate files, flush and purge their caches, and activate only after proving there are no writable mapped references. Keep owned-stream paging routed to its private backing. Candidate APIs are FltFlushBuffers(instance, file object) and CcPurgeCacheSection(SECTION_OBJECT_POINTERS); a clean offline/remount boundary is the alternative. The repo calls them only for owned-stream retirement. UNVERIFIED: exact documented IRQL/context requirements, whether a successful call removes live user mappings, and whether either API can prove zero writable references for a volume. Neither use in the repo enumerates arbitrary files. [driver/SafeUpload.Minifilter/StageStream.c:1291-1309]
Leak coverage: (a) and (b) are blocked while the raw paging-write fence remains closed; a proven clean remount before any file opens could permit a later active epoch. Holding the barrier through first policy installation and every expansion covers post-transition writes. A scan/flush without proof of zero live sections cannot reopen the fence. Existing mounted-volume attach cannot be called clean merely because the flush returned success.
Races / locks / lifetime: all opens/maps/writes must be fenced from before the scan through activation; otherwise a new map races the proof. InstanceSetup cannot wait for a scan or talk to the service. [driver/STAGED-WRITES.md:183-195] Policy replacement repeats the full barrier. Detach/unload must remain refused while the epoch is quarantined or any scan is incomplete.
Failure / user effect: any busy file, API failure, incomplete enumeration, unknown filesystem, or unavailable volume-exclusive boundary leaves the volume quarantined; unowned mapped writes stay denied, protected writes are refused, and the agent reports staging unavailable. No timeout or partial scan may be interpreted as success.
Uncovered / cost / test: no documented all-volume section inventory is found in the repo, so this option has no implementable proof yet. Large scan/flush cost and cache stalls are likely. Changes: Filter.c, Context.c, StageStream.c, Policy.c, Communication.c plus an offline/remount controller. Run both repros only after the barrier reports a proven clean epoch; add continuous open/map/flush during attach and policy transition and verify the barrier never opens early.

Option 3 — hybrid epoch tags plus fail-closed raw paging-write fence (recommended)
Mechanism: add per-instance admission state and a policy generation. At attach, initialize the instance CLOSED before it can process I/O; InstanceSetup does only bounded allocation/context setup, with no IPC or waits. Tag every successful nonowned create (including out-of-scope and no-policy opens) with the current generation. Protected creates still use StageCreate and own their upper stream. Before policy swap, atomically set TRANSITION, reject new nonowned writable creates/sections, drain in-flight physical-write/publication tokens, then commit the already-built policy and increment generation. A drain timeout/failure rejects the policy update and leaves admission closed. Existing owned streams stay owned across policy changes; never demote them to physical streams.

The decisive fence is before the legacy path in SafeUploadStageDispatch: if an unowned IRP_MJ_WRITE has IRP_PAGING_IO, allow it only when its file-object epoch equals the active policy generation. Missing/pre-attachment tags and stale/pre-policy tags complete with STATUS_MEDIA_WRITE_PROTECTED. Do no filesystem name query in paging I/O. On a policy replacement, all pre-replacement raw file objects become stale (conservative: even mappings outside the changed prefix); a fresh open sees the new policy and is either newly owned or tagged in the new generation. Reject writable SyncTypeCreateSection for missing/stale/transitional raw objects with STATUS_INSUFFICIENT_RESOURCES; always pass SyncTypeOther. The same status correction is needed for the existing owned-stream refusal, which currently returns STATUS_ACCESS_DENIED for a writable CreateSection while read-only or rename-frozen [driver/SafeUpload.Minifilter/StageStream.c:1185-1193]. This does not need a map-count API or a volume scan.

Leak coverage: (a) is blocked if the old view's writeback reaches this attached instance's IRP_MJ_WRITE callback; its FILE_OBJECT has no current epoch tag, so no physical paging write is passed. (b) is blocked because the old section's object has generation 0 / prior generation after policy commit, so later paging writes fail; fresh opens in expanded scope enter StageCreate. Both are conditional on the callback-routing and context-lifetime contracts marked UNVERIFIED below.

Races / locks / publication: use nonpaged interlocked state/rundown checks in callbacks; no blocking resource or name query in paging callbacks. Create and nonowned paging-write paths acquire an epoch token before proceeding and release it in post-op; policy update closes admission first, drains tokens at PASSIVE_LEVEL outside SafeUploadPolicyLock, then swaps the snapshot. If a create is still waiting on service allocation, do not hold the policy push lock; bound the drain and fail the update if it cannot finish. Exact publication create/rename remains the only physical-publication exception; pin its token through the successful rename commit and make policy update wait or fail. Existing paths already validate publication create and rename permits. [driver/SafeUpload.Minifilter/StageStream.c:1523-1527,1604-1608; driver/STAGED-WRITES.md:814-825]

IRQL / lifetime / unload: store tags in nonpaged stream-handle contexts or a per-file-object table; use the create-time normalized name only if needed for diagnostics, never resolve it in paging I/O. Do not clear a stale tag at CLEANUP; retain it through final close while a mapped section can still generate paging writes. `InstanceQueryTeardown`, service stop, and filter unload must refuse while the epoch fence or tagged objects can still receive writeback; the current detach check only counts owned streams and must be extended. [driver/SafeUpload.Minifilter/Filter.c:550-553; driver/SafeUpload.Minifilter/StageStream.c:1375-1409]

Failure / user effect: allocation/tag failure denies that create; CLOSED/TRANSITION denies new protected writes; stale mapped writes and flushes return a write-protected failure; stale writable map creation returns insufficient resources. If the filter cannot guarantee callback coverage on an instance, do not mark its epoch ACTIVE or admit protected streams. Taint enforcement remains; normal builds remain staging-disabled. Service restart with unchanged policy still advances the epoch, so old raw mapped writes are conservatively refused until reopened.

Uncovered / cost / test: unrelated memory-mapped writes through stale raw file objects will also fail after each policy push; this is deliberate fail-closed behavior but may be disruptive. It cannot undo bytes written before a destination entered policy. A forced unload/system failure can remove the fence; unload and restart recovery need separate gates. Changes: Filter.c, Context.c, Filter.h, StageStream.c, Policy.c, Communication.c; add per-instance state, per-file-object tags, counters/audit, and publication rundown. Fast-path cost is one context/generation check per paging write; policy pushes briefly close new admissions and drain in-flight work.

RECOMMENDATION
Choose Option 3. It is the only candidate that can block an already-existing physical section without pretending a file scan proves that no writable views exist: unowned or stale paging writes are refused, while current-generation protected opens use the owned stream. It also gives policy replacement a concrete generation boundary. Keep it explicitly unqualified until the exact preattachment repro proves the writeback callback is observed and the unchanged-byte assertion passes.

Minimal first slice: feature build only; add instance CLOSED/ACTIVE/TRANSITION state, nonowned create epoch tag, generation bump around SafeUploadSetPolicy, and an early unowned paging-write deny in StageStream dispatch. Add stale writable-section refusal with the required INSUFFICIENT_RESOURCES status, and correct the existing owned-stream refusal cited above. Pin detach/unload until epoch state is safe. Do not add a volume scan or claim general NTFS/SMB/removable support. Run both existing repros and concurrent create/map/attach and policy-update cases before enabling ACTIVE by default.

Top 3 unresolved risks:
1. UNVERIFIED: Windows 10 / FltMgr delivers modified-page writeback from a section created before attachment to this new instance, and completing that paging write in pre-op prevents physical change (including on later cache retry). If false, option 3 cannot close leak (a).
2. UNVERIFIED: the paging callback's TargetFileObject is the same identity as the tagged create object, and a stale tag cannot be replaced by a current-generation tag while the old section remains. If identity is lost, the missing-tag path must deny; availability may suffer if contexts disappear at cleanup while mapped views remain.
3. UNVERIFIED: rundown/lock ordering across policy push, service allocation IPC, publication rename commit, callback IRQL and unload can be bounded without deadlock or a commit gap. Must test under Verifier and prove the update either drains or fails closed.

EXTERNAL API CONTRACTS TO CHECK ON MICROSOFT LEARN (not verified here)
- FltMgr attach/setup flags and ordering: whether a newly mounted instance is guaranteed to precede every file open; InstanceSetup PASSIVE/no-sync/no-IPC constraints are recorded in STAGED-WRITES.md:183-195.
- IRP_MJ_WRITE paging pre-op completion: delivery for preattachment mappings, legal failure status/IRQL, and whether failed flushes can be retried below or after detach.
- FltSetStreamHandleContext / FltGetStreamHandleContext lifetime relative to cleanup, close, section objects, and paging callbacks.
- Ex rundown routines at the callback IRQLs selected for the epoch gate.
- FltFlushBuffers and CcPurgeCacheSection contracts if Option 2 is revisited; a successful per-file flush/purge must not be treated as proof of no writable mapped references without documentation.

Observable test plan (design only; not run)
1. Test-StagedPreAttachmentMapping.ps1: retain the preattach writable section after closing its source handle, attach, write/flush. Expected BLOCKED: writeback callback records missing epoch and denies it; fresh file object reads baseline bytes. A reproduced mutation means no activation.
2. Test-StagedPolicyTransitionMapping.ps1: create the section before first policy, push baseline then expanded scope, write/flush old view. Expected BLOCKED: epoch 0 object is stale after commit; fresh file object reads baseline bytes and its create is owned/staged.
3. Race matrix: loop create/map/close against filter attach and policy push/replace; pause at transition; verify every operation is either owned under the committed generation or refused, never passed as unowned physical paging I/O. Verify failed drain leaves prior policy active and no scope expansion.
4. Publication overlap: race approved publication rename with policy transition; verify exactly one approved destination version commits, or the policy update is refused. Test old view flush after publication and after attempted detach/unload; no stale paging write may reach the destination.
5. Record callback counts, NTSTATUS, policy/epoch generation, independent destination hashes/bytes, active Verifier, and restoration. These are proposed gates, not existing results.
